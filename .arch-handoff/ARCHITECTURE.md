# ADR-047. Переписывание реализации KDA-слоя

- Date: 2026-10-08
- Status: Accepted

## Context

**Измерено (лестница L0–L4, независимо подтверждено линией-1 с расхождением в пределах шума):**

| Ранг | Профиль | MFU% |
|---|---|---|
| L1 | dense-FFN | **60–65** |
| L2 | MoE top-2/12 | 42 (active 17–20) |
| L0 | чистый GEMM | 46 |
| **L3a** | **KDA, T=8192, chunk=64** | **2.17** |
| L3b | MLA | 20.7 |

## Decision

1. **Математика сохраняется: delta-rule KDA без изменений.** Любая новая реализация обязана проходить **численный паритет с recurrent-оракулом** (`net/tests/test_kda_wyut.py` и родственные тесты, `atol` из существующих констант). Смена математики — не эта дельта.
2. **Целевая структура реализации:**
   - **внутри чанка** — матрица `C×C` (attention-подобная, маскированная) вместо материализации `dk×dk` на каждый токен: попадает на тензорные ядра, память `O(C²)`;
   - **между чанками** — состояние `dk×dv` (компактное), обновляемое последовательно по `T/C` шагам, **а не** композиция моноида `dk×dk`.
3. **Диагностика до правки (обязательна).** Разложить время и память KDA-слоя по фазам (проекции, ShortConv, intra-chunk, inter-chunk, output gate, проекция выхода, backward) для обеих существующих форм — оптимизировать **доказанно дорогое**, а не предполагаемое. Отчёт диагностики прикладывается (JSON/таблица), он и обосновывает выбор конкретных изменений.
4. **Критерии приёмки:** (а) паритет с оракулом — зелёные существующие тесты; (б) MFU L3a **≥ 20%** (промежуточная ступень; потолок dense-профиля — 60–65%); (в) пиковая память слоя **не выше** текущей chunked (никаких аллокаций в 46 ГиБ); (г) детерминизм в гейтовом профиле не хуже текущего.
5. **Переключение — флагом** (`kda_impl`), с возможностью мгновенного отката на `chunked`: обе реализации сосуществуют, выбор — декларативный.
6. **Проверка на модели:** после паритета и L3a — прогон l3-full (4 шага, T=8192, B=1) с XLA-лимитом (ADR-041) и сравнение шаг/ток-с и loss с baseline `chunked` (85.5/85.3/82.7 с, 95.8–99.0 ток/с, loss 13.537→13.411).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Переписать реализацию, сохранив delta-rule** (принято) | Единственный путь поднять MFU *модели*, не меняя смысл слоя; паритет проверяем существующими тестами | Требует диагностики и аккуратной работы с памятью/графом; риск, что XLA не сгенерирует желаемый граф |
| B. Переключиться на `kda_impl=wyut` | Одна строка конфига | Измерено: **медленнее** (97.9 с против 85.5) и **OOM** (46.81 ГиБ). Отвергнуто фактом |
| C. Оставить chunked как есть | Ноль работы | KDA 2.17% → MFU модели 0.66%; цель 55% недостижима, вопрос владельца остаётся без ответа |
| D. Заменить KDA на dense-внимание | MFU как у L1 (60%+) | **Смена архитектуры модели L3** (ADR-021): другое качество, другие свойства (длина контекста), отдельное решение владельца — не в объёме этой дельты |

## Consequences



### Positive

- Адрес потерь зафиксирован числом (2.17%), а не мнением; цель 55% перестаёт быть спором о железе и становится инженерной задачей.
- Обе существующие формы остаются как fallback; переключение — флагом, откат мгновенный.
- Паритет гарантируется существующими тестами (WY/UT-оракул уже написан).

### Negative

- Работа затрагивает ядро модели (`net/kda.py`) — риск регрессий по качеству; закрывается паритетом и сверкой loss на 4 шагах (не более: полный прогон — дорого).
- Возможен сценарий «XLA не даёт желаемый граф» (например, C×C внутри чанка всё равно распадается на мелкие ядра) — тогда цель ≥20% может не быть достигнута первой итерацией; это фиксируется отчётом, а не замалчиванием.
- Диагностика и переписывание — не один прогон харнесса; ожидаются итерации.
- Параллельно в основном каталоге работает линия-1 (та же модель `net/`) — конфликты при мерже возможны; поэтому работа идёт в отдельном worktree от `main`.

## Reversibility

**Обратимо, цена низкая.** Обе реализации сосуществуют за флагом `kda_impl`; откат = переключить на `chunked` (одна строка конфига). Правки изолированы в worktree `arch/kda-rewrite`. Необратимых миграций и изменений данных нет.
