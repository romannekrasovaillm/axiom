# Диагностика: контейнмент D→K — «снято 0 (пар 0)» (ADR-020, дельта-2)

Дата: 2026-09-28. Предмет: фикс порядка контейнмента, `tools/axiom_ds/cpt_serialize.py`
(задача TASK.md, статус `blocked` по пункту 4 задачи).

Итог одной строкой: **двухфазная сборка реализована и защищена тестом T-order, но
гипотеза «порядок потока» числами боевого прогона опровергнута: индекс D был полный,
ноль пар — честный результат данных, а не дефект порядка. Боевой перегон после фикса
подтвердил: `dropped_containment = 0` при полном индексе (containers = 5658 = все D,
checked = 96217 = все K, checked_pairs = 0).**

## 1. Что реализовано

* **ФАЗА А** (`cpt_serialize.py:889`) — чтение, скраб, `serialize_one` и дедуп всех
  компонент в порядке K → D → S (он же «старшинство» в общем пуле дедупа);
  записи копятся целиком, до конца фазы не пишется ничего.
* **ФАЗА Б** (`cpt_serialize.py:910`, ступень — `apply_containment`, `:701`) —
  контейнмент по ПОЛНОМУ набору записей: `dedup_mod.containment_dedup` индексирует
  чанки всех контейнеров (D) до первого решения, поэтому K, идущий в потоке раньше D,
  сравнивается с полным D-корпусом. Пороги, геометрия окон (400×300, порог окна 0.55,
  покрытие 0.8) и `dedup.py` НЕ менялись.
  Добавлен **инвариант готовности**: если записи-контейнеры есть, а индекс чанков
  пуст — `ValueError` (CLI печатает «отказ», код 2), а не молчаливое «снято 0».
* **ФАЗА В** (`cpt_serialize.py:928`) — запись уцелевших в шарды в порядке K → D → S
  + манифест/отчёт, как раньше.
* Дедуп и скраб — прежние ступени, порядок K → D → S сохранён (T-dd1 зелёный).

## 5. Почему пар 0 — данные, а не код

Замер **294 реальных пар «одна статья»** (связи: `concepts:` дистиллята → слаг карточки,
986 пар; `source: arXiv:` дистиллята → `sources:` карточки, 3836 пар; поле `source:`
есть у 5652 из 5658 дистиллятов). Все метрики — числа, содержимое не выгружалось.

| Метрика (на пару) | median | p90 | max |
|---|---|---|---|
| `doc_jaccard` (MinHash, то, что видит Deduper) | 0.0156 | 0.0312 | 0.125 |
| `c5_containment` (доля 5-грамм K, встречающихся где-либо в D) | 0.1483 | 0.216 | 0.4839 |
| `w2_containment` (то же на биграммах слов) | 0.0421 | 0.0909 | 0.3333 |
| `best_window` (максимум истинного Jaccard по парам окон 400×300) | 0.0598 | 0.102 | 0.3524 |

* пар с `best_window ≥ CHUNK_JACCARD` (0.55): **0 из 294**;
* пар с покрытием окон ≥ 0.8: **0 из 294**.

Худший-лучший случай (реальная пара, «одна статья»): `k_chars=1224`, `d_chars=8018`,
`best_window=0.3524`, лучшие совпадения по окнам K
`[0.306, 0.287, 0.235, 0.289, 0.352, 0.352]` при пороге окна 0.55.

**Вывод.** Разрыв с порогами не «на границе разброса», а категорический: карточка и
дистиллят одной статьи — независимо написанные тексты с общей терминологией (~15%
5-грамм), а не «карточка ВНУТРИ дистиллята». Ступень в текущей геометрии не может
сработать на этом корпусе ни при каком порядке фаз (боевой прогон — исчерпывающая
проверка: 95249 × 5539, ноль пар ≥ 0.55).

## 6. Вопросы к архитектору

1. Премиса ADR-020 (дельта-2) «карточка K содержится ВНУТРИ дистиллята D» на текущем
   корпусе измерением не подтверждается. Какая пара была основанием премисы —
   возможно, речь о другом подмножестве (иной каталог D/K, иной тип карточки)?
2. Решение по ступени: оставить как есть (честный no-op, состав корпуса не меняет),
   отключить/пометить, или переопределить «вложение» (например, порог покрытия на
   уровне терминов/биграмм — тогда порог берётся из распределения, а не из ожидания
   «сотни»). Подгонка порога под ожидаемый результат задачей запрещена и не делалась.
3. Ограничивать ли контейнеры подкаталогом/статьёй (сейчас все D против всех K)?

## 7. Оператору: как закрыть CLI-гейт (и почему не кодом)

```bash
# AD-7 — проверка ресурсного инварианта на самом стенде:
ssh gb10 'cd <axiom> && python3 tools/check_gb10_single_load.py'

# AD-4 — исполнить spark_inference НА СТЕНДЕ и пересобрать манифест:
#   (status skipped/absent/failed гейт не закрывает — ADR-014;
#    подмена стенда локальным CPU-инференсом запрещена — ADR-010)
python3 tools/a4_manifest.py --output evidence/a4-skeleton-run-manifest.json \
    --run-ref <журнал> --stage spark_inference=executed:'<следы стадии>'
```

После этого `arch-be gate --route auto` закрывает `fitness` и stop-хук перестаёт
блокировать завершение. До прогона на стенде обе находки — долг доказательности
кейса, не дельта: воспроизводятся на baseline `a154797` (exit 1 обе).

Состояние на 28.09.2026 ~12:55: **стенд недоступен с этой машины** — `ssh gb10`
(192.168.101.50:22) → «No route to host». То есть закрытие AD-7/AD-4 сейчас
заблокировано не только правом доступа, но и доступностью самого стенда;
на этой машине (RTX 4080 SUPER) гейт зелёным быть не может by design — правило
AD-7 проверяет ЛОКАЛЬНЫЙ GPU.
