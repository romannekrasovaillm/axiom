# Задача для кодового харнесса

ЗАДАЧА (гейт G1 кампании MFU-55, первый рычаг — LU/TRSM-шторм в KDA).

КОНТЕКСТ. G0-диагностика (evidence/mfu-55/G0b/REPORT.md) на линии arch/mfu-int (kda_impl=chunked_cc): шаг = шторм мелких ядер — 493 173 запуска ядер за 120 с стационара при занятости GPU 5.1%; в топе — LU-ядра getrf_panel, batch_trsm_left_kernel, LuPivotsToPermutation (по 34 560 запусков каждого). Источник: net/kda.py, cc_chunk_step (и симметричное место WY/UT-пути): `t_mat = jnp.linalg.inv(eye + l_mat)` — инверсия единичной нижней треугольной (H, C, C) через LU на каждый чанк × голову × слой.

ЧТО СДЕЛАТЬ. Заменить инверсию батчевым РЕШЕНИЕМ треугольных систем, не строя обратную матрицу:
- либо `jax.lax.linalg.triangular_solve(a=eye+l_mat, b=xw, lower=True, left_side=True)` и то же для vw (batched TRSM: одно крупное ядро вместо десятков тысяч мелких);
- либо явная прямая подстановка через `jax.lax.scan` по строкам чанка, если triangular_solve недоступен/медленнее.
Математика НЕ меняется: (I+L) — единичная нижняя треугольная; w = T·xw, u = T·vw эквивалентны решениям систем.

ОГРАНИЧЕНИЯ. НЕ менять математику KDA, публичные сигнатуры, семантику kda_impl и net/config.json (пин скелета). Правки только net/kda.py и net/tests/*. GPU-прогоны НЕ запускать (стенд занят кампанией). Один рычаг за раз — никаких сопутствующих «оптимизаций» тем же коммитом. Если та же инверсия встретится в других местах net/kda.py — приведи тем же способом или перечисли в отчёте.

ПРОВЕРКА. `python3 -m pytest -q net/tests/test_kda_chunked_cc.py` (+ родственные WY/UT-тесты) — зелёные, те же atol. Приложить статический счёт: сколько вызовов linalg.inv было и стало, оценка сокращения запусков ядер (форма H × n_chunks × слои).

РЕЗУЛЬТАТ. .arch-handoff/result.json (status/assumptions/open_questions) + коммит. В assumptions — выбранный путь и почему; в open_questions — что должен измерить архитектор на GB10.

## Финализация (обязательно)

Результат забирается из git, поэтому перед финальным ответом зафиксируй работу коммитом:

```bash
git add -A -- . ':!.arch-handoff'
git commit -m "<кратко: что реализовано>"
git status --short   # пусто, кроме .arch-handoff/
```

- Коммитится код и тесты; служебный каталог `.arch-handoff/` в коммит не входит.
- Работа без коммита считается невыполненной: оркестратор увидит её только через git log.

### Самопроверка через MCP (маршрут Standard/Critical — обязательна)

Перед финальным коммитом вызови через MCP-сервер `arch-spine` (подключён per-run, `.arch-handoff/mcp.json`) ровно эти проверки и добейся `passed=true`:

- `fitness_check` — `{"repo": "<корень прогона>"}`;
- `scope_check` — `{"repo": "<корень прогона>"}`.

Их вызовы пишутся в MCP-журнал прогона (`.arch-handoff/mcp-journal.jsonl`) — это evidence «исполнитель проверял себя». Отсутствие записей = непроверенное, а не проверенное: на приёмке такой прогон не засчитывается (INCOMPLETE). `handoff_status` показывает обязательные проверки маршрута, `contract_validate` — пройдёт ли контракт результата.

## Контракт результата

Финальный ответ обязан завершаться JSON-объектом (после него — ни символа); тот же JSON запиши файлом `.arch-handoff/result.json` (файл переживает обрыв вывода):

Схема объекта: `{"status": "complete|partial|blocked", "assumptions": [], "open_questions": [], "conflicts_with_prior_decisions": []}`

- `status`: `complete` — выполнено полностью; `partial` — частично; `blocked` — заблокировано.
- `assumptions`: допущения, принятые при реализации.
- `open_questions`: вопросы к архитектору.
- `conflicts_with_prior_decisions`: расхождения с принятыми ранее решениями (ADR, spine).

Архитектурный контекст — `ARCHITECTURE.md`, ограничения — `CONSTRAINTS.yaml`, рубрика приёмки — `RUBRIC.yaml` (при наличии).
