ЧТО СДЕЛАТЬ:

1) **Гейт только для прогонов.** Убрать вызов `jax_preflight.gate_or_exit()` из проверяющих инструментов:
   - tools/check_precision_pinning.py (около строки 525),
   - tools/a4_manifest.py (около строки 923).
   Оставить там только `ensure_mem_fraction()` (лимит памяти обязателен всем). Обоснование в Amendment п.2: контрольный контур не должен падать (SystemExit) из-за чужой нагрузки на стенде, иначе C-042/C-038 дают ложный FAIL.
   Гейт обязан сохраниться в **прогонных** путях (обучение/профилировка): tools/pretrain_run.py, tools/bench_*.py, tools/run_*_smoke.py, tools/d8_isolate.py, tools/pool_cost_probe.py, tools/topk_exact_probe.py, tools/run_a4_pipeline.py — проверь, что он там есть, и не сломай.

2) **Enforce гейта — только на GB10.** `gate_or_exit()` должен реально блокировать только при наличии CUDA-устройства GB10 (детект: `nvidia-smi --query-gpu=name --format=csv,noheader` содержит «GB10»; при отсутствии nvidia-smi/не-GB10 — предупреждение в лог и продолжение, НЕ SystemExit). Правка внутри tools/jax_preflight.py; поведение на стенде (fail-closed) сохраняется полностью.

3) **`read_locks` в tools/check_gb10_single_load.py.** Сейчас `if not lock_dir.is_dir()` падает PermissionError на `~/gb10-shared/.locks` с режимом 000 (стендовый долг, дважды искажал диагностику и роняет C-040). Обернуть проверку в `try/except (PermissionError, OSError)` по образцу `jax_preflight._permission_grant`: при недоступности вернуть понятный статус (недоступный лок-каталог) вместо падения. Не менять семантику при доступном каталоге.

4) **Тесты** (tools/tests/test_jax_preflight.py — дополнить, не переписать):
   - проверяющий инструмент НЕ падает при чужой нагрузке (мок: чужие compute-процессы + инструмент-проверка → без SystemExit);
   - gate_or_exit: на GB10-моке с чужим процессом → SystemExit; без GB10-мока (или без nvidia-smi) → предупреждение и продолжение;
   - read_locks: PermissionError на каталоге → не падает, возвращает статус недоступности (мок os.scandir/listdir);
   - существующие тесты префлайта остаются зелёными.

## План отката

Откат = `git revert` коммита правок (или `git reset --hard 09652d2` при незакоммиченных правках): 09652d2 — якорь. Признаки: (1) после уточнения границы «гейт только для прогонов» проверяющие инструменты всё ещё вызывают gate_or_exit (проверяется grep'ом по tools/check_precision_pinning.py, tools/a4_manifest.py); (2) enforce на дев-ПК блокирует CPU-тесты (тесты падают без GPU) — это регрессия, откат обязателен; (3) в коммит попали чужие пути (evidence/facts/*, model/) — откат и чистка. Владелец решения — архитектор.

## Финализация (обязательно)

Результат забирается из git, поэтому перед финальным ответом зафиксируй работу коммитом:

```bash
git add -A -- . ':!.arch-handoff'
git commit -m "<кратко: что реализовано>"
git status --short   # пусто, кроме .arch-handoff/
```

- Коммитится код и тесты; служебный каталог `.arch-handoff/` в коммит не входит.
- Работа без коммита считается невыполненной: оркестратор увидит её только через git log.

## Контракт результата

Финальный ответ обязан завершаться JSON-объектом (после него — ни символа); тот же JSON запиши файлом `.arch-handoff/result.json` (файл переживает обрыв вывода):

Схема объекта: `{"status": "complete|partial|blocked", "assumptions": [], "open_questions": [], "conflicts_with_prior_decisions": []}`

- `status`: `complete` — выполнено полностью; `partial` — частично; `blocked` — заблокировано.
- `assumptions`: допущения, принятые при реализации.
- `open_questions`: вопросы к архитектору.
- `conflicts_with_prior_decisions`: расхождения с принятыми ранее решениями (ADR, spine).

Архитектурный контекст — `ARCHITECTURE.md`, ограничения — `CONSTRAINTS.yaml`, рубрика приёмки — `RUBRIC.yaml` (при наличии).
