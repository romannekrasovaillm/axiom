СОЗДАТЬ ДВА ФАЙЛА:

YAML-ledger: если PyYAML доступен — использовать; если нет — минимальный встроенный парсер нужного подмножества (список словарей с плоскими скалярами и блочными строками >-), иначе exit 2 с понятной ошибкой.
2) tools/tests/test_check_loss_changepoint.py — pytest, импортирует функции из tools/check_loss_changepoint.py.

АЛГОРИТМ (точно, менять нельзя):
- Вход: --metrics принимает один или несколько путей; каталог → все metrics-seg-*.jsonl в нём (сортировка по номеру сегмента, не лексикографически), файл → он сам. Строки схемы pretrain-metrics/v1, поля step (int) и loss (float).
- Валидация: битая JSON-строка, нечисловой step, NaN/Inf loss, пустой набор строк → exit 2 с сообщением в stderr.
- Сортировка по step; дубли шага схлопываются — остаётся последнее вхождение.
- Блоки по B=25 шагов; значение блока — МЕДИАНА loss; хвост короче B отбрасывается.
- Для каждого блока k (нужно >= N+G+M блоков истории): recent = медиана блоков [k-N+1 .. k] (N=6), reference = медиана блоков [k-N-G-M+1 .. k-N-G] (M=12, G=2).
- sigma_b = 1.4826 * MAD по ВСЕМ блочным медианам (MAD — медиана |m - медиана(m)|).
- delta = med(recent) - med(reference); z = delta / (sigma_b * sqrt(1/N + 1/M)); при sigma_b == 0 → exit 2 (вырожденный вход).
- Событие: |delta| >= min_abs (0.10) И |z| >= z_threshold (3.5), удержание >= persist (3) блоков подряд. Step события = медианный step первого блока удержания. Поля события: step, direction (up|down), delta, z, blocks.
- Слияние: события, отстоящие менее чем на 3 блока, сливаются (остаётся более раннее).
- --ledger YAML: список changepoints с полями step, direction, owner, reason, ref, review_by. Подавление при |detected_step - step| <= tol (--tol, дефолт 400). Запись без owner/reason/ref/review_by НЕ подавляет (считать недействительной и сообщить). Отсутствие файла ledger при явном --ledger → exit 2.
- Exit: 0 — нет неподавленных событий ИЛИ нет данных (status=neutral); 1 — есть неподавленные; 2 — некорректный вход.
- --json: один JSON-объект в stdout (status, events, suppressed, params, rows, blocks), без прочих строк.
- --quiet: только итоговая строка (или ничего при 0 в неинтерактивном режиме).
- --selftest: встроенные детерминированные кейсы (random.Random с фиксированным seed), exit 0 только если все PASS. Обязательные кейсы: (a) стационарный шум sigma=0.25, 20000 шагов → 0 событий; (b) линейный тренд -0.3 за 20000 шагов + шум → 0 событий; (c) ступень +0.17 на шаге 10000 → обнаружена, |detected-10000| <= 150; (d) ступень -0.17 → direction=down; (e) тяжёлые хвосты t3 стационарно → 0 событий; (f) NaN → exit 2; (g) дубли шагов и разрыв → без ложного события и без падения; (h) сдвиг на некратном блоке 10013 → обнаружен в допуске; (i) с подавлением реестром → exit 0.
- Производительность: 30k строк < 60 с.

## Контракт результата

Финальный ответ обязан завершаться JSON-объектом (после него — ни символа); тот же JSON запиши файлом `.arch-handoff/result.json` (файл переживает обрыв вывода):

Схема объекта: `{"status": "complete|partial|blocked", "assumptions": [], "open_questions": [], "conflicts_with_prior_decisions": []}`

- `status`: `complete` — выполнено полностью; `partial` — частично; `blocked` — заблокировано.
- `assumptions`: допущения, принятые при реализации.
- `open_questions`: вопросы к архитектору.
- `conflicts_with_prior_decisions`: расхождения с принятыми ранее решениями (ADR, spine).

Архитектурный контекст — `ARCHITECTURE.md`, ограничения — `CONSTRAINTS.yaml`, рубрика приёмки — `RUBRIC.yaml` (при наличии).
