# ADR-024. Эксклюзивный захват чекаута на время живого прогона исполнителя

- Date: 2026-10-05
- Status: Accepted (архитектор; ревью владельца — вместе с дельтой в PR)
- Основание: инцидент параллельности 05.10 (`docs/RESULTS-2026-10-05.ru.md` §2); уроки Лагуны §5.3 (приёмка дельт); spine AD-13

## Context

05.10 архитектор запустил кодовый харнесс на чекаут `main` (baseline `3034065`) и продолжил собственные документные дельты в том же рабочем дереве (коммиты `00753c2`, `1371f47`). Харнесс, прочитав пакет уроков из спеки, реализовал те же пункты бэклога параллельно: результат — по два раздела §8 в обеих спеках стадий и двойное изложение стоп-протокола; разрешение потребовало отдельного прохода схлопывания дублей (`7cbd8ee`). Спайн-тест принадлежности срабатывает: два независимых исполнителя над одним чекаутом без разграничения файлов расходятся несовместимо по построению — в этот раз дубли, в следующий раз взаимные затирания правок.

## Decision

1. Живой прогон исполнителя (harness-пакет, флот) **захватывает чекаут эксклюзивно**: с момента запуска пакета до его финального коммита рабочее дерево не правится никем другим, включая архитектора.
2. Все архитекторские дельты (спеки, ADR, спайн, конфиги) — **либо до запуска пакета** (зафиксированы коммитом в baseline), **либо после приёмки** его финального коммита.
3. Задача пакета явно перечисляет допустимые пути правки; выход за список = конфликт при приёмке (дельта откатывается, независимо от её качества).
4. Архитекторская дельта, нужная во время прогона, не «вносится параллельно»: прогон доводится до финального коммита (или штатно прерывается), дельта вносится, пакет при необходимости перезапускается от нового baseline.
5. По-настоящему параллельные работы — через worktree-изоляцию (`arch-ml worktree`), не через общий чекаут.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Worktree-изоляция каждого прогона по умолчанию** | конфликт исключён конструктивно | ломает контракт handoff (финальный коммит в рабочем дереве, `git log` — носитель результата); ветка+слияние на каждый мелкий пакет |
| **Технический замок чекаута** (файл-лок, проверяемый раннерами) | автоматика вместо дисциплины | лок не мешает fs-правкам «чужих» инструментов и ломает легитимные коммиты самого исполнителя; сложность выше пользы |
| **Статус-кво: правки «по аккуратности» без правила** | нулевая стоимость | прецедент 05.10: дубль-реализация бэклога и проход схлопывания; следующего раза цена выше |

## Consequences

### Positive

- Финальный коммит пакета — единственный носитель результата приёмки (§5.3); diff приёмки читается без примеси чужих правок.
- Бэклог не реализуется дважды; архитекторские и исполнительские носители не конфликтуют.

### Negative

- Архитекторская правка «прямо сейчас» ждёт конца прогона (до ~1 ч) — цена дисциплины; митигируется планированием: дельты дерева закрывать до запуска пакета.
- Аудит требует фиксации окна прогона (лог `hr-*`), по которому сверяется reflog.

## Reversibility

**Two-way**: процессное правило, отменяется/уточняется новым ADR; данные и код не меняются.
