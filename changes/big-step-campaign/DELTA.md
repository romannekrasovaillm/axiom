# Дельта: big-step-campaign
- Route: Standard
- Created: 2026-10-10
- Владелец: архитектор. Основание: ADR-053 (кампания «крупный шаг»), измерения 0.11.2 (`evidence/mfu-55/env0112/`).

## Проблема

Полный шаг l3-full даёт **431.4 ток/с = 1.32% MFU** (лучшая клетка 0.11.2). Цель G1 — 3% (977 ток/с), цель владельца — 55%. Измерениями установлено: **диспетчеризацию флагами не снять** (отключение command buffers даёт −2.5%), **кернелы вторичны** (KDA ≈7% шага, fp32-вход на Mosaic запрещён API), а **крупные формы дают втрое-вдесятеро больше** (L1 dense MLP: 59.9% при 8192 токенах → **65.2% при 32768**). Память при этом не блокер: бюджет шага при полном remat — 7.5 ГБ (8192 токенов), 10.5 (16384), 16.5 (32768), 28.5 (65536) при 128 ГБ.

## ADDED

- Гейты кампании: **S0** (память подтверждена: B=2 без OOM), **S1** (MFU ≥3% при B=2..4 + remat dots), **S2** (монотонность MFU по размеру шага B=2→4→8), **S3** (максимум от комбинации «батч + remat dots + chunked CE» — фиксируется как кампанийная конфигурация).
- Правило: размер шага (токенов/шаг) объявляется вместе с результатом; сравнения — только при одинаковых remat/ce-chunk/dtype/лимите XLA.
- Обязательная контрольная рука по loss на каждом размере шага (крупный батч меняет порядок редукций — рост MFU не должен покупаться расхождением траектории).

## MODIFIED

- Ничего в коде: кампания идёт **флагами** (`--batch-size`, `--remat-policy dots_with_no_batch_dims_saveable`, `--ce-chunk-tokens 4096`), окружение — кандидатная линия 0.11.2 (`<HOME>/venv-axiom-0112`).

## REMOVED

- Ничего.

## План отката

Возврат к B=1 (базовая клетка 431.4 ток/с) сменой флага; веса/данные не затрагиваются. Признак регрессии: loss при крупном шаге расходится с контрольной рукой при том же числе шагов, либо OOM/`INTERNAL` в компиляции.

## Критерии приёмки

- [ ] S0: B=2 (16384 токенов) — прогон без OOM, шаг завершается, числа сопоставимы.
- [ ] S1: MFU ≥3% достигнут на B=2..4 с remat dots (замер на GB10, условия объявлены).
- [ ] S2: зависимость MFU от размера шага измерена (B=2, 4, 8); монотонность подтверждена или потолок зафиксирован числом.
- [ ] S3: кампанийная конфигурация зафиксирована замером и внесена в `evidence/kpi-pins.json` как базовая точка.
- [ ] Контрольная рука: loss на крупном батче не хуже контрольной при равном числе токенов.
