## Проблема

`arch-be model drift` даёт 5 предупреждений `declared-edge-unused` («мёртвые `depends_on`»). Разбор по коду показал, что находки разнородны:

|---|---|---|
| CMP-003 → CMP-002 | есть: `from net import kda/model/config …` (tools/bench_kda_wyut.py:58, bench_block_merge.py:140-141, d8_isolate.py:14) | **ложное срабатывание прибора** |
| CMP-003 → CMP-005 | есть: `from env.util/verifier/run import …` (tools/rollout_harness.py:43,451,474; run_rl_smoke.py; run_a4_pipeline.py) | **ложное срабатывание** |
| CMP-006 → CMP-005 | есть: `from env.util import sha256_text` (tools/rollout_harness.py:43 — импорт верхнего уровня) | **ложное срабатывание** |
| CMP-004 → CMP-002 | импортов `net` в `clients/` нет ни в одну сторону; связь — **артефактная** (инференс использует веса, обученные претрейном) | решение архитектора: код-зависимости нет |
| CMP-006 → CMP-004 | ссылок `clients` в `tools/` нет (единственное упоминание — комментарий в `tools/check_reward_isolation.py:34`) | решение архитектора: ребро объявлено ошибочно |

## ADDED

- Правило работы с моделью: `depends_on` выражает **кодовую/контрактную** зависимость (проверяемую импортом или контрактом INT); поток артефактов (веса, чекпойнты, наборы) описывается текстом сущности и пинами (AD-4/C-032), а не `depends_on`.
