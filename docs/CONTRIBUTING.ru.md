# Contributing (RU)

## Что это за проект — на одном примере

Мы учим модель-агента, которая сама работает с кодом. Не «чат про код», а агент: получил задачу — покопал в репозитории — внёс изменения — отчитался. И главное: **верdict выдаёт не человек и не другая LLM, а механические правила** (fitness-гейты), зашитые в репозиторий.

Реальный случай из практики, чтобы было понятно. 13 сентября мы построили манифест прогона — файл, где пиннятся хеши весов, датасета и список стадий конвейера. Схема v1 проверяла: «хеши непустые? зелёный». Звучит разумно. Но потом выяснилось: можно прогнать только четверть конвейера, манифест будет с непустыми хешами — и гейт скажет «готово». Ложный зелёный хуже честного красного: на нём строятся следующие шаги. Пришлось переписать схему так, чтобы `pipeline_complete` считался машиной и половинчатый прогон давал красный со списком недостающих стадий.

Вот это и есть ядро проекта: **агент учится на траекториях, где награда — пройденные механические проверки, а не «похоже на правду»**. Всё остальное (сеть с нуля, JAX, своя RL-среда) существует, чтобы такой агент появился и работал на реальных репозиториях.

Сейчас у нас: сеть-скелет (~1B MoE) написана и протестирована (374 теста), конвейер смоук-проверен на 4 стадии из 5, доменный датасет (эпизоды агентов + 101k записей концептов/дистиллятов/скиллов) собран. Впереди — претрейн на 20B токенов.

## Как зайти в проект

```bash
git clone https://github.com/romannekrasovaillm/axiom.git
cd axiom

# тесты харнесса пойдут без JAX
python3 -m pytest tools/tests -q

# для сетевых тестов нужен JAX-venv (см. net/README.md про CUDA и LD_LIBRARY_PATH)
python3 -m venv venv-axiom && venv-axiom/bin/pip install -r env/requirements.txt
venv-axiom/bin/python -m pytest net/tests -q   # без GPU пойдёт на CPU, медленнее
```

## Чем реально помочь

Мы — маленькая команда, и в проекте есть слоты под разные руки. Всё — из живого списка [`docs/OPEN-QUESTIONS.md`](../OPEN-QUESTIONS.md):

- **Оператор на DGX Spark / GB10.** У нас есть рецепт: смоук-луп на полном конфиге + инференс на стенде закрывает гейт A4. Без стенда этот пункт не двигается, с ним — закрывается за вечер.
- **Ревизия скиллов.** В доменный датасет вошли 263 скилла из 22 плагинов. Ещё 1 331 скиллов в 9 плагинах, которые похожи на доменные (rl-training, memory-systems, safety-eval, credit-assignment…), ждут ревизию: глазами пройтись и сказать «это даёт модели процедуру Х». Одна итерация — заметный прирост доли процедурных данных.
- **Претрейн-луп.** Сеть и оптимизатор готовы, датасет качается. Нужно: потоковый dataloader, resume, кривые лосса, стоп-правило. Если вы писали JAX-тренинг — это ваша деталь.
- **Замер длинного контекста.** Есть флаг block-wise token merging (механика из Step-5) — нужен бенчмарк на 64K-гэпе, чтобы включить или выбросить. Методика готова (ADR-015), прибор наполовину.
- **Документация и честность.** Ловить в наших текстах «запах» генерации, проверять числа по файлам, ломать наши гейты и рассказывать, как вы их сломали. Последнее — самый ценный вклад: мы учимся на сломанных гейтах.

## Правила, без которых не работаем

1. **ADR раньше кода.** Архитектурное решение — сначала документ (Context/Decision/Alternatives/Consequences), потом реализация. 21 ADR — не украшение, а способ не переобсуждать одно и то же.
2. **Анти-ослабление.** Запрещено ослаблять fitness-правила, чтобы получить зелёный. Правило, которое стало неверным, заменяется новым с обоснованием — гейт это отслеживает.
3. **Fail-closed.** Проверка, которая не смогла выполниться, даёт FAIL, а не пропуск. Исключение фиксируется явно.
4. **Секреты — только наружу из данных.** Скраб идёт первой ступенью любого пайплайна над логами; `SALT`/`sha256`-ключи не секреты, `*_TOKEN` — секреты.
5. **Evidence, а не отчёт задним числом.** Критерии приёмки и план отката пишутся до реализации.

## Где спросить

Issues в этом репозитории. Для быстрых вопросов по контексту — читайте сначала spine и ADR: 80% вопросов «почему так» там уже отвечено, и это быстрее, чем ждать ответа.
