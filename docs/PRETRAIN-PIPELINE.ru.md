# Претрейн-конвейер axiom: как 20B токенов превращаются в обучение

Документ объясняет для контрибьютора полный путь данных — от сырой сети до шага градиента — и какое решение принимается на каждом стыке. Все пути и числа — фактические, из репозитория и evidence.

## 1. Три горизонта данных

| Фаза | Что | Где считается | Статус |
|---|---|---|---|
| **Претрейн 20B** | W: FineWeb-Edu 17B + C: codeparrot 3B + Q: decay 1B | аренда H800 (~$200) | W/C собраны и верифицированы, Q код готов |
| **Доменная CPT** | K/D/S корпус (axiom-domain-ds-v1, 101k записей) | GB10 локально | корпус собран, луп — следующий блок |
| **SFT / RL** | E: 2 000 верифицированных агентных эпизодов | GB10 / 4080 | пайплайн готов |

Приватное (CPT/SFT/RL) никогда не покидает контур (AD-6); на аренду идёт только публичное с карточкой и хешами (ADR-004).

## 2. Конвейер шардов W/C/Q (`tools/prep_pretrain/`)

```
HF-стрим → скраб-нормализация → дедуп → фильтры → ротация шардов 500 МБ → потоковый sha256 → манифест-курсор
```

Ключевые механики (почему именно так):
- **Стриминг, не загрузка**: весь корпус не помещается в память — запись идёт потоком, resume-манифест переживает любые обрывы (протестировано T-p2: обрыв без потерь и дублей);
- **Ротация 500 МБ + sha256**: каждый шард на диске проверяем `verify-manifest` — W 52/52, C 6/6, `bad: []`;
- **Выбор источника кода по измерению**: The Stack v2-dedup отпал (blob-ссылки вместо текста — 150 млн записей `dropped_empty_text`), план B codeparrot-clean (python, лицензии per-file) — ADR-021 amendment;
- **Q-decay**: сужёный фильтр W (строгий educational-порог) + 15% кода с тестами (записи с `def test_`/pytest-маркерами) — decay-фаза на качественном сужёном миксе даёт лучший финал при том же бюджете (WSD-расписание уже в лупе).

## 3. Луп обучения (`net/train_loop.py`, `tools/pretrain_run.py`)

```
шард-стрим → детерминированный shuffle(seed) → токенизация/пакет T=8192 → шаг (loss → grad → Muon/AdamW) → метрики jsonl
                                                          ↓
                              Orbax-чекпойнт (tree_hash) + resume-курсор + стоп-правило AD-8
```

- **Grad-checkpointing** — флаг обязателен: полный граф l3-full на 64K требует 956 ГиБ активаций (замер 29.09, GB10);
- **Детерминизм доказан**: parity/resume тесты зелёные на CPU (43 passed); на GPU — 0/138 расхождений шагов под `--xla_gpu_deterministic_ops` (ADR-013); без флага — 1 ULP, свойство XLA (зафиксировано, не дефект лупа);
- **Стоп-правило AD-8**: смета `evidence/budget/<run-ref>.json` (target_tokens, часы) составляется **до** старта; превышение = остановка с журналом;
- **WSD-расписание**: warmup → stable → decay на последних 5% — decay-фаза съедает Q-шард.

### 3.1. Стоп-правила здоровья ноги: протокол точек замера

Перенесено из пакета уроков Лагуны (`docs/research/LESSONS-LAGUNA-LADDER.ru.md` §1.1–1.2, LAG-ADR-015/022/030). Источник ложных тревог — не шум данных, а неверный носитель вердикта: «сводка по окнам» скрыла разворот 2.10→4.66 при зелёной сводке, а «база с разошедшегося чекпойнта» разрешала ухудшение ×8–16.

- **Вердикт о здоровье ноги — по последовательности точек замера**, не по сырым шагам и не по сводке.
- **Точка замера** — оконный агрегат по `metrics.jsonl` (медиана loss окна ≥20 шагов) либо штатный eval-замер чекпойнта (holdout ppl, проба генерации) — eval-точки не чаще 1 раза в 100 шагов (урок §1.6: замеры каждые 50 шагов обошлись Лагуне в +10.5 ч к стадии); частоту на живом прогоне не менять. Сырая per-step строка **не** точка замера: на здоровой endurance-ноге 05.10 сырой loss дал 3 роста подряд на шагах 89–91 (9.627→9.718→9.842) при нисходящем тренде 13.5→9.6 — стоп-правило по сырым шагам останавливало бы здоровую ногу.
- **Стоп-сигнал** — 3 последовательные точки замера выше предыдущей. Действие: стоп-файл `~/axiom-run/STOP` (не kill), разбор в порядке урока §1.5: окружение (дешёвые контрольные руки) → LR → данные; продолжение — новой ногой `--resume`.
- **Тревога** — точка выше потолка ноги и следующая точка не лучше. Потолок задаётся в смете ноги (`evidence/budget/<run-ref>.json`, поле `loss_ceiling`; вводится при следующей пересборке сметы — у идущей endurance-ноги потолок не задан, вердикт только по тренду).
- **Отдельный порог для самой ранней точки не вводится** — 100% ложных срабатываний (LAG-ADR-015/022). База прибора снимается с чекпойнта-старта тем же прибором и тем же режимом декодирования **до** старта обучения; полосы пересчитываются только от замеренной базы.
- Протокол применяется монитором постфактум по `metrics.jsonl`; вмешательство в живую ногу — только через стоп-файл (§5.2 уроков: правки под живой цепочкой запрещены).

## 5. Правила, которые нельзя обойти

1. **AD-8/C-041**: смета до прогона — страж сравнивает даты и падает при нарушении порядка;
2. **AD-6**: приватные корпуса не покидают контур — претрейн только публичный;
3. **AD-4**: манифест прогона честный — `pipeline_complete` вычисляется, не объявляется;
4. **ADR-013**: гейтовые прогоны детерминированы — A5-репродукция проверяется побитово.

## 6. Здоровье ноги и замеры: тренд, стоп-правила, бронь предмета (ADR-023)

### 6.1. База прибора снимается до первого шага стадии

База для любого eval-замера (holdout ppl, пробы генерации) снимается с чекпойнта-старта **тем же прибором и тем же режимом декодирования** до начала обучения; полосы тревог пересчитываются только от замеренной базы. Якорь «с первого успешного вызова» или с разошедшегося чекпойнта разрешает ухудшение на порядки (у Лагуны: ложная тревога +758 % и «разрешённое» ухудшение ×8–16, LAG-ADR-015/022).

### 6.2. Вердикт о здоровье ноги — по тренду, не по сводке окон

«Сводка по окнам» скрыла у Лагуны разворот loss 2.10→4.66 при зелёной сводке (LAG-ADR-030). Правила вердикта:

- источник истины — последовательность точек `metrics.jsonl` (per-step loss пишется всегда);
- **стоп** — рост loss на **трёх последовательных** точках замера;
- **тревога** — точка выше потолка и следующая точка не лучше;
- отдельный порог для самой ранней точки не вводится (у Лагуны 100 % ложных срабатываний);
- промежуточные eval-точки — не чаще чем раз в 100 шагов; частота на живом прогоне не меняется; часы монитора включаются в смету ноги (у Лагуны замеры каждые 50 шагов добавили +10.5 ч, LAG-ADR-033).

### 6.3. Бронь предмета замера (LAG-ADR-058)

Ретенция раннера — `--keep-last=2` (`tools/pretrain_run.py:164`): чекпойнт живого прогона может быть удалён под читающей пробой. Правила:

1. предмет замера бронируется **до** старта: hardlink (та же ФС) или копия чекпойнта в каталог замера; напрямую живой `*run*/checkpoints/` проба не читает;
2. sha256 снимается **с копии** до запуска пробы; расписка `RECEIPT.json` (путь копии, sha256, время брони, базовый чекпойнт) пишется до первого обращения прибора;
3. отчёт пробы называет состояние «замороженным на момент брони», а не «текущим»;
4. калибровочные чекпойнты именуются вне glob ретенции (у Лагуны `sft_probe_<step>.pt` с `PROBE_KEEP_LAST=24` — паллиатив, не гарантия: длинная проба живёт только на копии);
5. окно замера проверяется до старта: время пробы сравнивается с временем жизни предмета (шагов до вытеснения × с/шаг); проба длиннее окна — только копия.

Симптом нарушения: «чекпойнт исчез под пробой / FileNotFoundError на финальном sha после длинной пробы» — это дефект прибора, а не среды.
