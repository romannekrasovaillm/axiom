2. **Fitness/meta:** закрыто — C-005/C-036 и мета-тест зелёные с `d075e34` (ратификация выше); сущность `model/ADR-024` создана архитектором для симметрии с ADR-023 (trace_check PASS).

Прогон machinery (CPU, без GPU): `env.main generate --seed 5` → пул 20 public ({real}×{L0,L1}) + 50 holdout, 45 правил, hidden-constraints запиннены (sha256); `env.main calibrate --model stub` → `evidence/env-calib-stub-20261005/calibration-stub.json`: **pass_rate 0.0, ready: false** — честный fail-closed для заглушки, механика вердикта работает end-to-end. **R3-замер**: ~13 с/задача на полный цикл (воркспейс + arch-ml-вердикт) на CPU — на фоне минутной генерации роллаутов 8–32k накладные верификатора ~5–10 %, приемлемо (уточнить на стенде).

**Дефект генератора воркспейсов (зона линии-2, `env/**`)**: каждая задача копирует в воркспейс реальные артефакты репо целиком — `env/data/` = **35 ГБ** на 20 задач (~1,8 ГБ/задача, включая оба SFT-набора по 464 МБ; симлинков 0). Для RL с сотнями эпизодов неприемлемо (диск 87 % занят, время материализации). Требуется: минимальный снапшот воркспейса (только файлы, нужные задаче и гейтам) или copy-on-write. Пул на локальном диске — кандидат на удаление после подтверждения владельца (регенерация ~2 мин); дефект и запрос зафиксированы линии-2.

**Пробел проводки (зона линии-2)**: `calibrate` пока работает только на заглушке (`--model-name stub`) — калибровка §10 на **реальном чекпойнте** не подключена. Нужна дельта: `--model <checkpoint>` в calibrate (переиспользование роллаут-механики run_rl_smoke) — до неё реальный сигнал R1 недостижим; альтернатива — RL-смоук на чекпойнте пилота (его verdict_mix ≈ pass-rate).
