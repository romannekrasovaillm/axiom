# ADR-001. Модель с нуля как «убийца Kimi K3»: масштабный класс, ось победы и архитектурная база

- Date: 2026-09-11
- Status: Proposed
- Маршрут: Critical (significance score 7) — требуется решение человека (A3) по масштабному классу и бюджету
- **Статус решений:** этапность «скелет L3 первым» — принята владельцем 2026-09-11. **Принято владельцем 2026-09-11:** этапность (скелет L3 первым), ось победы (задачи с фитнес-гейтом), архитектурная база (опубликованный дизайн K3 с пиннингом на техотчёт). **Принято дополнительно (2026-09-11):** мультимодальность в v1 (text + image + video); прочтение «чётко как K3» = **верность рецепта на нашем масштабе** (раскрытое воспроизводится дословно, пробелы источника — наши помеченные решения, см. `docs/FIDELITY-TO-K3.md`); контур RL — схема базы (K2.5/K1.5), а не наш GRPO. **OPEN:** масштабный класс L1/L1+ — решение после результатов скелета. До явного accept эти пункты не являются решением и не могут служить основанием ни для закупки GPU-часов, ни для заявлений о результате.

## Context

Цель заказчика зафиксирована как «конкурент-убийца Kimi K3», артефакт определён явно: **нейросеть с нуля, полный претрейн + пострейн + агентные способности** (собственные веса и собственный конвейер обучения, не адаптация чужих).

Первичные факты о цели (карточка `moonshotai/Kimi-K3`, техотчёт `k3_tech_report.pdf` в `github.com/MoonshotAI/Kimi-K3`, 27.07.2026; проверено 11.09.2026):

| Параметр K3 | Значение |
|---|---|
| Параметры | 2,8T всего / **104B активных** на токен |
| Слои | 93 (1 dense); внимание — 69 KDA + 24 Gated MLA |
| MoE | 896 экспертов, 16 выбранных + 2 общих, Latent MoE dim 3584 |
| Контекст | 1 048 576 токенов, нативная мультимодальность (text/image/video) |
| Активация | SiTU-GLU; vocab 160K |
| Доступность | веса открыты, лицензия Kimi K3 License (не MIT; §2–3 ограничивают Ma-a-S и требуют атрибуции при >100M MAU / >$20M мес.) |

Калибровка стоимости обучения по опубликованному прогону-аналогу (DeepSeek V3, arXiv 2412.19437: 671B/37B активных, 14,8T токенов, 2,788M H800-часов полного обучения): **343 TFLOP/s эффективных на H800** (MFU ≈ 35% от 989). Расчёт ведётся в H800-эквивалентах, аренда ≈ $2/GPU-час, C ≈ 6·N_active·D.

Ограничение контура: личный NVIDIA DGX Spark (GB10, 128 ГБ unified, 273 ГБ/с, Arm, FP4) — инференс и эксперименты, не претрейн фронтирного класса.

## Decision

Строим модель **с нуля** на максимальном масштабном классе, достижимом в личном контуре:

1. **Этап — принято владельцем 2026-09-11:** строим и проверяем **скелет L3** — 1B dense, 20B токенов, ≈ 97 H800-ч аренды (≈ $200), полный конвейер до арены. Масштабный класс (L1: 30B/3B активных ≈ $44k; L1+: 100B/6B активных ≈ $117k) **не выбран** — решение принимается отдельно, после результатов скелета.
2. **Архитектурная база — опубликованный дизайн K3** (KDA + AttnRes + LatentMoE + SiTU-GLU), пиннится на конкретную версию техотчёта; собственная новизна — в данных, пост-тренинге (SFT → RL по схеме базы) и агентном харнессе, а не в изобретении механики внимания.
3. **Ось победы (принято владельцем 2026-09-11):** задачи с фитнес-гейтом — агент приводит артефакт репозитория в соответствие с механически проверяемыми правилами; вердикт и награда — существующие fitness-правила. Сравнение с K3: тот же контракт прогона, тот же харнесс, равный бюджет рассуждений. Паритет на общих бенчмарках не заявляется.
4. **Паритет с K3 по масштабу** (2,8T/104B, 20–40T токенов, 10–20M H800-ч, ~15 МВт, капекс $400M+) **вне рамок** проекта.
5. **Первый сквозной срез — walking skeleton L3**: 1B dense, 20B токенов, ≈ $200 аренды, полный конвейер «данные → претрейн → SFT → RL по схеме базы → инференс на Spark → eval» до масштабирования. Масштаб повышается только после зелёного скелета.

**Открытый вопрос (эскалация A3, срок 2026-09-25):** бюджет аренды GPU и подтверждение класса (L1 / L1+ / иной). Без этого решения вложение GPU-часов не начинается; всё остальное в ADR архитектурно не зависит от ответа.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Паритет с K3 с нуля** (2,8T/104B, 20–40T токенов) | честная победа на фронтире, полное владение стеком | 10–20M H800-ч на один чистый прогон ($20–40M), проект целиком $100–300M+, ~15 МВт, ~16k GPU; класс затрат — датацентр, не исследовательский контур. Отвергнут по арифметике, не по вкусу |
| **Пост-тренировка / LoRA поверх открытых весов K3** | дёшево (десятки $k), сразу фронтирная база, нет риска претрейна | не «с нуля» — заданный заказчиком артефакт не выполняется; зависимость от чужого релиза и лицензии (§2–3); собственного конвейера претрейна нет |
| **Статус-кво: локальный инференс чужих весов** | ноль затрат, работает сегодня на Spark | нет предмета победы и своего конвейера; смена поколения (K4) обнуляет результат; невоспроизводимо |
| **Мелкая модель с нуля без агентного пострейна** | минимум затрат и риска | агентные способности — часть определения артефакта; без RL-этапа и харнесса результат не проверяем на целевой оси |

## Consequences

### Positive

- Появляется собственный сквозной конвейер (данные → претрейн → midtrain → SFT → RL по схеме базы → харнесс → eval с механической проверкой); он воспроизводим и переносится на следующее поколение моделей — в отличие от разовой адаптации чужих весов.
- MoE-разреженность делает претрейн достижимым в личном масштабе: 30B/3B-active обучается по цене 3B dense, а инференс в 4-бит укладывается в 128 ГБ Spark.
- Линейное внимание (KDA, 69 из 93 слоёв) — единственный известный путь к 1M контекста при ограниченной памяти: классический KV-кэш на 1M токенов в 128 ГБ не помещается ни при какой квантизации.
- Пиннинг архитектуры на опубликованный техотчёт K3 снижает риск архитектурного тупика: механика валидирована чужой лабораторией, наши риски смещаются в данные и пост-тренинг.
- Локальный инференс собственной модели снимает внешнюю API-зависимость и границу эгресса данных: приватный домен остаётся внутри контура.

### Negative

- 3B активных против 104B у K3 — разрыв ~35× по активным и ~93× по общим параметрам: паритет на общих бенчмарках недостижим в принципе, победа возможна только на узкой оси. Это обязано проговариваться в любом заявлении о результате, иначе результат ложный.
- Затраты $44–117k возникают **до** первого доказательства качества: конвейер может заработать, а результат на целевой оси — не оправдать вложение. Митигация: сначала скелет L3, масштаб — только после зелёного скелета.
- «Движущаяся цель»: к моменту результата выйдет K4/GLM-6/Qwen-4. Митигация — победа на оси против воспроизводимого baseline, а не над снапшотом модели.
- Копирование публичного дизайна не даёт научного или патентного первенства; притязание ограничивается собственным работоспособным конвейером.
- Риск срыва аренды кластера при прогоне 14–38 суток. Митигация: чекпойнтинг, разбиение прогона на этапы, резервный провайдер.
- Лицензия Kimi K3 License (§2–3) не ограничивает исследовательское использование, но блокирует продуктовую монетизацию выше порогов без договора — если контур когда-либо станет продуктом, потребуется отдельное решение (новый ADR), включая вопрос производности архитектуры.
- Техотчёт K3 может не раскрывать часть деталей обучения (состав данных, расписания, стабилизация MoE) — **gap**, закрывается чтением `k3_tech_report.pdf` и воспроизведением на скелете L3.

## Reversibility

**Costly.** Выбор масштаба обратим вниз (уменьшить модель), но потраченные GPU-часы и токены данных невозвратны; смена архитектурной базы после претрейна — фактически новый претрейн, а не рефакторинг. Откат на «пост-тренировку открытых весов K3» (альтернатива 2) остаётся доступен в любой момент при условии, что сохранены среда и стенд (ADR-002)) — поэтому среда с верификаторами обязана быть в скелете, а не отложена до масштаба. Решение по масштабному классу (L1/L1+) откатывается только вместе с прекращением проекта.
