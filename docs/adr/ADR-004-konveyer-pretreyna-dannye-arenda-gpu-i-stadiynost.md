# ADR-004. Конвейер претрейна: данные, аренда GPU и стадийность

- Date: 2026-09-11
- Status: Proposed

## Context

Претрейн — самая дорогая и самая необратимая часть проекта (ADR-001): L3 ≈ $200, L1 ≈ $44k, L1+ ≈ $117k; длительность непрерывного прогона 12 ч / 14 сут / 38 сут на 8 / 64 / 64 GPU. Любой срыв на длинном прогоне без чекпойнтинга = потеря всего бюджета этапа.

Контур: DGX Spark годится для инференса, арены и микропроверок, но не для претрейна целевого класса (1B×20B токенов ≈ 330 ч на Spark ≈ 14 суток даже для скелета; 3B-active — месяцы). Данные: приватный корпус не может быть вывезен на арендованную инфраструктуру.

## Decision

Стадийный конвейер с измеримой ценой каждого этапа:

1. **Данные (локально, на Spark):** сбор, дедупликация, фильтрация качества, токенизация, упаковка в шарды; карточка датасета с хешем, лицензиями источников и составом. На аренду уходит только подготовленный обезличенный/публичный датасет — сырой приватный корпус контур не покидает (spine AD-6).
2. **L3-скелет на аренде 8 GPU × 12 ч (≈$200):** 1B dense, 20B токенов — прогон доказывает весь конвейер: токенизация → претрейн → loss-кривая → чекпойнт → квантизация → инференс на Spark → прогон в среде → SFT → RL по схеме базы → **MOPD-консолидация**. Скелет **мультимодальный с начала** (native multimodal, как база — :766) и стартует с контекста 8K; расширение идёт отдельными стадиями: 8K → 64K в претрейне, 256K → 1M в cooldown (:797). Масштаб повышается **только после зелёного скелета**.
3. **L1: 64 GPU × ~14 суток.** Обязательно: чекпойнт каждые N шагов с асинхронной выгрузкой в объектное хранилище вне арендованного хоста; разбиение прогона на этапы с контрольными метриками между ними; возобновление с последнего чекпойнта; резервный провайдер аренды, проверенный до старта.
4. **Midetrain на доменном корпусе** (открытом) — выравнивание распределения под целевую ось до пост-тренинга.
5. **Заморозка:** base-веса фиксируются хешем и становятся входом ADR-005; повторное обучение base — только новым решением.

Оценка стоимости каждого этапа (H800-часы × цена аренды) оформляется **до** запуска и служит лимитом: превышение останавливает прогон с чекпойнтом (spine AD-8).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Обучение на собственном Spark** | нет расходов на аренду, полный контроль данных, нет вопроса вывоза корпуса | 330 ч на скелет и месяцы на целевой класс; GB10 не проектировался под длительный претрейн (273 ГБ/с памяти — узкое место для обучающих шагов). Оставлено только для микропроверок и данных |
| **Покупка GPU** | нет арендной ренты, актив остаётся | капекс при бюджете $44–117k несопоставим с объёмом задачи; простой железа между прогонами; не для исследовательского контура |
| **Монолитный прогон без этапов и чекпойнтинга** | максимальная утилизация, минимум оркестрации | один сбой = потеря 14–38 суток аренды; при аренде на споте вероятность сбоя высока. Отвергнуто |
| **Обучение на аренде с приватным корпусом** | данные «как есть», без обезличивания | вывоз приватных данных на чужую инфраструктуру — нарушение периметра; отвергнуто безусловно (spine AD-6) |

## Consequences

### Positive

- Цена ошибки ограничена этапом: срыв прогона теряет шаги до последнего чекпойнта, а не весь бюджет.
- Скелет за ≈$200 проверяет весь стек до масштабных трат — самая дешёвая точка отказа.
- Данные готовятся локально: приватный корпус остаётся в контуре, на аренду уходит только обезличенный датасет с карточкой и хешем.
- Каждый прогон имеет предварительную смету и лимит — расход становится управляемым, а не наблюдаемым по факту.

### Negative

- Чекпойнтинг и выгрузка снижают полезную утилизацию кластера: цена аренды вырастает на несколько процентов при коротких интервалах чекпойнтов.
- Стадийность и возобновление требуют собственной оркестрации (запуск, сверка метрик, ветвление при расхождении) — это отдельный компонент, который надо поддерживать.
- Подготовка корпуса локально ограничена пропускной способностью Spark (273 ГБ/с, дисковый I/O) — этап данных может оказаться длиннее ожидаемого.
- Аренда на споте дешевле, но добавляет риск прерывания; аренда на выделенных мощностях дороже — компромисс надо фиксировать сметой под конкретный этап.
- Расхождение между средой аренды и Spark (CUDA/драйверы/Arm против x86) может вылезти только на интеграции чекпойнта — обязательный прогон «чекпойнт → инференс на Spark» входит в скелет именно поэтому.

## Reversibility

**Two-way** для провайдера аренды, длительности и нарезки этапов — меняются без последствий. **Costly** для подготовки данных (токенизация корпуса — основной невозвратный труд) и **irreversible** для потраченных GPU-часов: отменить претрейн нельзя, можно только остановить.

## Amendments

### 2026-10-05. Канонический токенизатор претрейна — корпусной BPE v2 (`16e4a532…0fac`)

**Контекст.** Решение п.1 фиксировало токенизацию как этап конвейера и хеш в карточке датасета, но не фиксировало, *какой* токенизатор канонический и как связан модельный словарь со словарём корпуса. К 04.10 сложились две сущности: корпусной BPE (обучается `tools/bpe_train.py` на собранном корпусе) и заглушка скелета `net/tokenizer.py`, обучаемая в тест-контексте на `synthetic_corpus_texts` (хеш `9f8d0309…`, пин только в `net/tests/test_09_tokenizer.py`). Утром 04.10 пин переведён на v2 — BPE 160K + русский доменный корпус (вариант B; коммиты `9346888`, `aca2ff5`, `6645667`): манифест v2 был записан обрезанным хешем (дефект, пойман гейтом; урок «гейт сравнивает полные хеши артефакт↔манифест»), пин теперь — полный sha256 (64 hex, `16e4a532…0fac`), совпадающий с `tokenizer-manifest.json` tokens-v2 (17,95B токенов). Endurance-нога пилота идёт на словаре корпуса v2 с громкой фиксацией `matches_canonical=false`: раннер в packed-пути строит «канон» из заглушки скелета (фолбэк T-ov3 `tools/tests/test_pretrain_tokenizer_override.py` — файл корпусного токенизатора не найден на shard-root стенда), и заглушка ошибочно выступает «каноном».

**Decision (амендмент).**
1. Канонический токенизатор претрейна — корпусной BPE v2: полный sha256 `16e4a532…0fac`, пин `net/config.json:101`, идентичен `tokenizer-manifest.json` tokens-v2; словарь 160K, обучен на корпусе W/C + русский доменный (вариант B).
2. Заглушка скелета (`net/tokenizer.py`, `9f8d0309…`) — артефакт тест-контекста, каноническим не объявляется никогда; её хеш пиннится только в тесте. Раннерам при наличии корпусного пина в `config.json` сверять данные с пином config.json, а не с заглушкой (код-дельта — в очереди исполнителя).
3. Контракт словаря модели: `vocab_size`/embedding строятся от манифеста `tokens/` (покрытие фактических id в `.bin`) — механика K2 `tools/pretrain_run.py:742-780` остаётся; `matches_canonical=false` допустим только с громкой фиксацией в журнале.
4. Гейтовый прогон (A4/A5) при `matches_canonical=false` не является валидным вердиктом: перед гейтом пин и данные обязаны совпасть — либо пересборка данных, либо пересборка пина; тихого прогона быть не может.
5. Миграция v1→v2: пакеты v1 (`500f8023…`) — `legacy-not-checked` (§5.4 пакета уроков `docs/research/LESSONS-LAGUNA-LADDER.ru.md`); все новые ноги — только tokens-v2. Нога, начатая на v2, продолжается на v2 (словари v1/v2 несовместимы).

**Alternatives Considered.**
- *Канон = заглушка скелета, данные пересобрать под неё.* Отказ: словарь заглушки не обучен на корпусе и не покрывает русский домен; обучение на чужом словаре — потери компрессии и чужие id.
- *Два словаря (модельный + корпусной с маппингом).* Отказ: два источника истины и лишняя трансформация без пользы; покрытие id уже решается механикой K2.
- *Токенизатор v3 (переобучение на полном 20B).* Отложено: переупаковка 17,95B готовых токенов ради маржинального выигрыша не окупается. Условие возврата: систематическая фрагментация доменных терминов на CPT/SFT (высокий сплит-фактор доменных токенов по замеру).

### Negative

- Расхождение пина/данных в журнале идущей endurance-ноги остаётся до её завершения (на живой ноге не чинится — §5.2 уроков); вердикты пилота не гейтовые, поэтому п.4 их не задним числит.
- Два имени токенизатора в проекте (корпусной/заглушка) повышают риск конфлации — стражем остаётся сверка полных хешей, а не имена.

**Reversibility.** Пин в `config.json` — однострочная правка (Two-way). Пакет tokens-v2 — Costly (переупаковка). Нога, начатая на v2, необратимо продолжается на v2 (несовместимость словарей).
