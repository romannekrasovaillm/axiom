# ADR-006. Домен оси победы — архитектурные гейты собственного контура

- Date: 2026-09-12
- Status: Accepted (решение владельца 2026-09-12, выбор из четырёх альтернатив)
- Маршрут: Critical (входит в пакет ADR-001; закрывает открытый вопрос №1 паспорта кейса)

## Context

ADR-002 определил контракт среды (task spec, детерминированный verifier, microVM-runner, run manifest), но не инстанцировал домен задач: что именно агент делает и по каким правилам выносится вердикт. Это последний открытый вопрос, блокирующий реализацию CMP-005/CMP-006 и RL-стадию walking skeleton — критерий A4 требует весь конвейер (чекпойнт → инференс на Spark → RL-среда → SFT → RL по схеме базы), без среды RL-стадия нечем доказывать.

Механизм оси уже зафиксирован владельцем 11.09 в `docs/DECISION-PACKAGE.json` (`victory_axis`): «задачи с фитнес-гейтом: вердикт и награда — механические fitness-правила репозитория». 12.09 владелец выбрал конкретизацию домена из четырёх альтернатив; решение записывается до запуска обучения, как того требует AD-1.

## Decision

**Домен оси победы — архитектурные задачи собственного контура.** Агенту выдаётся задача на репозиторий/спеку кейса (уровня кейсов `домашний репозиторий`); вердикт — детерминированная функция механических гейтов arch-ml: `fitness_check` (CONSTRAINTS.yaml), `trace_check`, `spine_lint` плюс задачные тесты. Деградация любого гейта относительно исходного состояния = провал задачи.

Три источника задач (все с карточкой и хешем, AD-4):

1. **Реальные кейсы контура** — живые задачи инструментального репозитория, верификатор = его гейты.
2. **Синтетическая порча чистого кейса** — контролируемая деградация (удаление секций ADR, разрыв трассируемости, нарушение правил) → задача восстановления; вердикт = возврат гейтов в зелёный.
3. **Holdout-набор** — невыпущенные кейсы и правила, недоступные ни обучению, ни подбору (рецепт ADR-002 п.7: скрытый верификатор спарен с публичным).

Лесенка сложности: число правил CONSTRAINTS, объём кейса, доля скрытых правил, бюджет попыток. Версия набора гейтов arch-ml пиннится в манифесте прогона (AD-3, AD-4).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Код с тестами (SWE-bench-стиль)** | готовые наборы, verifier тривиален, отраслевое признание | перегретое поле: K3 сильна на этом классе, на равном бюджете против 104B активных ось проигрышна по построению — AD-1 превратит любое заявление о превосходстве в ложное |
| **Математика/алгоритмы с механической проверкой** | verifier прост и компактен | та же конкурентность, плюс тяжёлый и дорогой сбор траекторий; преимуществ перед гейтами контура нет |
| **Отложить домен до результатов скелета** | быстрый старт претрейна | противоречит правилу скелета (FIDELITY §4: ось помечена «да» → обязана быть проверена в скелете) и критерию A4; RL-стадия осталась бы недоказанной, скелет не доказал конвейер |
| **Статус-кво: домен не определён** | ноль затрат | реализация среды заблокирована, проект стоит; отсутствие сметы на RL-стадию блокирует и её запуск (AD-8) |

## Consequences

### Positive

- Ядро верификации уже существует и обкатано на живом репозитории: разработка сводится к обвязке task spec и набору задач, а не к новым verifier'ам.
- Траектории уникальны — этого домена нет у внешних моделей; сбор происходит в собственном контуре, AD-6 соблюдён без специальных мер.
- Baseline K3 сравним на том же контракте локально (веса открыты, ADR-002 п.5).
- Задачи в точности совпадают с гейтами A4/A5: одна и та же механика обслуживает reward RL, conformance и drift-check — три роли из ADR-002 без дублирования.

### Negative

- **Self-referential benchmark**: модель учится проходить гейты, написанные нами; риск «мерить себя». Митигации: ротация holdout и запрет обучения по нему (уже в NFR-001), часть задач — из сторонних кейсов/спек, кальбровочный прогон K3 до обучения.
- **Вырожденное распределение вердикта**: если K3 на кальбровочном прогоне проходит >90% или <10% задач, лестница пересобирается до запуска RL — precondition, а не post-hoc.
- Гейты тяжелее юнит-тестов (fitness+trace+spine на каждый вердикт) — бюджет `budget_seconds` в task spec должен учитывать это; иначе деградирует доля состоявшихся прогонов.
- Награда зависит от версии arch-ml (инструмент эволюционирует) — без пиннинга версии гейтов в манифесте результаты невоспроизводимы; это дополнительная нагрузка на дисциплину AD-4.

## Reversibility

**Two-way (reversible).** Домен — конфигурация среды (набор задач + набор гейтов), версионируется как `environment v1`; смена домена = новый набор задач при том же контракте ADR-002. Старые прогоны воспроизводимы по манифесту; цена смены — перепрогон baseline-кальбровки, не переделка архитектуры.
