# ADR-007. Стек реализации модели — PyTorch + Triton (FLA), не JAX

- Date: 2026-09-12
- Status: **Superseded (ADR-008, JAX / MaxText — решение владельца 2026-09-12)**. Принят в течение дня и заменён в то же окно дешёвой смены; сохранён как проработанная альтернатива и кандидат отката при деградации JAX-плана.
- Маршрут: Critical (основа реализации артефакта; закрывает пробел — стек не был зафиксирован нигде в пакете)

## Context

Артефакт кейса — собственная модель с нуля: претрейн + пострейн + агентный харнесс (REQ-001). Архитектурная база пиннута на дизайн K3: KDA + Gated MLA + LatentMoE + SiTU-GLU, NoPE, QAT MXFP4 (ADR-003, FIDELITY §1). До 12.09 стек реализации не был зафиксирован ни в одном артефакте (проверено grep по кейсу) — два исполнителя могли разойтись несовместимо (тест спайна даёт положительный ответ), что блокирует массовую генерацию кода модели.

Факты по первоисточникам (проверено 12.09.2026):

- **KDA — самая рискованная компонента — уже реализована в PyTorch-экосистеме**: библиотека flash-linear-attention (FLA) добавила Kimi Delta Attention в октябре 2025; в марте 2026 — Context Parallel для KDA и GDN (распределённый тренинг по длине последовательности — прямой путь к 1M-контексту, NFR-005). `fla-core` зависит только от PyTorch, Triton и einops. Производственное подтверждение подхода: Gated DeltaNet-кернел FLA работает в Qwen3.5-397B.
- **Moonshot открыла FlashKDA** — CUTLASS-кернел Kimi Delta Attention, drop-in для FLA (ускорение префилла до 2,22× на H20) — план Б по производительности от самого вендора базы.
- **QAT MXFP4**: torchao — PyTorch-native QAT-воркфлоу (weights/activations fake-quant, prepare-train-convert); поддержка MoE-экспертов — частичная, открытый RFC pytorch/ao#4408 (запрос MXFP4 QAT для GPT-OSS 120B MoE, issue #3547). Скелет L3 — dense 1B (FIDELITY §4), MoE появляется только на L1 — риск MoE-QAT лежит за пределами скелета.
- **RL-посттрейн**: prior art в контуре уже PyTorch — ручной GRPO (`grpo_manual.py`, стенда 4090, H2.1).

## Decision

**Модель с нуля реализуется на PyTorch 2.x + Triton-кернелах:**

1. **Модельный код** — чистый PyTorch (`nn`, autograd): KDA, Gated MLA, LatentMoE, SiTU-GLU, NoPE — собственные слои с сохранением пропорций базы (FIDELITY §1).
2. **Кернелы внимания** — FLA (`flash-linear-attention`) как reference для KDA, включая Context Parallel для длинного контекста; опционально drop-in Moonshot FlashKDA (CUTLASS) по замеру префилла. Собственные кернелы — Triton.
3. **Распределённый тренинг** — `torch.distributed` (FSDP, CP из FLA, EP для MoE на L1+); PP с виртуальными стадиями — при масштабировании за скелет (FIDELITY §4 отложила PP/EP/ZeRO/CP-инфраструктуру в L1+).
4. **QAT MXFP4 с этапа SFT** — torchao; для скелета (dense, nn.Linear) покрывается полностью; для MoE-экспертов на L1 — собственное fake-quant-расширение либо пересмотр схемы (отдельное решение перед L1, см. Negative).
5. **RL-посттрейн** — PyTorch; алгоритм по схеме базы (ADR-005), инфраструктура харнесса переиспользуется.
6. **Инференс-рантайм на Spark** (NFR-004) — выбор конкретного рантайма (vLLM / llama.cpp / собственный) — отдельное решение; чекпойнты PyTorch конвертируются в любой из них, рамка NFR-004 не меняется.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **JAX / MaxText** | сильная MoE-экосистема исследований, pmap/pjit зрелые | против решения владельца; контур RL и Spark-инференс PyTorch-центричны — пришлось бы держать два стека; KDA+CP уже готова в FLA, в JAX — нет |
| **Megatron-LM / Mcore как основа конвейера** | промышленный претрейн-конвейер из коробки,高效 кернелы | чужой монолит против артефакта кейса — собственный переносимый конвейер (README «Что и почему»); кернелы заимствовать можно, базу — нет |
| **Чистый eager PyTorch без кернелов** | минимальный порог входа, всё «из коробки» | MFU упадёт в разы; смета 22k H800-ч выведена от якоря DeepSeek V3 (кастомные кернелы) и станет ложью — стоимость претрейна необратимо вырастет |
| **Статус-кво: стек не фиксирован** | ноль затрат сейчас | несовместимый расход исполнителей (тест спайна положительный); массовая генерация кода модели заблокирована |

## Consequences

### Positive

- Самая рискованная компонента рецепта (KDA) приходит с готовой отрепетированной реализацией и CP — главный технический риск скелета снимается чужими руками.
- Один стек на весь контур: модель, RL-посттрейн (grpo- prior art), QAT (torchao), данные/токенизация (HF, CMP-001) — нет второго рантайма.
- FlashKDA от вендора базы — готовый план Б по скорости префилла.

### Negative

- **Производительность = работа по кернелам**: смета валидна только при достойном MFU; eager-фолбэк для KDA годится для скелета (~$200), но перед L1 обязателен замер и выбор FLA-Triton vs FlashKDA-CUTLASS.
- **MoE-QAT MXFP4 — partial в torchao** (RFC #4408): перед L1 нужно либо собственное fake-quant-расширение, либо пересмотр схемы квантизации экспертов — отдельное решение, попадает в пересчёт сметы L1 (NFR-003, уже помечена нижней границей из-за мультимодальности).
- Triton-кернелы привязывают граф к GPU-архитектуре (FLA заявляет NVIDIA/AMD/Intel-верификацию — риск умеренный, но для Spark/GB10 нужно проверить сборку Triton) [ТРЕБУЕТ ПРОВЕРКИ перед скелетом].

## Reversibility

**Reversible до запуска претрейна L1, costly после.** На скелете L3 цена смены стека ≈ переписывание модельного кода без затрат на GPU-часы (~$200 прогон). После L1 модельный код и кернелы — капитальные артефакты; смена стека = проект заново. Поэтому решение фиксируется до массовой генерации кода, этим ADR.
