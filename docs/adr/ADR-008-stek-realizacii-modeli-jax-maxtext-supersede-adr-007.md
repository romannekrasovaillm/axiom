# ADR-008. Стек реализации модели — JAX / MaxText (supersede ADR-007)

- Date: 2026-09-12
- Status: Accepted (решение владельца 2026-09-12). Supersedes ADR-007 (PyTorch + Triton/FLA) — сменил решение владельца в единственное окно дешёвой смены: модельный код не написан.
- Маршрут: Critical

## Context

ADR-007 зафиксировал PyTorch + Triton/FLA по решению владельца. 12.09 владелец переоценил выбор в пользу JAX («как у лидеров рынка») — и это его право в единственном окне, когда цена смены ≈ ноль (код модели не написан). Дисциплина требует не переигрывать решение, а исполнить его честно: с реальной картиной рисков JAX-стека для рецепта K3, а не с картинкой PyTorch-ADR с заменёнными словами.

Факты по первоисточникам (проверено 12.09.2026):

- **MaxText** (github.com/google/maxtext, README прочитан): high-performance LLM-библиотека на чистом Python/JAX, таргет TPU **и GPU**, претрейн до десятков тысяч чипов, официальный путь «building models from scratch — fork and modify MaxText». Стек: Flax (NNX), Tunix (пост-тренинг), Orbax (чекпойнты), Optax, Grain.
- **Kimi-семейство поддержано**: K2 + MuonClip-оптимизатор (04/2026), K2-Thinking / K2.5 / K2.6 text (05/2026, `Run_Kimi.md`) — конверсия чекпойнтов и рецепты существуют; **Muon** в MaxText с 12/2025.
- **Пост-тренинг из коробки**: SFT, **GRPO и GSPO** (Tunix), multi-host RL-туториалы; MTP-тренинг (07/2025 — у K3 MTP-слой есть); MoE-кернелы Tokamax GMM v2 (08/2026); нативная мультимодальность (Gemma 4, Llama 4 VLM); расширяемость кастомными архитектурами показана поддержкой Engram/mHC от DeepSeek-AI (03/2026).
- **KDA в JAX-экосистеме НЕ найдена**: MaxText поддерживает K2-семейство (MLA), KDA появилась только в K3; в Megatron Core поддержка K3 тоже в работе (NVIDIA/Megatron-LM issue #6872), не готова. FLA — PyTorch-only. **KDA-кернелы — наша работа (JAX + Pallas).**
- **QAT MXFP4 в JAX**: готового эквивалента torchao не найдено при поиске 12.09 [ТРЕБУЕТ ПРОВЕРКИ при старте скелета: google/aqt и др.]; fallback — собственная fake-quant реализация (straight-through estimator) в JAX, помечается «наше» по FIDELITY §3.
- JAX на TPU — территория лидеров (Gemini-класс [по памяти, требует проверки]); мы арендуем H800 (INT-001) — сила JAX нужна нам на GPU: MaxText таргетирует и GPU.

## Decision

**Модель с нуля реализуется на JAX, база — форк MaxText:**

1. **База конвейера** — MaxText (JAX + Flax NNX): претрейн, распределённость (sharding/TP/PP/EP/CP — конфигурацией, не своим кодом), MTP, Orbax-чекпойнты. Форк и модификация — официально рекомендованный путь для с нуля.
2. **KDA** — собственная реализация по статье K3: двухшаговый план — (а) JAX-referенс (eager/scan, без кернелов) для проверки механики на скелете, (б) кернелы JAX-Pallas до L1 с замером MFU. Gated MLA — за основу брать реализацию K2-семейства в MaxText.
3. **Оптимизатор** — Muon из MaxText, адаптация до per-head Muon (K3 :772) — наша правка, помечается.
4. **Пост-тренинг** — Tunix SFT + GRPO по схеме базы (ADR-005: групповое преимущество + log-ratio-маска — настройка/расширение Tunix, не сторонний алгоритм).
5. **QAT MXFP4 с этапа SFT** — собственная fake-quant в JAX либо AQT [ТРЕБУЕТ ПРОВЕРКИ]; для скелета — минимум на dense-путь, проверка 4-бит на Spark (FIDELITY §4).
6. **Чекпойнты** — Orbax → каноническое хранилище `~/gb10-shared` (симлинки, C-032, хеш по содержимому AD-4). Конверсия для инференс-рантайма Spark — в рамках NFR-004, отдельное решение.
7. **RL-среда** (environment v1, спека уже готова и реализуется харнессом) — от стека не зависит: верификаторы/награда/манифест — Python-обвязка над arch-ml.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Остаться на PyTorch + FLA (ADR-007)** | KDA готова + CP, FlashKDA drop-in, torchao QAT, Megatron-гравитация (#6872) | против обновлённого решения владельца; уже не рассматривается как база |
| **MaxText без форка, только конфиги** | ноль кода конвейера | KDA/per-head Muon/native-multimodal-K3-рецепт конфигами не выражаются — форк обязателен |
| **Собственный JAX-конвейер без MaxText** | полный контроль | переписывание решённого: шардирование, чекпойнты, RL-инфра — против экономики личного контура |
| **Гибрид PyTorch-модель + JAX-эксперименты** | — | два стека в одном контуре; отклонён владельцем при выборе |

## Consequences

### Positive

- Конвейер претрейна/посттрейна приходит решённым: шардирование, MTP, Muon/MuonClip, GRPO/GSPO, чекпойнты — конфигурация и точечные правки вместо чужого монолита и вместо своего с нуля.
- K2-семейство в MaxText = конверсионная дорожка для baseline-сравнений и готовые приёмы для Gated MLA.
- Функциональная чистота JAX упрощает GRPO (детерминированные вычисления, jit-компиляция наград-агностичных rollout-петель).
- Портативность на TPU остаётся открытой дверью, если контур вырастет.

### Negative

- **KDA — наша работа с нуля (JAX + Pallas)**: главный технический риск проекта возвращается в проект; двухшаговый план (referенс → кернелы) удлиняет скелет. До готовности кернелов MFU на H800 низкий — скелет терпит (~$200), смета L1 пересчитывается после замера (NFR-003 и так нижняя граница).
- **QAT MXFP4 — своя реализация** (AQT не подтверждён): уход от torchao-готовности; риск скелета умеренный (dense), риск L1 (MoE-эксперты) — на пересчёте L1.
- **JAX-компетенция** — более узкий пул исполнителей и меньше готовых ответов на StackOverflow; отладка jit-графов специфична.
- **Откат на PyTorch после старта претрейна — costly** (ADR-007 остаётся в истории как проработанная альтернатива, но FLA/FlashKDA/torchao-плюсы при откате придётся восстанавливать заново по факту деградации JAX-плана).
- Проверки перед скелетом: JAX/MaxText на GB10 Spark (инференс) и на арендованных H800 (обучение) [ТРЕБУЕТ ПРОВЕРКИ — первый smoke-тест].

## Reversibility

**Reversible сейчас (код модели не написан), costly после старта претрейна.** Это последнее дешёвое окно смены стека; зафиксировано ADR-008. При деградации JAX-плана (KDA-кернелы не выходят по MFU к L1, QAT не собирается) — эскалация владельцу с evidence, кандидат отката — ADR-007 как проработанная схема.
