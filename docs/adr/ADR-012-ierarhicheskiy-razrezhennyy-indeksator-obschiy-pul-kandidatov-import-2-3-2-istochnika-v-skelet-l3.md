# ADR-012. Иерархический разреженный индексатор: общий пул кандидатов (импорт §2.3.2 источника в скелет L3)

- Date: 2026-09-13
- Status: Proposed (решение владельца 2026-09-13 принято: вариант «импорт пула кандидатов» выбран против «гибрида по длине» и «остановить прогон»)
- Маршрут: Standard (изменение механики длинного контекста + существенный NFR стоимости)
- Связь: AD-5 (архитектурная база — опубликованный дизайн), AD-9 / ADR-009 D2, AD-8 (смета), критерий приёмки A4 №16

## Context

**Критерий 16 красный.** `net/tests/test_15_cost_8k_64k.py`: forward на 8K идёт **2.054×** против плотного пути при пороге ≤1.05× (время); память 0.041× — зелёная. На 64K: время 0.849×, память 161 МБ против расчётных 206 ГБ — то есть плотный путь на 64K **не исполним** (подтверждено OOM на 16 ГБ GPU при независимом прогоне 13.09), разреженный является не оптимизацией, а условием возможности длинного контекста.

**Где теряется время (профиль 8K, GPU, end-to-end 20.65 мс):** `top_k` по всему префиксу ≈ 10.4 мс (**50%**), gather+attention ≈ 8.1 мс (39%), SWA ≈ 1.6 мс (8%), indexer-einsum ≈ 0.7 мс. Причина архитектурная: точный отбор `O(T²·log T)` выполняется **в каждом из 6 MLA-слоёв независимо**, а gather полных fp32 K/V даёт ≈12.8 ГБ трафика против ≈6.4 ГБ у плотного пути.

**Поправка к прежней записи.** Ранее в отчёте дельты механизм был атрибутирован как «ADR-009 Alternatives 5». Это неверно: Alternative 5 в ADR-009 — «Кросс-слойное переиспользование KV (CSA2 Full/Reindex/Reuse)», **отвергнутое** решение (семантика расходится при разрежении каждого четвёртого слоя). Фактический источник механизма — **техотчёт V4.1-Flash §2.3.2** (`docs/research/v41-flash-report-extract.md:37`): «Первый CSA2-слой декодера в режиме Full выбирает свои Top-512 и строит **общий пул кандидатов** из выбранных блоков (blockwise: максимум скора блока)». Зафиксировано, чтобы решение не опиралось на несуществующую ссылку.

**Отношение к принятому ADR-009 D2.** D2 выбрал «CSA2-lite»: лёгкий indexer → `top_k` в 6 MLA-слоях, **без** компрессии последовательности и **без** кросс-слойных режимов. Иерархический пул кандидатов — расширение именно этого места, поэтому оформляется новым ADR (AD-9: изменение механики длинного контекста — только декларативно и только новым решением).

## Decision

Импортировать иерархический разреженный индексатор §2.3.2 в скелет L3 — двухуровневый отбор с общим пулом кандидатов:

1. **Уровень 1 (пул):** первый MLA-слой (режим *Full*) считает скоры по блокам и строит **общий пул кандидатов** — top-`m` блоков по максимуму скора в блоке (blockwise max), стоимость отбора амортизируется на остальные слои.
2. **Уровень 2 (выбор внутри пула):** остальные MLA-слои выбирают свои `top_k` **внутри пула** (режим *Reindex* — своя переоценка скоров внутри пула; *Reuse* — переиспользование выбора), а не по всему префиксу.
3. **Декларативность (AD-9):** раскладка режимов по слоям, размер блока пула, `m` и `top_k` задаются в `net/config.json` и дублируются строкой в `deviations`; правка кода по месту запрещена.
4. **Оракул сохраняется:** плотный путь остаётся за флагом как оракул до снятия гейта A4; критерий 13 (`mla_top_k ≥ T`, `swa_window = 0` → совпадение с плотным до 1e-4) остаётся в силе и распространяется на путь с пулом.
5. **Порог критерия 16 не меняется** (8K ≤ 1.05×, 64K строго лучше) и методика замера не меняется.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Гибрид по длине** (ниже кроссовера — плотный путь, выше — разреженный; параметр `sparse_min_len`) | Критерий 16 выполняется по букве без изменения порогов: 8K = 1.0× (плотный), 64K = 0.849×; дёшево — faст-path критерия 13 уже реализован | Меняет предмет измерения: разреженный путь не проверяется на короткой длине вовсе; **конфликтует с ADR-009 D5** (train-aware симуляция sparse/окна во всех стадиях): обучение на 8K шло бы плотным путём, инференс на 16K+ — разреженным, то есть расхождение train/inference. Отвергнуто владельцем 2026-09-13 |
| **Остановить прогон** (буква критерия 16: «иначе — новый расчёт сметы, прогон не стартует») | Контракт приёмки неприкосновенен; никаких сомнительных обходов | A4 останавливается на неопределённый срок; при этом 64K-выигрыш (161 МБ против неисполнимых 206 ГБ) уже получен и им нельзя воспользоваться. Отвергнуто |
| **Статус-кво** (оставить точный `top_k` в каждом слое = 2.054×) | Ничего не делаем | Критерий 16 красный, прогон A4 не стартует (AD-8/C-041) |
| **Выбранный: общий пул кандидатов §2.3.2** (амортизация отбора между слоями) | Бьёт прямо в измеренное узкое место (50% времени на `top_k` × 6 слоёв → 1 построение пула + переоценка внутри пула); механизм есть в источнике, значит укладывается в AD-5; декларативен и обратим параметром | Приближённый отбор: recall внутри пула < 1 при `m` < всех блоков; на случайных весах indexer'а blockwise-max даёт низкий recall (наблюдение 0.1–0.7) — корректность проверяется не только смоуком, но и на обученной модели; остаётся вторая половина узкого места (gather 39%) — возможно, 1.05× не достигается и после импорта |

## Consequences

### Positive

- Устраняется главный измеренный дефект: отбор кандидатов перестаёт считаться 6 раз независимо — строится один раз и переиспользуется.
- Механизм взят из опубликованного дизайна (§2.3.2), а не изобретён: не нарушает AD-5, отклонения по реализации допустимы и помечаются в `deviations`.
- Решение декларативно и обратимо: раскладка режимов и параметры пула — конфигурация, а не правка кода.
- При успехе критерий 16 закрывается честно, без сдвига порогов и без сокрытия короткой длины — A4 разблокируется по существу, а не по формулировке.

### Negative

- **Приближённый отбор.** Пул из top-`m` блоков может не содержать истинно релевантные записи: recall отбора < 1. На случайных весах indexer'а blockwise-max даёт recall 0.1–0.7 — то есть на смоуке механизм выглядит слабее точного `top_k`; судить о нём можно только после претрейна/тёплого старта indexer'а. Принимаем риск: проверка на скелете стоит ≈$200 против $44k на L1 (та же логика, что в ADR-009).
- **Не гарантирует достижения 1.05×.** Пул снимает часть дефицита (`top_k` 50%), но gather+attention (39%) не затрагивает. Если цель не берётся — честный отчёт с профилем, а не правка порога.
- Усложнение пути: два уровня отбора, раскладка режимов по слоям, дополнительный параметр `m`, больше мест для ошибки — растёт потребность в тестах (эквивалентность при `m`, покрывающем префикс; регрессия на индексер).
- Кросс-слойная связность: слои перестают быть независимыми по отбору (пул — общий), это меняет профиль ошибок и усложняет отладку: расхождение в первом Full-слое каскадно влияет на пять остальных.

## Reversibility

**costly.** Параметры пула и раскладка режимов обратимы конфигурацией (вернуть точный `top_k` = выключить пул), но как только путь участвует в приёмочных прогонах A4/A5, откат меняет вердикты критериев 13/16 и требует пересмотра evidence-пакета. Окно дешёвой смены — сейчас: A4 не закрыт, манифеста нет, претрейн не запущен.
