# ADR-013. Детерминизм вычислений на GPU для A5: `xla_gpu_deterministic_ops` в гейтовом профиле

- Date: 2026-09-13
- Status: Accepted (решение владельца 2026-09-13: выбран пиннинг ядер; варианты «A5 на CPU» и «канонизация артефактов» отклонены)
- Маршрут: Standard (изменение условий приёмочных прогонов; затрагивает AD-2, AD-4, ADR-010 и гейт A5)
- Связь: AD-2 (механический вердикт), AD-4 / ADR-010 (пиннинг), ADR-011/C-042 (стражи предметны), критерии A4/A5

## Context

**Находка 13.09.2026 (при реализации ADR-010).** Тест `net/tests/test_13_integration.py::test_end_to_end_manifest_and_determinism` проверяет A5-инвариант: два одинаковых прогона (одинаковый `run_id`, seed, spec) дают **идентичный манифест**. Наблюдения:

| Конфигурация | Результат |
|---|---|
| baseline `f3eaf0d`, CPU | ✅ 304 с |
| baseline `f3eaf0d`, GPU (дефолтная политика точности) | ✅ 544 с |
| ветка ADR-010, CPU-профиль (`NET_JAX_BACKEND=cpu`) | ✅ 330 с |
| ветка ADR-010, **gate + GPU + `matmul_precision=highest`** | ❌ 894 с (расхождение) / ✅ 611 с на повторе |

Расхождение — в поле `workspace_sha256`: оно считается как `tree_sha256(out_dir)` (`env/net_executor.py:147`) — content-addressed sha256 по отсортированным парам (относительный путь, sha256 содержимого) файлов снапшота рабочего пространства (`env/util.py:43`). Снапшот создаётся `copy_case_snapshot` (исключены `env/`, `evidence/`, `__pycache__`, скрытые, `*.pyc`, `*.html`) и содержит артефакты прогона. Значит **содержимое артефактов между двумя формально одинаковыми прогонами различается**, когда вычисления идут на GPU.

Причина: XLA по умолчанию **не гарантирует побитовый детерминизм операций** на GPU (недетерминированные редукции/атомарные операции). Пока бэкенд выбирался оболочкой, A5-прогон мог идти на CPU и «случайно» совпадать; ADR-010 сделал GPU обязательным для гейтового профиля (`test_10_gpu_smoke` — PASS, не SKIP) и A5 начал честно краснеть. То есть это не регрессия дельты, а **вскрытое свойство контура**: вердикт воспроизводимости зависел от окружения, как и критерий 2 до пиннинга.

Действующие ограничения: AD-2 требует механического вердикта; AD-4 — пиннинга; A5 прямо требует «повторный прогон по манифесту даёт тот же вердикт». Флейки-вердикт этим требованиям не удовлетворяет.

## Decision

Включить детерминированные операции XLA в **гейтовом** профиле прогонов кейса:

1. `net/tests/conftest.py` (единственная точка пиннинга, ADR-010) при `NET_GATE_PROFILE=1` выставляет `XLA_FLAGS=--xla_gpu_deterministic_ops` **до** инициализации JAX; в локальном профиле флаг не ставится (скорость итераций важнее).
2. Пиннинг объявляется в заголовке прогона вместе с политикой точности и `jax.devices()` — вердикт несёт платформу и режим детерминизма, в которых он получен.
3. Страж C-042 расширяется: в гейтовом профиле проверяется не только `matmul_precision=highest` и CUDA-устройство, но и фактическое наличие `--xla_gpu_deterministic_ops` в окружении прогона (runtime-проверка, не grep по файлу).
4. A5-приёмка (два прогона → идентичный манифест) выполняется на GPU в гейтовом профиле; повторная проверка стабильности — не менее 3 прогонов подряд без расхождения.
5. Изменение не касается порогов критериев, методики замеров и точности оракулов.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **A5 на CPU, GPU — только для производительности** | Нулевая цена по скорости; на CPU побитовость есть всегда (подтверждено: 304 с и 330 с, стабильно зелёный) | Воспроизводимость доказывается на **другом** бэкенде, чем продуктовый прогон: манифест GPU-прогона остаётся вне проверки A5. Для агентной оси (rollout'ы идут на GPU) это ослабление существенное. Отклонено владельцем |
| **Канонизация артефактов перед хешированием** (хешировать вердикт/структуру, а не биты) | Быстрее, чем детерминированные ядра; устойчиво к любому железу | Ослабляет проверку: побитовое сравнение заменяется сравнением канонизированного представления, часть реального дрейфа (численные сдвиги) перестаёт ловиться. Отклонено владельцем |
| **Статус-кво: принять флейки** | Ничего не делаем | A5 не форсится, вердикт зависит от случая; прямое нарушение AD-2 (механический вердикт). Отклонено |
| **Выбранный: `--xla_gpu_deterministic_ops` в гейтовом профиле** | A5 форсится на том же бэкенде, что и продуктовый прогон; инвариант неприкосновенен; флаг декларативен и виден в заголовке вердикта | Замедление GPU-прогона; часть ядер может не иметь детерминированной реализации → возможна ошибка компиляции/исполнения; остаётся риск, что детерминизм гарантирован не для всех операций пути |

## Consequences

### Positive

- A5 становится механическим на том же бэкенде, на котором идёт продукт: «повторный прогон → тот же манифест» перестаёт зависеть от случая.
- Вердикт несёт объявленный режим детерминизма в заголовке — читатель видит, в каких условиях он получен, а не догадывается.
- Находка зафиксирована в артефактах (`evidence/net-suite-verdict-2026-09-13-adr010.md`, §5), а не списана на «флейки теста».
- Локальные итерации не замедляются: флаг только в гейтовом профиле.

### Negative

- **GPU-прогон становится медленнее.** Детерминированные ядра могут терять в производительности на редукциях; цена в минутах гейтового прогона фиксируется замером, а не оценивается на глаз.
- **Возможен отказ вместо недетерминизма:** если операция из пути не имеет детерминированной реализации, XLA может упасть — тогда выбор сужается до «CPU для A5» или «канонизация», то есть к отклонённым вариантам. Риск принимается; проверяется первым же прогоном.
- **Детерминизм неполон по определению:** флаг покрывает операции XLA, но не гарантирует отсутствие недетерминизма на уровне, например, некоторых библиотечных вызовов вне XLA. Поэтому A5-проверка остаётся статистической: 3 прогона подряд, а не доказательство для всех возможных запусков.
- Расширение стража C-042 усиливает связность тестов с профилем: локальный прогон проверяет меньше, чем гейтовый, — это надо держать в голове при чтении зелёного локального результата.

## Reversibility

**costly.** Флаг — одна строка в `conftest` и одна проверка в страже, снять его дёшево технически. Но если A5-вердикты уже получены с ним (а без него они флейкуют), откат означает признание A5 непроверяемым на GPU — то есть пересмотр приёмки A4/A5 и evidence-пакета. Окно дешёвой смены — сейчас: A4 не закрыт, манифеста нет.
