# ADR-017. Вычислительный стек остаётся JAX; Rust только точечно через FFI и на инференсе

- Date: 2026-09-25
- Status: **Accepted** — ратифицировано владельцем явно 2026-09-26 («принимай адр-017») после
  проверки фактов по первоисточникам и подтверждения прецедентом xAI; маршрут значимости Critical
  (new_vendor, irreversible_migration, существенный NFR, критичность). Решение-обёртка над ADR-008.

## Context

Возник вопрос «есть ли JAX под Rust — если да, мигрируем». Проверка по первоисточникам (25.09.2026):

- **Официального порта JAX на Rust не существует.** JAX — Python-API над XLA. Официальный
  механизм интеграции Rust — **JAX FFI**: кастомные ops на Rust, вызываемые из Python-JAX
  (jax-ml/jax discussion #24187; пример `rust-jax-ffi`).
- Крейт `jax-rs` 0.5.1 (docs.rs) — тёзка-одиночка «JAX in Rust для веба»: CPU/WASM/WebGPU,
  **без CUDA**, соло-мейнтейнер. Не кандидат в тренинг-стек.
- Поддерживаемых Rust-биндингов XLA на crates.io нет (крейт `xla` — 404).
- Реальные Rust-фреймворки (Burn, Candle, dfdx, tch-rs) — это *не* JAX: нет XLA-градус
  компиляции (jit/vmap/pmap), нет форка MaxText (ADR-008), нет аналога Pallas под наши KDA-кернелы,
  нет RL-экосистемы уровня Tunix.

Наш контур жёстко держится на текущем стеке: KDA-кернелы на JAX+Pallas, MaxText-форк,
парити-тесты (`net/tests/test_02_kda_parity.py` и др.), Muon/Newton–Schulz, BF16-пайплайн,
RL-среда и харнесс. Оценка значимости миграции стека: **Critical** (смена вендора,
необратимая миграция, существенный NFR перф/детерминизм, критичность конвейера).

## Decision

1. **Стек axiom остаётся JAX** (подтверждение и граница ADR-008). Полный перенос на Rust
   отклонён до результатов скелета L3 и не запускается без нового Critical-ADR.
2. **Rust допускается только точечно**, там, где он даёт реальную выгоду, без замены стека:
   - **JAX FFI**: кастомные вычислительные ops на Rust, если Pallas упрётся в потолок
     (KDA-кернелы, sparse/индексные операции);
   - **инференс/сервинг** на Rust (Candle/Burn-класс) на этапе инференс-фазы L3 — при
     появлении требований tok/s/латентности, которые Python-сервинг не закрывает;
   - обычные CLI-инструменты — вне этой политики (язык по целесообразности).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Остаться на JAX** (принят) | Сохраняем парити-тесты, MaxText-форк, Pallas-кернелы, RL-стек, сроки; миграционный риск = 0 | Остаются Python-ограничения (GIL в харнессе, скорость интерпретатора в инструментах) |
| Полный перенос на Rust (Burn/Candle) | Один язык, потенциальная скорость инференса, компиляция в натив | Переписка скелета+среды+харнесса (месяцы), потеря MaxText/Pallas/Tunix, незрелые CUDA-бэкенды, отставание претрейна; модель не приближается ни на день |
| `jax-rs` (крейт) | Формально «JAX на Rust» | Без CUDA, без XLA, масштаб веб-игрушки; не удержит L3 ни в каком режиме |
| **Julia + Reactant.jl** (EnzymeML → MLIR → XLA) | Настоящий «JAX-опыт» вне Python: jit/vmap-подобный трейсинг, autodiff через EnzymeMLIR, CPU/GPU/TPU | Экспериментальный проект с меняющимся API; экосистема LLM-тренинга (Flax/Equinox/MaxText/Tunix/Orbax/Levanter) живёт в Python — всё нужное пришлось бы писать самому; multi-GPU/нода ещё в работе |
| **C/C++ напрямую через PJRT C API** | Исполнение StableHLO без Python (проверено: пример epicure-hpc, 08.2026) | Это рантайм-исполнитель, а не JAX: нет трейсинга/autodiff/vmap/jax.numpy; фронтенд пришлось бы писать самому — проект-летне, не кейс |

## Consequences

### Positive

- План претрейна L3 не сдвигается; инвестиции в JAX-код и тесты сохранены.
- Зафиксирована точка возврата: Rust-трек возможен (FFI/инференс) без ревизии стека.
- Снят риск повторного «а давайте перепишем» — критерии пересмотра формализованы (ниже).

### Negative

- Языковая привязка к Python-экосистеме сохраняется; если Rust-XLA созреет внезапно,
  часть выгоду (компиляция, деплой) мы получим позже, чем могли бы при раннем переносе.
- Гибридный стек (JAX+Rust-ops) несёт стоимость сборки двух тулчейнов (nanobind/cxx против
  автосгенерированных биндингов — типы `Buffer`/`Binding` в FFI переносятся плохо, см. #24187).
- Условие «переписать на Rust» остаётся соблазном для будущих сессий — дисциплину держит
  этот ADR и правило C-031-стиля: любое изменение стека = новый Critical-ADR.

## Reversibility

**costly → reversible на уровне решения, irreversible на уровне кода.**
Остаться на JAX ничего не блокирует. Начатый перенос на Rust был бы фактически необратим
без потери месяцев (переписка скелета, среды, парити-тестов). Поэтому решение «не мигрировать»
дешёво и обратимо, решение «мигрировать» — дорого: оно и требует нового ADR.

**Триггеры пересмотра** (любой — повод для нового ADR):
1. Pallas/компилятор XLA упирается в потолок на KDA-кернелах, и FFI-op на Rust даёт измеримый
   прирост (критерий: p99 шага претрейна, ≥10%).
2. Инференс-фаза L3: Python-сервинг не закрывает цели tok/s на GB10.
3. Появление поддерживаемого Rust-XLA или зрелого CUDA-бэкенда у Burn с LLM-тренинг-экосистемой
   (перепроверка фактов по первоисточникам обязательна).
