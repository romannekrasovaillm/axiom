# ADR-019. Narrow-but-deep — гипотеза пропорций для L1-конфига (заимствование Step-5)

- Date: 2026-09-26
- Status: **Accepted как гипотеза-альтернатива** — решение владельца 26.09.2026 («берём narrow but deep»)
  по model card Step-5-Preview (92 слоя narrow-deep, 600B/27B active, 1M контекст).
- Форма решения: НЕ смена конфигурации скелета (L3 остаётся по MODEL-L3-SKELETON: 24 слоя, база K3),
  а внесение пропорции «глубже-уже» как проверяемой альтернативы в пакет выбора L1.

## Context

StepFun в Step-5-Preview сознательно строит 92-слойный «narrow but deep» трансформер с обоснованием:
длинные пути распространения информации для implicit multi-hop reasoning при длинных префиллах —
то есть пропорции сети связываются с агентной работой на длинном контексте. Ось победы axiom —
агентные задачи с механическим вердиктом (ADR-001/006), и L1-конфиг (MoE ~30B total / ~3B active)
ещё не зафиксирован: решение владельца 11.09 отложено до результатов скелета. Существует окно
внести альтернативу пропорций до выбора L1.

## Decision

1. В пакет выбора L1 (масштабный класс, хвост ADR-001 / DECISION-PACKAGE.json) вносятся ДВЕ
   альтернативы пропорций, обе при равном бюджете ~30B total / ~3B active:
   - **A — «широко-неглубокая» (статус-кво):** пропорции в духе базы K3 (наш скелет L3 — прямое
     масштабирование по слоям 24→~48).
   - **B — «narrow but deep»:** тот же param_budget, существенно больше слоёв, уже hidden
     (ориентир класса Step-5: layers↑, hidden↓ при том же total), скрытая гипотеза — выигрыш
     в multi-hop/агентных задачах на длинном контексте.
2. Проверка — по оси победы: обе пропорции сравниваются на лестнице сложности среды (механический
   вердикт), цена претрейна одинаковая (param_budget равен) — решение владельца по результатам,
   НЕ по чужим бенчмаркам.
3. Проверка stability на скелете ДО L1 не планируется: скелет остаётся базе-верным (AD-5),
   узко-глубокая стабильность MoE (router collapse на глубоких стеках) — риск, отмечаемый в
   пакете L1; дешёвого смоук-замера этой гипотезы нет, смоук tiny/small не переносится на
   пропорции 30B.

## Alternatives

- **Зафиксировать narrow-deep сразу для L1 без сравнения:** решение по чужому bенчмарку без
  собственного вердикта — нарушает ось победы (равный бюджет, механический вердикт) — отклонено.
- **Отклонить гипотезу (только статус-кво):** выбрасываем дешёвую альтернативу из окна до
  выбора L1; Step-5 даёт наблюдение топ-3 open-weight на этой пропорции — отклонено.
- **Проверить пропорции на скелете:** скелет — base-верный провод конвейера (AD-5, ≈$200);
  превращать его в A/B по пропорциям = +1 претрейн — отклонено (проверка на L1 по оси победы).

## Consequences

Positive: L1-выбор становится двухальтернативным с механическим правилом сравнения; гипотеза
состыкована с нашей осью (агентные задачи, длинный контекст). Negative: A/B на L1 удваивает
претрейн-бюджет класса (2×~$44k), если владелец решит сравнивать честно; риск router-collapse
на глубоких стеках MoE — требование стабилизаторов (router z-loss и т.п.) в спеке L1 при выборе B.
Reversibility: решение — про состав альтернатив, не про веса; полностью обратимо до старта L1.

## Reversibility

Обратимо полностью до фиксации L1-конфига и запуска L1-претрейна.
