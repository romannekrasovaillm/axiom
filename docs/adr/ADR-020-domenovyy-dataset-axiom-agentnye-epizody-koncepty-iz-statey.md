# ADR-020. Доменный датасет axiom: агентные эпизоды + концепты из статей

- Date: 2026-09-26
- Status: **Accepted** — решение владельца 26.09.2026 (идея «сессии агентов → эпизоды → датасет» +
  расширение «добавить концепты из статей»). Маршрут Standard (new_component, new_datastore,
  data_contract_change): ADR → дельты пайплайна кодовым харнессом → гейт качества данных.
- Рамка: **пострейн-данные** (SFT/CPT/RL-домен), НЕ претрейн. Претрейн остаётся публичным
  корпусом по ADR-004. Датасет приватный — AD-6, в контуре, на аренду не уходит.

## Context

- На машине владельца 1378 сессий Claude Code (~0,5 ГБ jsonl) + qwen (573 МБ) + codex + harness-логи
  — суммарно ~0,2–0,4B токенов после чистки. Это 1–2% претрейн-объёма (20B) — как претрейн-наполнитель
  бесполезны, но как **агентные траектории с механическим вердиктом** (fitness-гейты контура) —
  верифицированное SFT/RL-ядро оси победы. Подтверждается практикой Step-5 (агентные траектории
  из реальных tool-use сред в тренировочной смеси).
- Библиотека концептов `/home/roman/library` — 289 041 концепт-файлов (7,2 ГБ, уровни α/β/γ,
  типы algorithmic / architectural_component / benchmark / design_proposition / hypothesis / task):
  доменное знание, дистиллированное из статей. Билдеры CPT-корпусов уже существуют на gb10-shared
  (`build_sft_v*.py`, корпуса cpt_corpus_v10.1/v12r) — не дублировать, переиспользовать/дообучать.
- ADR-005: SFT-стадия требует карточку датасета (состав, sha256, лицензии, источник траекторий).

## Decision

1. **Состав датасета `axiom-domain-ds-v1`** — три компонента:
   - **E — агентные эпизоды:** сессии → эпизоды (задача → ход → инструмент → результат), формат
     контракта среды v1 (thinking_budget, tool-циклы, вердикт). Эпизод в SFT-компонент входит только
     с механически подтверждённым исходом (зелёный гейт/тесты в конце сессии); эпизоды с красным
     исходом — в negative-пул RL, не в SFT.
   - **K — концепты из статей:** карточки библиотеки (фильтр по релевантности домену axiom:
     algorithmic, architectural_component, design_proposition; уровни α/β/γ), сериализация в
     обучаемую прозу; переиспользовать существующие CPT-билдеры gb10-shared, не писать новые с нуля.
   - **D — дистилляты статей** (добавлено владельцем 26.09.2026): `/home/roman/library/distillate`
     — 5 536 md / 60 МБ (в основном `2_статьи`), прозаические разборы первоисточников. Скраб той же
     первой ступенью; **дедуп обязателен МЕЖДУ D и K** (дистиллят и концепты нередко выросли из
     одной статьи — блочные хеши + near-dup на пересечении компонентов, а не только внутри).
   - **S — скиллы** (добавлено владельцем 26.09.2026): `~/experiments/agents/0710-ariadna/plugins/`
     — 1 593 SKILL.md / 3,2 МБ, процедурный слой («md хранит знание, скилл — процедуру»). Фильтр
     релевантности домену axiom — механический, по зафиксированному в карточке списку ML/агентных
     плагинов (laguna, agentic-rl, data-curator, verification, effort, frontier-*, document-tools…);
     контурно-чужие плагины (banking, sbp-gateway, jvm-archunit, govproc…) — вне фильтра. Скраб
     обязателен: скиллы несут операционные детали контура (пути, хосты, команды). **Дедуп обязателен
     S↔D↔K** — скиллы градуируются из дистиллятов, пересечение текста с D и K ожидаемо.
2. **Пайплайн (шесть ступеней, порядок строгий):** (1) deny-list каталогов + скраб секретов
   (`*_KEY`, bearer, ssh-, приватные пути) — ДО любой обработки; (2) эпизодизация по границам
   tool-циклов; (3) верификация исхода механически; (4) дедуп: точные хеши блоков + MinHash near-dup;
   (5) фильтр шума (оборванные, циклы повторных ошибок, мусор харнесса); (6) карточка датасета
   (ADR-004): состав, хеши шард-файлов, доли, происхождение. Спот-аудит скраба после сборки.
   **Уточнения по результатам дельты-1 (решения архитектора, 26.09.2026):**
   - **Fail-closed верификации:** при противоречии источников (контракт complete vs отчёт blocked)
     эпизод получает verified-failed — ложный negative предпочтительнее ложного positive.
   - **Классы:** verified-complete / **verified-partial** (partial + механический признак зелёного
     сьюта в последних tool-результатах — допускается в SFT с флагом) / verified-failed (→ negative-
     пул, пока пул не используется — RL-задачи генерируются отдельно) / unverified (→ отбраковка).
     Частичные верификации «по окну времени» логов — флаг verification_source=log-window, доля —
     в карточке.
   - **Скраб-аудит — в точной форме** паттернов скраба (подстрочные ложняки вида «di**sk-**sizing»
     не считаются); hex_env правило НЕ трогает ключи с hash-именами (sha256/salt — не credential,
     их замена портит доменные данные); паттерн остаётся для key/token/secret/password-имён.
   - **Межкомпонентный дедуп** (D↔K, S↔D↔K) — общий компонентно-агностичный Deduper + экстракторы
     блоков per-source (проектируется в дельте-2/3; дельта-1 покрыла только внутри-E).
3. **Хранение:** шард-файлы на `~/gb10-shared/datasets/axiom-domain-ds-v1/`, в репозитории — только
   симлинки (C-032/C-033). Доли E/K/D/S — решение по карточке после замера объёмов, стартовая гипотеза:
   K+D+S — ядро проза-токенов (домен и процедуры), E — ядро агентности; микс на упаковке (`net/data.py`).
4. **Реализация** — дельтами кодового харнесса: дельта-1 (эпизоды: парсер сессий, скраб, эпизодизация,
   верификация, дедуп), дельта-2 (концепты: фильтр+сериализация через существующие билдеры), дельта-3
   (карточка + микс + аудит). Каждая дельта — со своими тестами и отчётом.

## Alternatives Considered

- **Сессии как претрейн-наполнитель:** 1–2% объёма, формат диалогов, приватность — отклонено.
- **Покупной/внешний агентный датасет:** лицензии, чужой домен, нет механических вердиктов
  нашего контура — отклонено (ось победы требует наш контракт).
- **Только эпизоды:** теряем доменное знание (концепты) — модель не узнаёт наш контур — отклонено.
- **Только концепты (копия laguna-подхода):** SFT-модель без агентных траекторий не тянет ось
  победы — отклонено; пересечение с laguna-датасетами — по карточкам, не по файлам.

## Consequences

### Positive

Positive: верифицированные агентные траектории с бесплатным reward; доменное знание из 289k
концептов; полный контроль происхождения (карточка). Negative: **риск утечки секретов при скрабе**
(митигируется deny-list + паттерны + спот-аудит, ступень 1 — до всего); эпизод-объёма мало для
RL-масштаба (эпизоды — SFT-ядро; RL-задачи — отдельная генерация по среде v1); доли микса —
эмпирика, не теория; парсинг форматов сессий хрупок к обновлениям агентов. Reversibility:
датасет добавляемый; компоненты независимы; удаление компонента не ломает другой.


### Negative (обязательны к учёту)
Негативные последствия перенесены в план рисков соответствующих дельт; ключевые: рост комбинаций флагов приёмки (ADR-018), риск утечки секретов при скрабе и доли микса — эмпирика (ADR-020), A/B-претрейн L1 при честном сравнении пропорций (ADR-019).

## Reversibility

Полностью обратимо до включения в SFT-прогон; после — смена состава = пересборка датасета и
пересмотр SFT (карточка версионирована).


- 28.09.2026 (дельта-2, решения архитектора по находкам): (1) CPT-корпус — новый модуль
  cpt_serialize.py (jsonl-по-документу, фильтр 8 ML-типов, allowlist плагинов); старый
  cpt_corpus_full.txt — legacy-источник (30.8% пересечения типов, txt-склейка), решение о доле
  legacy в миксе — в дельте-3. (2) Дедуп D↔K: MinHash-обрушение на длинных документах — фикс сэмплирования шинглов
  (точных дублей снято 9 873 на 101 051 записи). Премиса «карточка K содержится ВНУТРИ дистиллята D»
  (дельта-2) ОПРОВЕРГНУТА измерением 28.09: исчерпывающий прогон 96 217 K × 5 658 D дал 0 пар
  при пороге 0.55, максимум оконного Jaccard 0.3524 — карточки и дистилляты суть разные формы
  одного знания без текстового вложения (для CPT это аугментация, не дубль). Контейнмент-ступень
  оставлена в коде как непрерывный монитор пересечения (синтетика зелёная, на бою no-op). (3) Карточки K без поля level — включаются (10 466 шт). (4) Allowlist
  плагинов — обрезан до фактически присутствующих в корне; ревизия 1 331 скиллов вне allowlist
  (кандидаты: rl-training, memory-systems, safety-eval, credit-assignment, reasoning, gb10,
  lambert-rl, agents, kat) — решение владельца в дельте-3. Доли K84.2/D15.0/S0.8 approx-токенов
  — заготовка карточки (дельта-3).
## Amendments

- 27.09.2026 (решение владельца): **доменная адаптация — явная CPT-фаза**. K/D/S → CPT-корпус
  (карточка + хеши, билдеры gb10-shared, дельта-2 сериализации) → CPT-луп на GB10/4080 **до SFT**;
  E → SFT/RL. Последовательность фаз: претрейн (аренда, публичное) → **CPT-адаптация (приватное,
  локально)** → SFT/RL (приватное, локально). Сквозной скраб обязателен (та же ступень 1).
  Диаграмма data-map перерисована: фаза CPT выделена узлом, а не слита с SFT/RL.

- 28.09.2026 (дельта-3b, решения архитектора): (1) **красный признак сьюта расширен** — наряду с
  `FAILED`/`ERROR` верхним регистром красными считаются строчные итоги pytest (`1 failed, 5 passed`,
  `2 errors`): до этого такая строка проходила по слову `passed` и давала частичному эпизоду флаг
  `partial-green`, то есть красный прогон уходил в SFT-компонент. Ложное срабатывание стоит одного
  неверифицированного эпизода, пропуск красного — целого класса брака. (2) **Числа прогона вместо
  атрибуции текстом в карточке**: контейнмент несёт числа прогона (из манифеста, а не из текста
  решения) и замер пересечения D↔K с источником; доля `verified-partial` (флаг `partial-green`) —
  числом; проверка повторного дедупа выхода корпуса — числами (`records`, `exact_dropped`,
  `near_dropped`) с названным источником прогона. (3) **`SALT` и hash-семейство исключены из
  `env_assignment` по сегментной семантике; `hex_env` сохраняет имя ключа.** Заслон сегментный, а не
  подстрочный: имя ключа режется по `_`, и ЛЮБОЙ сегмент (после lowercase), равный `sha256`/`sha1`/
  `md5`/`hash`/`salt`/`checksum`, отключает правило целиком — даже когда имя кончается
  credential-словом (`SALT_KEY`, `sha256_HASH`, `IMG_HASH_KEY` остаются нетронутыми: их значения —
  хеши и соли доменных данных, замена портит корпус, а не защищает). Подстрока маркером не является:
  `HASHICORP_VAULT_TOKEN` (сегмент `hashicorp` ≠ `hash`) вычищается — подстрочный заслон дельты-3
  пропускал такое присваивание с секретом. `hex_env` (длинное hex-значение в присваивании) заменяет
  значение, а имя ключа сохраняет: `KEY=<REDACTED>`, а не `<REDACTED>` вместо всей строки — по
  вычищенному тексту видно, что за ключ там был. Границы правил закреплены тестами T-s3/T-s3b.
