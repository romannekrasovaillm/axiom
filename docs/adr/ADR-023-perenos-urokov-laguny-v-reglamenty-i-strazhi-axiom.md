# ADR-023. Перенос уроков лесенки Лагуны в регламенты, спеки стадий и стражи axiom

- Date: 2026-10-05
- Status: Accepted (решение архитектора, маршрут Standard; ревью владельца — вместе с дельтой в PR)
- Основание: `docs/research/LESSONS-LAGUNA-LADDER.ru.md` (коммит `75425a7`) — дистиллят 63 ADR кейса `laguna-compact` (CPT→SFT→RL→eval на Qwen2.5-0.5B/GB10), бэклог §7 из 11 пунктов

## Context

Кейс Лагуны прошёл полный цикл лесенки и заплатил за уроки конкретными потерями: ~14 ч SFT выброшены из-за дефектной структуры набора (LAG-ADR-042/043), 2 ч 14 мин пробы — из-за удаления чекпойнта ретенцией под читающим замером (LAG-ADR-058), отозванные выводы — из-за коллинеарного сравнения (LAG-ADR-026), «PPL ×0.99» — артефакт утечки eval-набора (LAG-ADR-025/044), RL обречён заранее — пустая полоса трудности и незнакомый интерфейс среды у SFT-политики (LAG-ADR-049/061/062).

Пакет уроков уже в репозитории; покрытие в axiom сверено в §0 пакета (одна нагрузка, сон стенда, хеш токенизатора, стоп-файл, смета, изоляция судьи, precondition калибровки — закрыто). Бэклог §7 не начат. Спеки стадий (`SFT-STAGE.delta`, `RL-STAGE.delta`) не содержат ни одного из критериев Лагуны; eval-наборы (`eval_holdout.jsonl`, `eval_ood*`) ещё не собраны — правило чистоты можно закрепить до первого вердикта, а не после.

Оговорки пакета обязательны: числа бюджетов Лагуны — 0.5B/GB10, для axiom (~1B) это **методика пересчёта**, не константы; Лагуна делала CPT поверх готовой базы — переносятся протоколы замера, чистоты и останова, не оси K1/K2; уроки §4 RL не подтверждены полным прогоном.

## Decision

1. **Здоровье ноги — тренд, не сводка** (п. 1.1, 1.2, 1.6): база прибора снимается с чекпойнта-старта до первого шага стадии; вердикт о здоровье — по последовательности точек `metrics.jsonl`; стоп — рост loss на **трёх последовательных** точках замера; тревога — точка выше потолка и следующая не лучше; отдельного порога для самой ранней точки нет; eval-точки не чаще раз в 100 шагов, частота на живом прогоне не меняется; часы монитора включаются в смету явно. Носитель: `docs/PRETRAIN-PIPELINE.ru.md` §6.
2. **Бронь предмета замера** (п. 1.3, LAG-ADR-058): любая проба/калибровка, сопоставимая с окном ретенции (`--keep-last=2`, `tools/pretrain_run.py:164`) или длиннее, — только на hardlink/копии чекпойнта в каталог замера, sha256 снимается с копии, расписка `RECEIPT.json` до старта; отчёт называет состояние «замороженным на момент брони». Носитель: `docs/PRETRAIN-PIPELINE.ru.md` §6.
3. **Чистота eval до вердикта** (п. 2.1): `eval_holdout.jsonl` и `eval_ood*.jsonl` получают `leak_check` (документы подстрокой + 12-граммовые окна) против tokens-v2 (W/C/Q) и всех SFT/RL-наборов **до первого вердикта** по ним; без поля `leak_check` в карточке число справочное, вердикт не выносится. Страж `tools/check_eval_leak.py` (selftest с мутантами) + fitness-правило **C-043**; спин-инвариант **AD-12**.
4. **Единый режим декодирования и различимость** (п. 2.2, 2.3): штатный режим проб — no-repeat-4gram + eos на конце хода; каждый отчёт несёт `protocol.decoding`; смена прибора = пересъёмка базы, старые числа помечаются `legacy-not-checked`; n ≥ 100 на вердикт; один сид — только направление (`std: null, single_seed`); разница < SE — «неразличимо», pass@k не экстраполируется. Носитель: `docs/specs/EVAL-HYGIENE.delta.md` (новая).
5. **SFT до запуска стадии** (п. 3.1–3.7): структурный аудитор набора ДО стадии — три класса дефектов (незакрытый `<think>` считается только среди естественно завершённых ходов; `<tool_call>` внутри `<think>`; ход без ответа) + `unfinished_tool_call`; лечение — механическая нормализация **новым файлом** (исходник не трогается, неизменённые байт-в-байт), не правка на лету; контроль длины think-спанов на этапе сборки + `truncated_share` в evidence, при ≥20 % усечённых вердикт по формату не выносится; критерий стадии `unfinished_tool_call ≤ 5 %` (проба n ≥ 100); дедуп MinHash/20-gram + кап 4–5 эпох на чанк, `duplicates_share` и `effective_passes` — в карточку в любом случае; раздельные метрики «кириллица в think» и «кириллица в ответе»; выбор учителя синтеза — по выборочному чтению смысловых подмен (n ≥ 5), не по tok/s. Носитель: дополнение `docs/specs/SFT-STAGE.delta.md` §8.
6. **Env-интерфейс в SFT-наборе — сильнейший урок связки SFT→RL** (п. 4.4): SFT-набор обязан включать блок в формате `env/` v1 (вызов инструмента → наблюдение → ответ): стартовая доля заземлённых примеров 15 % (пересмотр одним шагом 5/15/30 %), траектории с ≥ 2 действиями ≥ 50 %, синтез по среде с проверкой по состоянию, судья запрещён. Без этого блока RL-замер после SFT измеряет незнакомый интерфейс, а не способность (LAG-ADR-061/062). Носители: SFT-STAGE.delta §8.5 + cross-link в RL-STAGE.delta.
7. **Гейты здоровья RL с мутантами** (п. 4.1–4.3): страж по первым 50 шагам — `pass_rate=0 ∧ reward_mean ≤ 0.05`, или `zero_reward ≥ 90 %` → **стоп**; `no_group_variance` (adv ≠ 0 отсутствуют на окне) → **стоп**; `template_collapse` (повтор 4-граммы ≥ 8) → warn; `clip_frac ≥ 0.2` → warn; энтропия < 0.5 два шага подряд → **стоп**, < 1.0 — внимание; действие — остановка, не смена алгоритма на ходу; страж обязан краснеть на вырожденном ряде и не краснеть на здоровом (мутанты). Энтропийные коридоры Лагуны не копируются — перекалибровка на 1B по первым 50 шагам (п. 4.2). Полоса трудности замеряется базовой моделью до RL и по каждому раунду синтеза; список «мёртвых типов» задач — отдельным файлом; пустая полоса — RL не запускается. Смета RL — от собственного smoke-замера (доля генерации ~71 %, заземление ×1.02–1.34 — как ориентиры пересчёта); `RESYNC_EVERY` и `KL` — явные поля манифеста (п. 4.5). Носитель: дополнение `docs/specs/RL-STAGE.delta.md` §8.
8. **Процесс** (п. 5.3, 5.4): решение, меняющее вход, не принимается без «доказательства исполнения» (носитель — поле манифеста/строка лога/sha — плюс потребитель — читающая сторона; обещание проверки вместо проверки = красное); исторические решения — `legacy-not-checked`, задним числом не дописываются; приёмка дельты — 4 пункта (артефакты существуют, финальный коммит, гейт/тесты, JSON-контракт `complete|partial|blocked`), иначе `blocked`; сверка sha256 CONSTRAINTS ветка↔main до мержа; post-merge гейт на main обязателен, повторный — после разрешения конфликта. Носитель: `docs/CONTRIBUTING.ru.md` §4–5.
9. **Отложенные кандидаты претрейна** (п. 6 пакета: wd=0 на эмбеддингах, стадийность микса, усреднение чекпойнтов decay) этим ADR **не принимаются** — каждое требует собственного замера с контрольной рукой и (для усреднения) расширения ретенции; по мере готовности — отдельные ADR.
10. **Реализация стражей** (`tools/check_eval_leak.py`, `tools/check_sft_dataset.py`, `tools/check_rl_health.py`) — дельтой кодового харнесса; GB10 занят endurance-ногой — GPU-прогоны дельте запрещены, только CPU-тесты; поведенческий прогон leak_check на реальных наборах — при их сборке.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Принять бэклог целиком, включая п. 11 (отложенные кандидаты)** | один цикл, меньше сессий | отложенные кандидаты — гипотезы, требующие контрольных рук и расширенной ретенции; смешение «принять методику» с «сменить гиперболизацию обучения» — коллинеарная ошибка, за которую Лагуна заплатила LAG-ADR-026 |
| **Копировать числа Лагуны как константы** (полосы памяти 35/50/49 ГБ, коридор энтропии 1.0–2.0, бюджет 500 шагов) | быстро, без пересчёта | прямо противоречит п. 4.2 (91/100 шагов выше 2.0 без коллапса) и оговорке о масштабе; пороги от чужого замера дают ложные тревоги и ложную чистоту |
| **Статус-кво: пакет остаётся справочником, стражи и спеки не меняются** | нулевая стоимость, ничего не ломается | уроки без носителя в правилах расходятся (прецедент C-040: llama-server под пилотом при «решённой» одной нагрузке); ошибки Лагуны воспроизводятся поимённо на стадиях, которые ещё впереди |
| **Поведенческий прогон leak_check на реальных наборах в этой же дельте** | закрыл бы AD-12 полностью | eval-наборы ещё не собраны — поведенческая часть нечем проверяться; честный статус — structural-страж + PENDING-EVIDENCE (AD-10) |

## Consequences

### Positive

- Инварианты Лагуны получают механических носителей **до** стадий SFT/RL, а не после первой воспроизведённой аварии.
- Критерии стадий становятся проверяемыми гейтом A4: `unfinished_tool_call ≤ 5 %`, `truncated_share`, `duplicates_share`/`effective_passes`, `leak_check`, `protocol.decoding` — обязательные поля артефактов, а не пожелания.
- Связка SFT→RL получает контракт env-интерфейса заранее — самый дорогой урок кейса (RL измерял незнакомый API, не способность) закрыт конструктивно.
- Вердикты по eval-наборам в axiom не могут повторить «PPL ×0.99» Лагуны: без `leak_check` вердикта нет по построению.

### Negative

- Три новых стража — постоянная поддержка с мутантами на оба края; 12-граммовые окна на легитимных пересечениях корпусов могут дать ложные тревоги — митигация: selftest на синтетике, ручная верификация первых реальных прогонов, пороги правятся новым правилом (анти-ослабление), не правкой на лету.
- Спеки стадий усложняются; до сборки полных наборов зелёность смоук-гейтов не доказывает соответствие полному прогону — расхождение честно остаётся видимым (смоук помечается масштабом).
- Уроки §4 RL переносятся как «контракт среды + разведка стоимости», не как подтверждённый прогоном факт — первый полный RL axiom обязан их перепроверить (зафиксировано в RL-STAGE.delta §8).
- Объём ревью дельты растёт: 2 дополненные спеки, 1 новая спека, AD-12, C-043, 3 инструмента с тестами.

## Reversibility

**reversible.** Все изменения — документы, спеки, новый код инструментов и одно fitness-правило; данные, веса и живые прогоны не затрагиваются (endurance-нога идёт на отдельном чекпойнте, дельта её файлов не касается). Откат — `git revert` дельты; спеки возвращаются к прежнему тексту. Если C-043 окажется неверным (пороги окон), он заменяется новым правилом с обоснованием по CONTRIBUTING §4.2, а не ослабляется.
