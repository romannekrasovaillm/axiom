# ADR-025. RL-стадия в двух методологиях — ветки «Лагуна» и «FrogNano» на одном чекпойнте с механическим сравнением

- Date: 2026-10-05
- Status: Accepted — директива владельца 2026-10-05 («нужен RL на стенде arch-ml в двух методологиях: лесенка Лагуна и FrogNano»); структура сравнения выбрана владельцем из трёх вариантов («две ветки-сравнения»)
- Амендмент: ADR-022 (слитая схема) — элементы распределяются по веткам; substrate, precondition'ы и гигиена остаются общими

## Context

Директива владельца 2026-10-04 (ADR-022) собрала RL-стадию в одну слитую схему: онлайн-синтез сред по FrogNano + reward-цепочка Лагуны поверх базовой схемы ADR-005 с CISPO-флагом-абляцией. Уточнение владельца 2026-10-05: RL нужен **в двух методологиях** — лесенка Лагуны и FrogNano — на стенде arch-ml. Слитая схема не отвечает на вопрос «какая методология работает на нашей 1B на arch-ml»: при неудаче непонятно, какой пакет виноват (урок LAG-026 о коллинеарных сравнениях — в реверсе: слитый пакет и есть коллинеарность).

Из трёх структур (две ветки-сравнения; лестница FrogNano→Лагуна; гибрид одним прогоном) владельцем выбраны **две ветки-сравнения**: один SFT-чекпойнт, равный бюджет, один holdout, механический вердикт.

## Decision

1. **Две именованные ветки** (конфигурационные пакеты раннера, флаг `--arm`):
   - **Arm `laguna`** — алгоритмически-селекционный пакет: алгоритм **CISPO** (потокенный суррогат, клип IS-веса (1, 4), length-weighted leave-one-out baseline); отбор задач из пула по коридору pass-rate [10 %, 90 %] калибровочным прогоном текущего чекпойнта, сэмплинг ∝ 1 − pass_rate, вырожденные {0, 1} выбрасываются; reward — формула среды v1 **с префиксом Лагуны** (ошибка парсинга −0,1; anti-give-up −0,1 при < n_min вызовов; таймаут 0,0).
   - **Arm `frognano`** — среда-синтезный пакет: алгоритм — **базовая схема ADR-005** (групповое преимущество + токен-уровневый log-ratio клип-маска, MuonClip, плотный soft-score); задачи — **онлайн-синтез раундами** ~300 задач × до 5 раундов генератором-мутатором `env/corruption.py` (seed → байт-идентичный кейс, AD-4), приёмка задачи — двусторонняя исполняемая валидация (гейты падают на порченом снапшоте ∧ restore-патч проходит ∧ пустое решение падает), насыщение чекпойнта открывает следующий раунд; reward — формула среды v1 **без** префикса Лагуны; вердикт — по финальному состоянию среды.
2. **Общее для обеих веток** (не дифференциаторы, гигиена контура): substrate `env/` на arch-ml (train/prod TITO, AD-3); маскирование в loss промпта и выводов инструментов; LLM-судья вне награды (AD-2/C-039); QAT наследуется из журнала SFT; batch=1, контекст роллаутов 8–32k; пиннинг сидов и снапшотов (AD-4/AD-11); health-гейты §8.1 с мутантами (C-045) и перекалибровкой порогов на 1B; анти-reward-hacking контур (скрытый ротируемый holdout, раннер без сети, sha256 constraints до вердикта, post-hoc review вне награды); смета до запуска (AD-8/C-041).
3. **Справедливость сравнения**: обе ветки стартуют с **одного** SFT-чекпойнта (симлинк, C-032), один скрытый holdout, **равный бюджет RL-шагов** (стенография в сметах обеих веток; wall-clock фиксируется в карточках и может отличаться — синтез/валидация ветки `frognano` в равенство бюджета не входят), одна и та же машина оценивания (AD-3). Верdict — **методологического уровня**: внутри пакета факторы коллинеарны (LAG-026), атрибуция по отдельным факторам этой веткой эксперимента не выдаётся.
4. **Вердикт**: МакНемар на фиксированном holdout, 4 прогона mean pass@1 (ADR-022 п. 8); разница < 8 попаданий на n=100 ростом не считается → «методологии неразличимы», обе остаются конфигурационными ветками, выбор контекста применения — владельцу с числами. При различимой разнице победитель становится основной схемой RL-стадии; элементы проигравшей ветки сохраняются флагами-абляциями (механика ADR-022 п. 3).
5. **Precondition'ы запуска любой ветки** (без изменений, поверх SFT-стадии): env-блок в SFT-наборе (SFT-STAGE §8.5); калибровка K3 pass-rate [10 %, 90 %] (ENVIRONMENT-V1 §10); непустая полоса трудности по раунду синтеза + файл «мёртвых типов» (RL-STAGE §8.2); смета от smoke-замера (§8.4); интерфейс замера = интерфейс обучения (§8.3).
6. **Порядок исполнения**: (1) дельта исполнителя — arm-конфиги в раннере (`--arm laguna|frognano`, декларативные пакеты флагов) после SFT-стадии; (2) smoke обеих веток (провод, масштаб смоука в журнале); (3) precondition'ы; (4) полные прогоны **последовательно** (одна GPU, AD-7); (5) вердикт. RL-гейты §8.1 действуют на обе ветки; стоп по health — остановка ветки, не «дожим бюджета».
7. Порядок старта веток — по готовности (обе требуют калибровку; ветка `frognano` дополнительно требует первый раунд синтеза); очерёдность не является частью вердикта (разные чекпойнты-старты запрещены — оба прогона с одного чекпойнта).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Лестница FrogNano → Лагуна** (две последовательные RL-стадии) | каждая методология на своём участке кривой; FrogNano силён в холодном старте инструментальной грамотности | атрибуция между стадиями смешана — вердикт «какая методология лучше» не выдаётся; те же ~2× затрат GPU; отклонено владельцем |
| **Гибрид одним прогоном** (текущий ADR-022 как есть) | дешевле всех (1× GPU) | методологии неотделимы — не отвечает директиве «в двух методологиях»; при неудаче виноватый пакет неопределим; отклонено владельцем |
| **Параллельные ветки на двух GPU** | быстрее вдвое | на контуре одна машина (AD-7); аренда второй — деньги и новый vendor без нужды; отклонено |

## Consequences

### Positive

- Владелец получает механический ответ «какая методология RL работает на нашей 1B на arch-ml» — с одним прибором, одним holdout и равным бюджетом (AD-3).
- Проигравшая методология не выбрасывается: остаётся флагами-абляциями для факторных экспериментов позже (по одной оси за прогон — дисциплина LAG-026).
- Общая гигиена (health-гейты, анти-hacking, маскирование) не становится предметом сравнения — обе ветки в равных условиях безопасности.

### Negative

- **2× RL-времени GPU** против гибрида; календарь пост-трейна удлиняется на полный прогон второй ветки — принимается владельцем осознанно (директива).
- Сравнение методологическое: при победе одной ветки нельзя утверждать, какой её внутренний фактор решил (коллинеарность пакета) — факторные вопросы только отдельными абляциями.
- Синтез-раунды ветки `frognano` — дополнительная wall-clock стоимость вне равного бюджета шагов (фиксируется в карточках, на вердикт не влияет).

## Reversibility

**reversible.** Ветки — декларативные конфигурации раннера; вердикт меняет только значение по умолчанию `--arm`. Откат — git revert дельты; данные, веса и precondition'ы не затрагиваются. Ослабление/замена вердиктной процедуры — только новым решением (анти-ослабление).
