# ADR-025. Две сессии в одном репозитории: зоны архитектуры и операций

- Date: 2026-10-05
- Status: Accepted (решение владельца 05.10 ~07:30 МСК — выбор «разделить зоны» из трёх: остановка второй / мой стоп / разделение)
- Основание: повтор инцидента параллельности 05.10 — параллельная сессия-оператор (нормализация v12 `f46af15`, RESULTS §9 `cd27521`, отзыв C-040 `049f5f7`) при архитекторской линии (`1c50aac`, `5161e43`); коммиты разошлись на 79 секунд (`1c50aac` 06:51:55 ↔ `f46af15` 06:53:14)

## Context

Утренний инцидент (RESULTS §2) породил AD-13 «эксклюзивный захват чекаута на время harness-пакета». К полудню выяснилось, что параллельно работает **вторая постоянная AI-сессия** с прямым доступом владельца (упоминает его разрешения в коммитах). Обе сессии качественны и координируются через репозиторий (оператор сам ренумеровал коллизию §6→§9 и пометил supersede), но без явных границ пишут в одни файлы в одном окне — гонка повторилась. Владелец выбрал разделение зон вместо остановки одной из линий.

## Decision

Постоянное разделение зон владения файлами:

- **Зона «архитектура»** (сессия-архитектор): `docs/adr/**`, `docs/specs/**`, `ARCHITECTURE-SPINE.md`, `model/**`, `CONSTRAINTS.yaml`, `docs/CONTRIBUTING.ru.md`, `docs/PRETRAIN-PIPELINE.ru.md`, `docs/RUNBOOK-GB10.ru.md`, `docs/OPEN-QUESTIONS.md`, архитектурные разделы `README.md`.
- **Зона «операции»** (сессия-оператор): `docs/RESULTS-*`, `docs/research/**`, `docs/datasets/**`, `data/**`, `env/**`, `tools/**`, `net/**`, `evidence/**`, `AGENTS.md`, `.arch-handoff/`, `.locks/`, стенд `~/axiom-run/**`, `~/gb10-shared/datasets/**`.
- Кодовые дельты (`tools/`, `net/`) выполняются кодовым харнессом **оператора** (у него стенд и данные); архитекторские дельты спек/правил/спайна — архитектором. Карточки датасетов — зона операций (носитель данных).
- **Протокол координации:**
  1. перед серией правок — `git pull` (стенд — git-bundle'ом); перед push — `git fetch` и rebase при расхождении;
  2. коммит и push сразу по завершении дельты — не копить локальные линии;
  3. чужие файлы не трогаются даже «для исправления»; замеченное — сводкой в свой канал (RESULTS для оператора, OPEN-QUESTIONS для архитектора);
  4. конфликт содержаний одного файла — не «кто последний», а стоп и сводка двух версий в OPEN-QUESTIONS (решение владельца);
  5. AD-13 (эксклюзивный захват на время harness-пакета) действует в обеих зонах.
- Аварийная правка в чужой зоне — только через сводку владельцу зоны; «тихое» исправление = breach (фиксируется в аудите пакета, как `d075e34`).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Остановка второй сессии** | один писатель, ноль гонок | потеря её контекста: нормализация, стенд-доступ, свежие разрешения владельца |
| **Worktree на каждую сессию** | полная изоляция | слияние двух живых линий документации дороже дисциплины путей; сессии и так координируются через репо |
| **Статус-кво без зон** | ноль затрат | гонки `1c50aac`↔`f46af15` повторяются; дубль-носители чисел (§5.5 уроков) |

## Consequences

### Positive

- Обе линии сохраняют контекст; граница проверяема механически по списку путей.
- У каждого числа один носитель в одной зоне; diff приёмки читается без примеси.

### Negative

- Срочная правка в чужой зоне ждёт владельца зоны — митигируется сводкой в свой канал.
- Два потока коммитов в main — дисциплина «коммит+push сразу» становится обязательной.

## Reversibility

**Two-way**: процессное правило, отменяется/переразмечается новым ADR владельца; данные и код не меняются.
