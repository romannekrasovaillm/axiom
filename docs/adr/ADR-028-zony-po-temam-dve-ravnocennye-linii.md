# ADR-028. Зоны по темам вместо ролей: две равноценные линии в одном репозитории

- Date: 2026-10-05
- Status: Accepted — решение владельца 05.10 ~07:55 МСК (выбор «зоны по темам» из трёх: принять их разметку ролей / инвертировать / темы)
- Амендмент: ADR-025 «зоны сессий» — разделение по путям сохраняется, разметка **ролей** (архитектор ↔ оператор) заменена **тематическими** зонами; протокол координации ADR-025 сохраняется целиком

## Context

ADR-025 закрепил разделение зон по ролям: вторая линия — «архитектура», эта линия — «операции». Фактическая работа 05.10 распределена иначе: обе линии писали и ADR/спеки/спайн (023/027/AD-12/C-043–045/EVAL-HYGIENE против 022-ревью/024/025/SFT-§8), и операции (стенд-верификация/нормализация против модельных сущностей/trace-фиксов). Ролевая разметка не совпадает с гравитацией работы и переводит закреплённые за линией-1 решения (ADR-027, пакет уроков) в чужую зону. Владелец выбрал тематические зоны: обе линии равноценны, каждая владеет своей темой целиком — оба типа артефактов (ADR и операции) внутри своей темы.

## Decision

**Линия-1 (эта сессия) — тема «претрейн, данные, стенд, приборы, внедрение уроков»:**

- файлы: `docs/PRETRAIN-PIPELINE.ru.md`, `docs/RUNBOOK-GB10.ru.md`, `docs/RENTAL-VAST.ru.md`, `docs/RESULTS-*.ru.md`, `docs/research/**`, `docs/datasets/**`, `data/**`, `tools/check_*`, `tools/prep_pretrain/**`, `tools/bpe_*`, `evidence/**`, `AGENTS.md`, `.arch-handoff/**`, `~/gb10-shared/.locks/**`, стенд `~/axiom-run/**`, новые файлы `~/gb10-shared/datasets/**`;
- ADR-темы: претрейн-кандидаты, датасеты и eval-гигиена, внедрение пакета уроков Лагуны (LESSONS-бэклог); закреплённые решения ADR-023, ADR-027 и их наследники.

**Линия-2 (вторая сессия) — тема «методология стадий, среда, модельный канон»:**

- файлы: `docs/specs/**` (SFT-STAGE, RL-STAGE, ENVIRONMENT-V1, MODEL-L3-SKELETON, A4-RUN), `ARCHITECTURE-SPINE.md`, `model/**`, `CONSTRAINTS.yaml`, `docs/CONTRIBUTING.ru.md`, `docs/OPEN-QUESTIONS.md`, `env/**`, `net/**`, стадийные раннеры `tools/run_*`, `docs/RENTAL-VAST.ru.md` при аренде полных прогонов;
- ADR-темы: рецепты стадий (линия ADR-022: CISPO/FrogNano/Laguna-детали), среды и калибровка, спин-инварианты; закреплённые решения ADR-022, ADR-024, ADR-025.

**Нейтральная зона:** `docs/adr/**` — обе линии пишут ADR своей темы; номера сквозные, перед созданием — сверка каталога (`ls docs/adr`), номера не переиспользуются и не резервируются молча.

**Общее (без изменений от ADR-025):** координация — `git pull` перед серией, коммит+push сразу по завершении дельты; AD-13 (эксклюзивный захват чекаута на время harness-пакета) действует в обеих линиях; чужие файлы не трогаются — замеченное сводкой в канал другой линии (линия-1 → RESULTS, линия-2 → OPEN-QUESTIONS), конфликт содержаний — OPEN-QUESTIONS владельцу. **Правка файлов смешанной истории:** владельцы файлов с этого момента — `SFT-STAGE.delta` и `RL-STAGE.delta` → линия-2 (дополнения линии-1 — сводкой); `PRETRAIN-PIPELINE`, `RUNBOOK-GB10`, `EVAL-HYGIENE.delta` → линия-1.

**Владелец может перекроить темы новым ADR в любой момент; «тихие» правки чужой зоны = breach (аудит пакета).**

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Роли как в ADR-025** (архитектор ↔ оператор) | одна линия аккумулирует весь архитектурный канон | не совпадает с фактической гравитацией: решения линии-1 (ADR-027, пакет уроков) уходят в чужую зону; вторая линия теряет право фиксировать свои же методологические решения; отклонено владельцем |
| **Инверсия ролей** | зеркально | та же проблема для линии-2; отклонено владельцем |
| **Статус-кво без зон** | ноль затрат | гонки `1c50aac`↔`f46af15` и взаимные ренумерации повторяются; отклонено владельцем (ADR-025) |

## Consequences

### Positive

- Каждая линия владеет своей темой целиком — и решениями, и операционными следами: у числа один носитель в одной зоне (§5.5 уроков).
- Граница механически проверяема по списку путей; ADR-номера сквозные и без коллизий при сверке каталога.
- Обе линии сохраняют полный контекст своих тем — ничего не маршрутируется через третью сторону.

### Negative

- Темы не ортогональны до конца: SFT/RL-спеки (линия-2) ссылаются на приборы и карточки (линия-1) — кросс-зонные изменения только через сводку, что добавает латентность.
- Два потока коммитов в main: дисциплина «pull → дельта → commit+push сразу» обязательна, иначе конфликты слияния.

## Reversibility

**two-way**: процессное правило; перекройка тем — новым ADR любого владельца темы (по согласованию владельца контура); данные и код не затрагиваются.
