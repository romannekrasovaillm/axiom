# ADR-029. QAT MXFP4: собственный fake-quant STE (`net/quant.py`); AQT не принимается

- Date: 2026-10-05
- Status: Accepted (архитектор; маршрут Fast — реализация существует и отработала в смоук-прогонах, ADR фиксирует решение до полного SFT)
- Закрывает: OPEN-QUESTIONS «Требует проверки фактов» — «QAT MXFP4: своя fake-quant либо AQT» ([ТРЕБУЕТ ПРОВЕРКИ] из DECISION-PACKAGE)

## Context

ADR-005 п. 7: QAT включается со стадии SFT и продолжается в RL; ADR-009 D3: веса MXFP4 (E2M1 + один E4M3-скейл на 16 каналов, без второго глобального скейла, деkвантизация перед attention), латентный KV — FP8 на SWA-ветке. Реализация — `net/quant.py`: собственный pure-JAX fake-quant (straight-through estimator, блок 32 для весов; латентный KV — блок 16 E2M1/E4M3). Отработано: смоук SFT 200 шагов с `qat_weights: on` на ПК и GB10 (`evidence/a4-run-wire/sft*/stage-journal.json`, status executed). Открытым оставался выбор: продолжать собственную реализацию или перейти на библиотеку AQT.

## Decision

1. **QAT-тренировка — собственный fake-quant STE** (`net/quant.py`): веса MXFP4 (блок 32, power-of-two scale, 3-битная мантисса), латентный KV по ADR-009 D3, FP8 E4M3 для SWA KV; включение флагом `qat_enabled`/`qat_weights` с SFT; на претрейне выключен.
2. **AQT не принимается** для тренировочного контура. Inference-путь (реальные квантованные matmul'ы ради скорости инференса) — отдельное решение стадии инференса (ADR-003/004), не тренировки: QAT-веса делают последующий PTQ тривиальным.
3. Семантика квантования — ровно ADR-009 D3; отклонения от OCP-спеки фиксируются в `net/config.json deviations` как прежде.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---|---|---|
| **AQT (google/aqt) для QAT** | зрелая библиотека, квантованные dot-операции | семантика AQT — int8/fp8-дот-квантизация TPU-ориентированной линии, нет OCP MXFP4 microscaling с E4M3-скейлом/16ch (ADR-009 D3) — фиделити к K3 терялась бы или требовала форка; новый вендор-триггер значимости; поддержка sm_121/GB10 не подтверждена; для fake-quant-тренировки ускорения не даёт (квантование симуляция, не реальные доты) |
| **Постквантование без QAT (PTQ сразу)** | ноль изменений в цикле обучения | ADR-005 п. 7 принят: QAT со стадии SFT — модель встречает квантованный режим в обучении; PTQ--only проигрывает на 1B-масштабе и противоречит принятому решению |
| **Статус-кво без ADR** | ноль затрат | решение «де факто реализовано, де юре не принято» — нарушение дисциплины (ADR до полного SFT); карточка решения без носителя (урок §5.4) |

## Consequences

### Positive

- Полный SFT стартует с закрытым решением; QAT-ветка уже покрыта тестами и смоук-прогонами на обеих машинах.
- Детерминизм сохранён: fake-quant — чистый JAX без внешних состояний (гейты A5/ADR-013 применимы без оговорок).

### Negative

- Собственная реализация = свой код сопровождения (митигировано: ~130 строк, покрыто тестами round-trip/quant_error; FIDELITY-секция документирует семантику).
- Реального ускорения инференса fake-quant не даёт (симуляция) — это осознанно: ускорение — вопрос стадии инференса.

## Reversibility

**Two-way**: переход на другой QAT-механизм — новый ADR; чекпойнты несут веса (не квант), совместимы в обе стороны; PTQ-путь из QAT-весов доступен всегда.
