# ADR-030. Канал публикации артефактов Axiom — Hugging Face (профиль Rob1234567), коллекция + приватные репо

- Date: 2026-10-05
- Status: Accepted (решение владельца 05.10: канал HF, аккаунт Rob1234567, ssh-канал/токены — архитектору)
- Закрывает: запрос владельца «создать на HF коллекцию и лить промежуточные важные чекпойнты и доки про эксперимент Axiom»

## Context

Владельцу нужен внешний канал хранения/публикации артефактов эксперимента Axiom: промежуточные важные чекпойнты (pilot step-300 — первый, база полного SFT) и документация о ходе эксперимента. Профиль-цель: `Rob1234567` (отдельный user; локальный токен HF принадлежит `Roman12322` — прав на целевой профиль нет; решение владельца: fine-grained write-токен Rob1234567, передаётся файлом `~/gb10-shared/.hf-rob-token`, chmod 600, вне git). Корпус претрейна пилота — микс L3 (ADR-021), но фактическая выборка ран-конфига `[ТРЕБУЕТ ПРОВЕРКИ]` — доменная приватная часть исключить нельзя до аудита. В контуре действует C-011 (секреты), C-021 (приватный корпус не покидает контур), C-032 (канон весов на сетевом диске).

## Decision

1. **Репозитории**: под `Rob1234567`, **default private**; перевод в public — отдельное решение владельца после аудита корпуса пилота (запомненный приватный текст). Соглашение имён: `axiom-<стадия>-<объект>-<шаг>` (первый: `axiom-pilot-l3full-step300`).
2. **Коллекция**: `Rob1234567/axiom` — агрегирует репо-артефакты по мере стадий.
3. **Состав публикации**: (а) важные чекпойнты — по вердикту стадий (первый: pilot step-300: params+opt_state+meta, orbax-формат как есть, без конверсии в safetensors до потребности инференса); (б) карточка модели (что за модель, стек, цель, шаг, метрики — БЕЗ внутренних путей стенда, токенов, сетевых дисков); (в) доки — карточки датасетов и дайджесты стадий; внутренние ADR/спеки контура не публикуются (гигиена C-011, C-021).
4. **Транспорт**: `huggingface_hub` 1.27 (CLI `hf`), токен из файла; чекпойнт копируется со стенда на ПК (`ssh gb10-fast`) и льётся с ПК (HF доступен напрямую; локальный socks-прокси мёртв — env -u *PROXY).
5. **Гигиена**: токен вне git (файл 600 на сетевом диске, вне chекаута); перед upload — санитизация: grep артефактов на секреты/внутренние пути; manifest загрузки (файлы+sha256) пишется в evidence/ контура.

## Alternatives

1. **Публиковать от `Roman12322`** — отклонено: решение владельца — целевой профиль `Rob1234567` (два аккаунта — факт; канал должен быть закреплён за профилем эксперимента).
2. **Собственный git-lfs/NAS-канал** — отклонено: HF стандарт для весов (версионирование, дедупликация, карточки), владельцу нужна внешняя доступность.
3. **Публиковать только после полного SFT** — отклонено: владелец явно запросил промежуточные важные чекпойнты (страховка прогресса, история стадий).

## Consequences

Положительные: внешняя страховка артефактов; история стадий; стандартный формат для будущей публикации. Отрицательные: (а) до аудита корпуса — private-only, шеринга нет; (б) полоса: 6.9 ГБ/чекпойнт с ПК (загрузка десятки минут); (в) двойной учёт: canon остаётся на `~/gb10-shared` (C-032) — HF-копия НЕ канон, ретенция HF-репо не управляет жизненным циклом чекпойнта; (г) токен — новый секрет-носитель (утечка файла = доступ к репо) — вне git, 600, отзыв через HF-настройки.

## Reversibility

Reversible: репо/коллекция удаляются в HF за минуты; токен отзывается; канон артефактов остаётся в контуре (HF — копия). Зависимости контура от HF-канала нет (детерминизм AD-4 не опирается на HF).

## Локальные правила контура

- Публикация — только по вердикту стадии (что «важно» — решает приёмка стадии, не ручной выбор).
- Каждый upload — запись в `evidence/hf-publications.md` (репо, sha256 файлов, дата, кто).
- Видимость (private→public) — только решение владельца.
