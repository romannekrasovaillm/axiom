# ADR-031. KDA на WY/UT-алгоритме, ток/с — главный KPI претрейна, батч ~256K токенов/шаг

- Date: 2026-10-05
- Status: Accepted — директива владельца 05.10 («перепиши чанковый KDA на WY/UT-алгоритм или возьми готовые кернелы; ток/с — главный KPI; батч до сотен тысяч токенов на шаг»)
- Маршрут: Standard (new_component, significant_nfr). Зона: претрейн (линия-1); файлы `net/kda.py`, `net/train_loop.py` — владение линии-2 по ADR-028, дельта исполняется харнессом линии-1 с уведомлением линии-2 (директива владельца — прямое поручение)

## Context

Текущая скорость претрейна на l3-full@8192 B=1 — **78–86 ток/с** стабильной фазы (троттлинг до 30–54): нога в 300 шагов = 8–12 ч, 0,5B токенов — месяцы. MFU оценочно <1 %: 6·N·tok/s ≈ 0,5 TFLOP/s против сотен TFLOP/s пика GB10 — GPU почти простаивает (аномальный power.draw 25,6 Вт, RESULTS §6). Причина структурная: текущий «чанковый» KDA (`net/kda.py`, дельта `1e621c0`) тянет `lax.associative_scan` по моногруппе переходов — материализует per-token матрицы переходов (источник и 41,5 ГиБ/слой, и памяти-стены D-8), вычисление мемори-BOUND, а не matmul-bound; батч B=1 не амортизирует хост-оверхед.

Директива владельца задаёт программу: (1) KDA на WY/UT-алгоритме (Kimi Linear, arXiv 2510.26692 §3.1 — Hardware-Efficient Chunkwise Algorithm: WY representation + UT transform) или готовые кернелы; (2) ток/с — главный KPI; (3) батч до сотен тысяч токенов на шаг.

## Decision

1. **KDA → WY/UT chunkwise-форма.** Заменить `associative_scan`-по-моногруппе на алгоритм Kimi Linear §3.1: перенос состояния `S (d_k×d_v)` между чанками через matmul-обновления; внутри чанка коррекция через WY-представление (`P = X − WY`, C×C-операции), UT-transform для триангуляции; память O(C·d) вместо O(T·d²). Эталонные исходники: FLA `chunk_kda` (fla-org/flash-linear-attention — KDA поддержан нативно, «fast WY representation») и текст arXiv 2510.26692.
2. **Лестница реализации (в порядке попыток, каждая с паритет-тестом):**
   - **Шаг 1 — pure-JAX WY/UT**: чистая JAX-реализация (matmuls + `lax.scan` по чанкам), без кастомных кернелов — ADR-017 чист, паритет с текущей реализацией `allclose` на малых T, детерминизм под `--xla_gpu_deterministic_ops`.
   - **Шаг 2 — Pallas/Triton-фьюз** (если профилировщик покажет потолок pure-JAX): кернел в JAX Pallas (Triton backend, sm_121) по мотивам FLA `chunk_kda` — тот же ADR-017.
   - **Шаг 3 — FlashKDA (MoonshotAI, CUTLASS, до 3,27× на Blackwell) через FFI** — только если KPI (п. 4) не достигнут шагами 1–2; требует амендмента ADR-017 (CUDA-кернелы на тренировочном пути) — отдельное решение владельца.
   - Готовые кернелы FLA (PyTorch/Triton) напрямую не встраиваются: наш луп JAX; используется их математика, не код.
3. **Паритет и переключение.** Новая реализация — за конфиг-флагом `kda_impl: chunked|wyut` (default `chunked` до приёмки); паритет `allclose` old-vs-new на малых T (свойство XLA, прецедент дельты chunked-CE); после паритета — флип дефолта, старый путь остаётся регрессионным эталоном. Числовые базасы A4/A5 перезаписываются один раз с фиксацией перехода в манифесте (ADR-013-профиль).
4. **Ток/с — главный KPI претрейна.** Измерение: медиана ток/с по стабильному окну ≥ 20 шагов (§3.1 PRETRAIN-PIPELINE, тот же носитель `metrics.jsonl`). Базис: 80–86 ток/с (l3-full@8192 B=1, до троттлинга). Целевая лестница: **≥800 ток/с** (10×, порог приёмки дельты WY/UT+батча) → далее профилировка до ≥10 % MFU (≈8 000+ ток/с для 1B на GB10 — ориентир, не обещание). KPI-гейт в CONSTRAINTS возвращается вместе с достигнутым числом (канон: правило приходит с инструментом).
5. **Батч ~256K токенов на шаг оптимизатора.** Семантика: микробатч B×8192 с градиентным накоплением до 256K токенов на шаг (накопление решает память-стену без потери семантики большого батча; WY/UT снижает и саму стену). Конфиг: `--micro-batch` + `--accum-tokens 262144`. Пиковая скорость обучения LR пересматривается по правилу линейного скейлинга от микробатча — контрольная рука: короткая нога на новом батче против старой конфигурации (та же методика контрольных рук LAG-022).
6. **Порядок внедрения:** дельта харнесса (реализация + паритет + бенчмарк на фиксированной конфигурации CPU/GPU) → бенчмарк tok/s на GB10-окне между ногами → при ≥800 ток/с: флип дефолта + нога-3 на новой конфигурации → KPI-гейт в CONSTRAINTS. Ноги В2-две продолжаются на текущей реализации — программа не срывает календарь.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---|---|---|
| **FlashKDA CUDA/CUTLASS сразу через FFI** | максимальная скорость (до 3,27× на Blackwell), готовые кернелы MoonshotAI | вне буквы ADR-017 (CUDA на тренировочном пути) — нужен амендмент; FFI-обвязка + сборка CUTLASS на sm_121; отложено шагом 3 лестницы |
| **FLA Triton-кернелы напрямую через jax-triton** | готовые отлаженные кернелы | FLA — PyTorch-экосистема: тензоры/аллокации/автоград не переносятся 1:1; дрейф сигнатур версий; дешевле написать математику в JAX по их тексту |
| **Оставить associative_scan, поднять только батч** | нулевая стоимость кода | память-стена (41,5 ГиБ/слой масштабируется с батчем) и мемори-BOUND алгоритм остаются — ток/с не вырастет в разы; против директивы |

## Consequences

### Positive

- Путь к 10×+ ток/с: ноги претрейна сокращаются с дней к часам, 0,5B токенов становится достижимым на GB10; KPI ток/с делает прогресс измеримым и главным критерием инженерных дельт.
- WY/UT снимает и память-стену D-8 (O(C·d) вместо O(T·d²)) — открывает большие батчи без экстремального чекпойнтинга.
- Паритет-методика и флаг — управляемый переход без срыва идущих ног.

### Negative

- **Числовой сброс**: новая ассоциация вычислений меняет битовые результаты — базасы A4/A5 и паритеты перезаписываются один раз с явной фиксацией перехода (риск скрытых регрессий — митигация: allclose-паритет старой-vs-новой и регрессионный старый путь в коде).
- Расписание LR при батче 256K требует контрольной руки — риск потерять короткий отрезок обучения на неудачный LR.
- Три ступени лестницы = инженерное время; если pure-JAX не даст KPI, шаги 2–3 добавят кернел-сложность и (на шаге 3) амендмент ADR-017.

## Reversibility

**reversible**: флаг `kda_impl` возвращает старый путь; батч/накопление — конфигурация; числовой сброс базасов — однократный, документируется. Откат дельты — git revert; ноги на старом пути не затрагиваются.
