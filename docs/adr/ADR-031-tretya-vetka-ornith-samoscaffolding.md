# ADR-031. Третья ветка RL `ornith` — самоскаффолдинг (DeepReinforce/Ornith-1.5) в сравнении ADR-027

- Date: 2026-10-05
- Status: Accepted — директива владельца 05.10 («новый скилл Ornith самоскаффолдинг — использовать активно в проекте»); структура выбрана владельцем («третья ветка сравнения»)
- Амендмент: ADR-027 — сравнение методологий расширяется до трёх веток: `laguna | frognano | ornith`
- Источник методики: скилл `deepreinforce-harness-self-scaffolding` (плагин ornith; DeepReinforce AI / Ornith-1.5, 2026-08-18); смежный `ornith15-self-improvement-loop`

## Context

Обе ветки ADR-027 — solver-only: модель учится решать внешние задачи под ручным харнессом. По терминологии Ornith это уровень 1.0; замкнутый цикл самоулучшения требует, чтобы reward доходил до **генератора задач** и **генератора харнесса** — иначе цикл вырождается в обычный RL на фиксированных задачах. Владелец выбрал трёхветочное сравнение: третья ветка `ornith` — самоскаффолдинг, где модель сама пропонирует задачи, строит task-specific скаффолды и роллауты, а три reward-потока оптимизируются совместно.

Сравнение остаётся методологического уровня (ADR-027): пакет `ornith` коллинеарен внутри, атрибуция факторов — отдельными абляциями. Цена осознана владельцем: 3× RL-времени GPU и самая тяжёлая имплементация из трёх веток.

## Decision

1. **Arm `ornith` — одна политика, три роли.** Та же модель играет proposer / harness-generator / solver с разными промптами; три reward-потока (задачи, харнесс, роллауты) идут в один GRPO-цикл **раздельными стримами** — не смешивать в один скаляр (contract п. 7 скилла). Базовая схема обновления — ADR-005; групповое преимущество считается по каждой роли отдельно.
2. **Три reward по формулам скилла:**
   - `R_task = V × D × N`: `V` — validity, **жёсткий гейт** (наша двусторонняя исполняемая валидация: гейты падают на порче ∧ restore-патч проходит ∧ пустое решение падает); `V = 0 ⇒ R_task = 0`; `D = exp(−(p−p*)²/2σ²)` — frontier-сложность, `p` — эмпирический pass-rate на N роллаутах **текущей** политики, `p* = 0.2` (перекалибровка σ и p* от smoke на 1B — чужие константы не копируются, ADR-027 §8.1-принцип); `N = 1 − max sim(q, q_j)` против буфера принятых задач `B` — вторична к V и D; буфер пополняется только валидными.
   - `R_harness = C × F × H`: `C` — task alignment (гейты харнесса ссылаются на объявленные задачей правила); `F` — reward fidelity (заведомо верное решение проходит, заведомо неверное падает — механика нашей двусторонней валидации); `H` — hack resistance (изоляция оценки: без сети, без git-истории, sha256 constraints, скрытый holdout — наш анти-hacking контур ADR-022 п. 6).
   - `R_rollout(τ_i) = h(q, τ_i)` — роллаут скорится сгенерированным харнессом; для верифицируемых задач — бинарный вердикт среды v1.
3. **Детерминизм (AD-4) при стохастической учебной программе**: инференс proposer/harness-generator — greedy/низкая температура с пиннутым сидом на запиннутом чекпойнте; каждая сгенерированная задача/харнесс логируется с hash модели и сидом. Воспроизводимость раунда = воспроизводимость инференса + пин мутатора.
4. **Fail-closed старт ветки**: V-гейт на слабой базе может обнулить весь поток (модель не умеет писать валидные спеки). Правило: если K = 3 раунда подряд не дают ни одной валидной задачи — ветка честно останавливается, в сравнении фиксируется «методология не жизнеспособна на данной базе» — это результат сравнения, а не сбой. Разогрев proposer не подмешивает человеческие задачи в его reward (иначе цикл не замкнут — грабли скилла).
5. **Порядок и бюджет**: ветки исполняются последовательно на одной GPU (AD-7) в порядке готовности: `laguna` (пул готов) → `frognano` (машина раундов) → `ornith` (самая тяжёлая зависимость: три потока роллаутов на шаг — стоимость ~3× frognano, принята владельцем). Равный бюджет RL-шагов на ветку (AD-3); wall-clock — в карточках.
6. **Вердикт**: попарные МакНемары на одном holdout с поправкой Бонферрони (3 сравнения, α/3) — по уроку §2.3 Лагуны; неразличимость пар — честная фиксация. Победитель — основная схема; элементы остальных — флаги-абляции.

## Грабли скилла → наши стражи (маппинг активного применения)

| Грабель Ornith | Носитель в axiom |
|---|---|
| «Только солвер — цикл не замкнут» | три reward-стрима в один GRPO, атрибуция по ролям в журнале ветки |
| «Ручной харнесс — уровень 1.0» | harness-generator = роль модели; харнесс генерируется под задачу |
| «Мягкая валидность» | V — жёсткий гейт: двусторонняя исполняемая валидация (env/verifier.py) |
| «p* фиксирован навсегда» | p пересчитывается по текущим роллаутам каждой ноги ветки |
| «Новизна важнее валидности» | порядок множителей V → D → N; буфер пополняется только валидными |
| «Харнесс без H» | H-множитель = наш анти-hacking контур (C-039, скрытый holdout, изоляция) |
| «Оценка без изоляции» | раннер без сети, без git-истории, sha256 constraints до вердикта |
| «Смешивание трёх reward в скаляр» | три стрима, раздельная атрибуция в stage-journal |
| «Сравнение разноразмерных» | одна база, один размер, один бюджет (AD-3) |

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Двухфазный frognano** (Ornith как фаза 2 ветки после сатурации) | дешевле; наследует сатурацию FrogNano как триггер | сравнение методологий смешивается внутри одной ветки — вердикт «laguna vs frognano+ornith» не разделяет вклад; отклонено владельцем |
| **Эволюционный путь после вердикта** (Proposed-заготовка) | нулевая стоимость сейчас | Ornith вне активного контура до вердикта — против директивы «использовать активно»; отклонено владельцем |

## Consequences

### Positive

- Сравнение отвечает на вопрос владельца в полной постановке: какая из трёх методологий (внешний пул / адаптивный синтез / самоскаффолдинг) работает на нашей 1B на arch-ml.
- Контур axiom уже несёт механику Ornith-граблей (валидация, изоляция, анти-hacking) — третья ветка переиспользует готовые стражи, а не строит новые.
- Замкнутый цикл при успехе даёт самоэволюционирующую учебную программу — стратегический актив за пределами одного сравнения.

### Negative

- **3× RL-времени GPU** и самая тяжёлая имплементация: три потока роллаутов на шаг, joint-GRPO по трём ролям, буфер новизны — крупнейшая дельта раннера из всех.
- **Реальный риск V-коллапса**: слабая база (пилот ~900 шагов, SFT впереди) может не выдать ни одной валидной задачи — ветка честно остановится по п. 4; вердикт тогда покрывает две ветки + факт нежизнеспособности третьей на данной базе.
- Три попарных сравнения требуют поправки Бонферрони — порог различимости растёт.

## Reversibility

**reversible.** Ветка — конфигурация раннера; остановка по п. 4 — штатный fail-closed. Откат — git revert дельты; никаких данных/весов не затрагивается.
