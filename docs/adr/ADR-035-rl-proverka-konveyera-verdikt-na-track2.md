# ADR-035. RL на нашей базе — проверка конвейера; вердикт методологий — на track-2; микро-лесенка — в проработку

- Date: 2026-10-06
- Status: Accepted — решение владельца 06.10 («всё три по приоритету») на основании тезиса владельца: «Задачи харнесса — многоходовый агентный цикл (list_files / read_file / edit_file / run_gates / finish) на контексте 8–32k, с чтением YAML-правил и правкой файлов. Скелет L3 (1B параметров, 20B токенов) такого не потянет ни при каком SFT. Это проверка конвейера, а не рабочая модель»
- Амендменты: ADR-027 (вердикт трёх веток переезжает на track-2), ADR-030 (track-2 становится домом методологического вердикта), AD-1 (ось победы — формулировка откладывается к решению владельца по масштабу, п. 5)

## Context

Тезис владельца проверен против известных ориентиров: FrogNano довёл 4B-модель до 37 % SWE-bench на базе с ~36T токенов претрейна и тяжёлым RL; наша база — 1B на ~20B токенов (в ~1800 раз меньше данных, вдвое меньше параметров). Многопаузовый агентный цикл (инструменты → файлы → YAML-правила → гейты) на 8–32k контекста требует инструктивно-агентной глубины, которая на этом масштабе не возникает ни при каком объёме SFT. Профиль не выравнивается калибровкой: это разрыв **класса задач**, а не полосы трудности. Следствие: RL на нашей модели в текущем классе задач не даёт обучающего сигнала (pass_rate → 0, health-гейты останавливают) — и не должен его давать: стадия переопределяется.

## Decision

1. **RL на нашей базе = wire-тест конвейера (разовое мероприятие).** Запуск полного контура на чекпойнте после SFT: роллауты → вердикты → награда → health-гейты → честная остановка по вырождению (pass_rate ≈ 0 — **ожидаемый и правильный** исход, детектируемый стражами C-045 как подтверждение их работы). Журнал стадии A4 маркирует `scope: conveyor-wire-test`. Стадия закрывается фактом корректной работы всех механик, а не pass-rate.
2. **Методологический вердикт трёх веток (ADR-027/029) исполняется на track-2** — открытой модели, где capability существует: Tunix + Gemma-3-4B-it (Stage B ADR-030). Ветки `laguna | frognano | ornith` репетируются с градиентами до полноценного сравнения; вердикт «какая методология работает» выдаётся на открытой модели и **индикативен для нашей базы** (переносимость ограничена архитектурой — ADR-030 п. 3).
3. **Микро-лесенка — задача линии-2 с оценкой реализуемости (не обещание).** Спроектировать класс задач под фактический потолок 1B/20B: одиночные ходы, микроконтекст (~512–1k токенов), без файловых операций — кандидаты: токен-левел/форматные задачи, микро-редакты по шаблону, lookup по лесенке концептов. Результат проработки: вердикт «реализуемо/нет» + прототип задач + оценка pass-rate на чекпойнте пилота. Только после положительного вердикта — RL-обучение на нашей базе как настоящее обучение.
4. **Приоритеты исполнения (решение владельца):** (а) wire-тест конвейера — после SFT-стадии, разово; (б) вердикт методологий на track-2 — параллельный трек, не блокируется ногами; (в) микро-лесенка — проработка линии-2 в фоне.
5. **Ось победы (AD-1): формулировка «агентная арена против K3» на масштабе 1B/20B недостижима — откладывается к решению владельца о масштабе** (аренда 20B+ на 8×H100 после ADR-034, или рост модели). До того момента фактические оси проекта: (а) работающий конвейер с нуля end-to-end (претрейн → SFT → wire-RL), (б) качество претрейна против известных кривых (VERIFICATION-LEG, BPB), (в) методологический вердикт RL на открытой модели. Итоговая переформулировка оси победы — решение владельца с числами на столе; DECISION-PACKAGE.json не правится без его явного выбора.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Вердикт только на track-2** (без пунктов 1 и 3) | минимум работы | конвейер остаётся непроверенным end-to-end на нашей модели; класс задач для нашей базы не спроектирован вовсе; отклонено владельцем |
| **Микро-лесенка вместо вердикта на track-2** | наш базовый RL становится настоящим | микро-класс не отвечает на вопрос «какая методология RL работает» — методики (CISPO, машина раундов, joint-GRPO) требуют capability; отклонено владельцем |
| **Настаивать на агентной арене для 1B/20B** | ось AD-1 неизменна | противоречит тезису владельца и опыту FrogNano; гарантированный нулевой сигнал; отклонено |

## Consequences

### Positive

- Честная фиксация масштаба: конвейер и методология развиваются на том, где каждая работает (конвейер — на нашей базе, capability-RL — на открытой модели), без симуляции возможностей.
- Health-гейты получают своё настоящее применение: детекция вырождения на wire-тесте — их поведенческая приёмка.
- Микро-лесенка открывает потенциально настоящий RL на нашей базе в пределах физики масштаба.

### Negative

- Ось победы AD-1 в текущей формулировке недостижима на этом масштабе — проектный нарратив «агент против K3» откладывается к решению о масштабе; это цена честности.
- Три параллельных направления при одной GPU-очереди (ноги / track-2 / проработка) — дисциплина окон (RUNBOOK §7) становится критичной.
- Вердикт методологий на открытой модели индикативен: перенос на нашу базу ограничен архитектурой (ADR-030 п. 3) — финальная валидация на нашей базе возможна только после микро-лесенки или роста масштаба.

## Reversibility

**reversible** с одной оговоркой: wire-тест — разовое мероприятие, повторяется тривиально; перенос вердикта на track-2 — организационный; микро-лесенка — пока только проработка. Возврат к агентной арене на нашей базе возможен при росте масштаба (новая база → новая калибровка → ADR).
