# ADR-041. Дисциплина памяти JAX-прогонов на GB10: XLA_PYTHON_CLIENT_MEM_FRACTION обязателен, префлайт-гейт перед стартом (инцидент OOM 08.10)

- Date: 2026-10-08
- Status: Accepted

## Context

**Инцидент 08.10.2026, стенд GB10 (`spark-44c3`), 08:45–08:47.** Ночной прогон профилировки
`nsys` по клетке l3-full (6 шагов, T=8192, B=1, micro=1) завершился **global OOM** хостовой
памяти и **неплановым ребутом стенда**. Из журнала прошлого бута:

- `34` события `oom-kill` с `global_oom` (не cgroup-scoped): убиты мой `python`
  (pid 481493, `session-697.scope`, total-vm 128 ТБ — это JAX),
  а также сервисы владельца: `systemd`, `NetworkManager`, `pipewire`, `wireplumber`,
  `dbus-daemon`, `xdg-document-portal`, `snap`, и даже стендовый сторож `mem-guardian.service`;
- `NVRM: nvCheckOkFailedNoLog: Out of memory [NV_ERR_NO_MEMORY]` (`mem_desc.c:1359`,
  `system_mem.c:345`) — драйвер NVIDIA тоже упал по памяти;
- журнал прошлого бута обрывается на 08:45:52, новый бут — 08:47:11.

**Корневая причина (проверено, не гипотеза):** в контуре нигде не задан
`XLA_PYTHON_CLIENT_MEM_FRACTION`. Проверено grep'ом по репо и по окружению стенда
(`~/.bashrc`, `~/.profile`, `~/.config`): из XLA-флагов есть только
`--xla_gpu_deterministic_ops` для гейтового профиля (ADR-013). Значит **любой** JAX-процесс
(профилировка, паритетная нога, раннер претрейна) стартовал с дефолтным резервом JAX
(~75% памяти устройства) — на совмещённом стенде это гарантированный OOM-каскад.

Это **повторение инцидента 26.09.2026** (смоук axiom на GB10 при живом SFT владельца:
одновременная смерть нескольких процессов, логи без traceback, симптом SIGKILL). Правило
после 26.09 было сформулировано в рабочих заметках, но **не было механизировано**: ни в
скриптах приборов, ни в правилах CONSTRAINTS, ни в префлайте раннера. Словесное правило
не пережило смены контекста — это и есть дефект, который закрывает настоящий ADR.

**Цена инцидента:** потерян ночной прогон, стенд ребутнут (убиты пользовательские сервисы),
риск для чужих прогонов владельца на общем ресурсе; сам nsys-отчёт уцелел (578 МБ) и был
использован для атрибуции MFU.

## Decision

1. **`XLA_PYTHON_CLIENT_MEM_FRACTION` обязателен для любого JAX-процесса в контуре.**
   Единый префлайт-модуль `tools/jax_preflight.py` выставляет лимит **до `import jax`**
   (дефолт `0.5`, перекрывается одноимённой переменной окружения; для совмещённых
   прогонов — 0.15–0.5 по фактически свободной памяти). Все JAX-запускающие инструменты
   `tools/*.py` импортируют префлайт первой строкой исполняемой части.
2. **Префлайт-гейт перед стартом (fail-closed).** До запуска прогона фиксируется состояние
   стенда: `nvidia-smi --query-compute-apps=pid,process_name,used_memory` и `free -g`;
   при обнаружении чужих compute-процессов запуск **не стартует** без явного
   текстового разрешения владельца в `~/gb10-shared/.locks/` (правило 26.09, п.3).
3. **Механический страж.** Правило в `CONSTRAINTS.yaml`: у каждого JAX-инструмента
   `tools/*.py` (набор перечислен явно) в коде обязан присутствовать префлайт-вызов —
   `each_file_must_contain` по маркеру префлайта. Правило проверяется в гейте и не
   откатывается молча.
4. **Инцидент записан в `evidence/incidents.yaml`** с датчиком-предвестником
   (префлайт: чужие процессы/свободная RAM ниже порога) и стражем (правило CONSTRAINTS +
   тест префлайта), по образцу линии-1.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **A. Единый префлайт-модуль + правило CONSTRAINTS + запись инцидента** (принято) | Лимит нельзя забыть: он в одном месте и под механическим стражем; состояние стенда проверяется до старта; инцидент оставляет след для следующего исполнителя | Требует правки 11 инструментов и правила; при жёстком лимите прогон может упасть на OOM-XLA раньше, чем на хосте (это правильный, явный отказ) |
| B. Оставить словесное правило (статус-кво) | Ничего не делать | Уже проверено дважды: словесное правило теряется при смене контекста; инцидент 08.10 — прямое следствие. Повторится третий раз |
| C. Поставить лимит только в приборах профилировки (узко) | Минимум правок | Не закрывает раннер претрейна, паритетную ногу и бенчмарки — то есть большинство реальных прогонов; дыра остаётся |
| D. Внешний враппер/юнит-обёртка над всеми JAX-прогонами | Единая точка | Ломает интерактивные запуски и `nsys`-обёртку; настройка живёт вне репо и не видна в диффе; стражи CONSTRAINTS её не видят |

## Consequences

### Positive
- OOM-каскад от JAX-резерва закрыт структурно: лимит применяется до инициализации рантайма.
- Совмещённые прогоны получают явный предстартовый гейт вместо надежды на удачу.
- Правило проверяемо механически (CONSTRAINTS + тест) — не зависит от памяти исполнителя.

### Negative
- Лимит `0.5` при реально свободных 60% может дать отказ XLA-аллокации там, где раньше
  «пролезало»; такой отказ — явный и диагностируемый, но это новый класс падений.
- Значения лимита для совмещённых прогонов остаются ручным решением (автоматический
  подбор по `free -g` — вне объёма; снижение риска — параметр окружения).
- Правило CONSTRAINTS статично (проверяет наличие префлайта, а не корректность значения) —
  корректность значения ловится только префлайт-гейтом и логами прогона.
- Правка 11 инструментов — риск регрессий в их CLI; закрывается тестами и тем, что
  префлайт ничего не делает, если лимит уже выставлен окружением.

## Reversibility

**Обратимо, стоимость низкая.** Откат = снятие префлайт-импортов и правила CONSTRAINTS
(один revert-коммит); сам ADR помечается Superseded. Данные и артефакты не затрагиваются.
Повторное принятие возможно в любой момент — цена та же. Необратимой миграции нет.
