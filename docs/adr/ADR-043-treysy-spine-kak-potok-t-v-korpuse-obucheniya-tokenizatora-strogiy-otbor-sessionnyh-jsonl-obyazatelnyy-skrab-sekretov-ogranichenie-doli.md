# ADR-043. Трейсы Spine как поток T в корпусе обучения токенизатора

- Date: 2026-10-08
- Status: Accepted

## Context

**Требование владельца (08.10.2026):** «добавь трейсы Spine в обучение токенизатора»,
с уточнением состава — вариант **D: всё, включая hermes/openclaw**.

**Обследование (измерено, не оценка).** «Spine» в контуре — не один каталог, а семейство
проектов и агентских рантаймов. Сырые объёмы:

| Источник | Размер | Что внутри |
|---|---|---|
| `~/.claude/projects` | 1.5 ГБ | **jsonl 1363.6 МБ (1469 файлов)** — трейсы сессий Claude Code; txt 68.5 МБ; jpg/json/md — мелочь |
| `~/.arch-ml/sessions` | 73 МБ | **jsonl 72.4 МБ (145 файлов)** — сессии нашего Spine-контура |
| `~/.arch-ml/reports` | 6.2 МБ | отчёты харнессов (373 файла) |
| `~/.qwen` | 597 МБ | jsonl 98.3 МБ (519), **js 252.7 МБ — код/установка**, wasm/node |
| `~/.openclaw` | 9.2 ГБ | jsonl 144 МБ (36), **so 2678 МБ, sqlite 721 МБ, «12»/«9»/«11» ≈ 2.3 ГБ — бинарь/БД/установка** |
| `~/.hermes` | 4.2 ГБ | jsonl всего 3.4 МБ (8), **pack 1338 МБ, db 1134 МБ, js/py 288 МБ — установка** |
| `spine-wow-live/arch-session*`, `spine-archive-20260927` | ≈12 МБ | экспортированные архитектурные сессии (context/handout/reports) |

**Ключевой вывод обследования:** «всё» из варианта D **нельзя** вливать как есть. В указанных
каталогах текстовый трейс-слой — это **1.64 ГБ jsonl (2177 файлов)**, а рядом лежат
установочные пакеты, shared-библиотеки (`.so` 2.7 ГБ), SQLite-базы (1.1 + 0.7 ГБ), venv с
чужими данными (`fake_useragent/data/browsers.jsonl`), чужие eval-результаты репозитория
`hermes-agent/evals/...`. Влив их «как есть»: (а) засорим словарь техническим шумом
(base64, хеши, пути пакетов), (б) утащим в корпус чужие и, возможно, лицензионно чужие тексты,
(в) получим 90% мусора в выборке вместо трейсов.

**Приватность — не гипотетическая.** В уже собранном доменном датасете (`axiom-domain-ds-v1`,
компонент E — агентные эпизоды из `~/.claude/projects`) счётчик редактирований: **1906**,
в том числе `aws 49, bearer 25, openai 96, private_key 56, private_key_dangling 51,
url_password 209, env_assignment 636, hex_env 733`. То есть трейсы **гарантированно**
содержат секреты, и без скраба их вливать нельзя ни в каком варианте.

**Инструмент уже есть:** `tools/axiom_ds/` (`scrub.py` — скраб секретов, `build.py` — парсер
сессий и эпизодизация, `cpt_serialize.py`, `card.py`) — пайплайн ADR-020, проверенный на
E-компоненте. Повторно изобретать парсер и скраб не нужно; их надо переиспользовать.

## Decision

1. **Поток T (traces) входит в корпус обучения токенизатора** — как отдельный источник
   `tools/build_domain_corpus.py`, наряду с доменным потоком R.
2. **Строгий отбор:** включаются только **сессионные jsonl-трейсы** с валидацией формата
   (строка = событие сессии: роль/текст/вызов инструмента). Явные исключения: `venv/`,
   `node_modules/`, `site-packages/`, `evals/`, `*.so`, `*.sqlite|*.db`, `*.pack`, файлы без
   расширения и любые бинарные. Признак включения — разбор строк, а не только имя файла.
3. **Обязательный скраб секретов** через `tools/axiom_ds/scrub.py` **до** записи корпуса;
   отсутствие скраба — fail-closed (корпус не собирается). Скраб применяется к потоку T
   обязательно, к R — как и раньше (по тому же пайплайну).
4. **Ограничение доли:** доля T в выборке обучения токенизатора ограничена и параметризована
   (`--traces-share`, дефолт **≤0.15**), чтобы трейсы-логи (≈1.6 ГБ сырья) не задавили
   домен R (960 МБ) и потоки W/C. Фактическая доля фиксируется в манифесте.
5. **Собственный текстовый корпус T** (после скраба и нормализации) не попадает в git:
   приватные тексты и производные — только на диск, в репозиторий — манифест/карточка
   (C-032/C-033, AD-6).
6. **Прогоны — на GB10 с `XLA_PYTHON_CLIENT_MEM_FRACTION`** (ADR-041) и префлайт-гейтом.
7. **Если сессии TUI-агента лежат только в SQLite** (openclaw 721 МБ, hermes db 1134 МБ) —
   их извлечение делается отдельной дельтой с явным контрактом; до этого такие источники
   фиксируются в манифесте как `EMPTY-PENDING` с причиной, а не имитируются.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Поток T: строгий отбор jsonl-сессий + скраб + доля ≤0.15** (принято) | Реально приносит трейсы, а не установку; секреты вырезаются; домен не задавлен | Требует валидации формата и параметра доли; SQLite-источники (openclaw/hermes) отложены |
| B. Влить «всё» из D как есть (15.5 ГБ) | Буквальное исполнение | `.so` 2.7 ГБ, SQLite 1.8 ГБ, venv, чужие eval — мусор в словаре; секреты без контроля; лицензионно чужие тексты; корпус теряет смысл |
| C. Только `~/.claude/projects` | Просто, ядро трейсов | Не выполняет выбор владельца (D) — теряем qwen/openclaw/hermes и arch-session |
| D. Совсем без трейсов | Ноль рисков | Отклонено владельцем: домен Spine-доков и смешанной речи не покрывается |

## Consequences

### Positive

покрытие смешанной речи (русский + идентификаторы + код + пути), характерной
для документов Spine; переиспользован проверенный пайплайн скраба; доля ограничена и измеряема.

### Negative

(1) корпус вырастет, сборка станет дольше (чтение ~2200 jsonl);
(2) качество скраба критично — пропущенный секрет = утечка в артефакт корпуса и, потенциально,
в веса; (3) трейсы шумны (JSON-обёртки, повторы системных промптов, tool-call дубликаты) —
нужна дедупликация, иначе словарь перекосит в служебные строки; (4) доля 0.15 — эвристика,
которая может быть пересмотрена после замера на holdout; (5) SQLite-сессии openclaw/hermes
останутся непокрытыми до отдельной дельты.

## Reversibility

**Обратимо, цена низкая.** Поток T включается флагом (`--traces-*`); отключение = вернуть
корпус без T (пересборка). Скраб и лимит доли — параметры. Откат решения = отключение потока
и пометка ADR Superseded. Данные на диске удаляются владельцем по его решению; в git их нет.
Необратимых миграций нет.
