# ADR-049. Политика ремaтериализации как рычаг backward

- Date: 2026-10-09
- Status: Accepted

## Context

**Полная раскладка шага получена** (диагностика с новыми ногами, l3-full, `chunked_cc`, jit-оптимизатор, 20 шагов, сверка сошлась):

| Нога | Секунды | Доля |
|---|---|---|
| **`sec_backward`** | **14.698** | **73%** |
| `sec_forward` | 4.292 | 21% |
| `sec_backopt` (оптимизатор) | 1.223 | 6% |
| `sec_loader` | 0.001 | — (вне шага) |
| сверка | 20.213 из 20.130 с | **100.4%** |

KPI — 407 ток/с. Внутри forward: `sec_kda` 1.453, `sec_ce` 1.127, `sec_mla` 0.463, `sec_moe` 0.163.

**Отключение grad-checkpointing запрещено контуром** (раннер отказывает: «без remat графа прогон упирается в память активаций — урок OOM 956 ГиБ»). То есть backward обязан пересчитывать активации, и это не тюнингуется «в лоб».

**Но текущая реализация использует `jax.checkpoint` без политики** — то есть пересчитывается **всё** (save-nothing). JAX поддерживает policy, при которой сохраняются дорогие результаты и ремaтериализуются дешёвые. Отношение backward/forward = 3.4× (вместо типичных ~2× для тренировки) указывает, что значительная часть этих 14.7 с — именно пересчёт.

## Decision

1. **Параметризовать политику ремaтериализации** в местах, где стоит `jax.checkpoint` (backbone-слой `net/model.py`, тела scan в `net/kda.py`): конфигурируемое значение `remat_policy` с вариантами как минимум:
   - `none` — **текущее поведение** (дефолт; save-nothing, максимальная экономия памяти) — сохраняется побитово;
   - `dots_saveable` — сохранять выходы matmul, ремaтериализовать elementwise;
   - `dots_with_no_batch_dims_saveable` — то же, но только для matmul без batch-измерений (обычно безопаснее по памяти).
2. **Численный паритет обязателен:** политика меняет только *что* пересчитывается, не математику; тесты должны подтвердить совпадение loss/градиентов между вариантами (малые формы, CPU).
3. **Критерии (измеряются на GB10):** (а) `sec_backward` существенно ниже 14.7 с без превышения лимита памяти (ADR-041: лимит XLA, никаких «до упора»); (б) KPI растёт; (в) при `none` результат **побитово** тот же, что сейчас (дефолт не двигается).
4. **Память — жёсткий ограничитель:** если выбранная политика не влезает в лимит, это фиксируется как «неприменимо по памяти», а не «откатываем лимит». Матрица «политика → время/память» прикладывается отчётом.
5. Прогоны — на GB10 с префлайт-гейтом (ADR-041); при чужой нагрузке — отказ, не совмещение.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Параметризовать policy, мерить матрицу «время/память»** (принято) | Прямо адресует 73% шага; обратимо флагом; дефолт не меняется | Память может вырасти — под жёстким лимитом; возможен вариант, что выигрыш мал (тогда это тоже результат) |
| B. Отключить grad-checkpointing | Убирает пересчёт | **Запрещено контуром**: OOM 956 ГиБ (память активаций l3-full) |
| C. Уменьшить модель/последовательность | Гарантированно влезает | Смена объекта обучения (ADR-021) — не эта дельта |
| D. Оставить полный пересчёт | Ноль риска | 73% шага в backward; 55% MFU недостижимы даже при идеальном forward |

## Consequences

### Positive
- Адрес оптимизации — измеренный (backward 73%), а не предположенный.
- Политика переключаема, дефолт сохраняет текущее поведение побитово → сравнивать можно честно.
- Матрица «политика → время/память» станет аргументом и для выбора режима тренировки.

### Negative
- Политики JAX — тонкая настройка; возможен сценарий «XLA игнорирует ожидания» (тогда вывод — отрицательный результат, а не тихая деградация).
- Рост памяти может оказаться неприемлемым именно на этом профиле (1.01 млрд параметров, T=8192).
- Добавляется конфигурационная поверхность (риск ошибки конфигурации) — закрывается fail-closed валидацией значения.
- Сверка «сумма ног = шаг» на границе 100.4% показывает, что диагностика чуть переоценивает (перекрытие/округление) — это известная граница метода, а не точность до знака.

## Reversibility

**Обратимо, цена низкая.** `remat_policy=none` возвращает текущее поведение (и оно дефолт). Правки локальны в обёртках `jax.checkpoint`. Числа/данные не затрагиваются. Необратимых миграций нет.

## Amendment (09.10.2026) — что оказалось доступно, а что нет

**Факт, установленный проверкой (не предположение):** в установленной версии JAX (**0.10.2** на GB10) политики **`offload_dots_saveable` НЕ существует** — `hasattr(jax.checkpoint_policies, 'offload_dots_saveable') == False`. Ближайшее по смыслу — **фабрика** `jax.checkpoint_policies.offload_dot_with_no_batch_dims(offload_src, offload_dst)`, которая требует двух аргументов (пространство памяти источника/назначения) и готовая callable не является. Похожим именем политика не подменена; отсутствие зафиксировано в `net/config.py`, `net/remat.py` и пином-тестом `test_offload_policy_is_absent_in_this_jax_version`.

**Итоговый набор политик в реализации:** `none` (дефолт, побитово прежнее поведение), `dots_saveable`, `dots_with_no_batch_dims_saveable`, `everything_saveable` (крайняя точка шкалы). Единая точка «имя → callable» (`net/remat.py`), fail-closed валидация значения, число remat-границ по-прежнему определяется `grad_ckpt_policy` — политика меняет только содержимое границы.

**Матрица на GB10 (измерено, 20 шагов, l3-full/`chunked_cc`):**

| Политика | KPI | `sec_backward` | Комментарий |
|---|---|---|---|
| `none` | 407.2 ток/с | 14.635 с | полный пересчёт |
| `dots_with_no_batch_dims_saveable` | **468.6 ток/с** | **11.950 с** | лучшая рабочая точка (×1.15) |
| `dots_saveable` | — | — | OOM: аллокация **106.94 ГиБ** |
| `everything_saveable` | измеряется | — | ожидается OOM (шкала вверх исчерпана в память устройства) |

**Вывод по линии remat:** шкала «сколько сохранять» **упирается в память устройства**, а не в механику: лучшая достижимая точка — `dots_with_no_batch_dims_saveable`. Хост-оффлоад (единственный способ пойти дальше вверх) в этой сборке JAX недоступен как готовая политика. Решение о попытке собрать политику через фабрику `offload_dot_with_no_batch_dims` (с явными memory spaces) **отложено** до отдельного решения: выигрыш не гарантирован, а конфигурация memory spaces на унифицированной памяти GB10 требует проверки, а не догадки.
