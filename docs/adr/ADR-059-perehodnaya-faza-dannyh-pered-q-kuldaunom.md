# ADR-059. Переходная фаза данных перед Q-кулдауном: разделить смену корпуса и старт LR-decay

- Date: 2026-11-13
- Status: Proposed

## Context

В живом прогоне `long-jax2-ab14050` (шаг 42 435 на 13.11.2026, target 50 000) объявлен decay-шард Q
(`--decay-stream Q`). По действующей механике `PackedTokenLoader` на шаге `decay_start = 47 500`
**одновременно** происходят два события:

1. данные переключаются с потока W на Q целиком (жёсткая граница, а не градиент);
2. стартует косинусный спад learning rate с 1e-3 до 0 за 2 500 шагов.

Q — не тот же поток, что W: по манифесту и замеру 30.09.2026 W содержит `int_score=3` у 85,7 %
документов, Q фильтрован порогом `int_score >= 4` (верхние ~14,3 % потока), плюс окно длины
800…50 000 символов и 15 % кода с тестами. То есть на границе меняется распределение данных,
а не только их источник.

Эмпирическое основание считать это риском:

- Lara Mini Base Technical Report (arXiv:2611.16956, §2.3): «A sudden change in data can cause a
  model to forget what it learned earlier, and keeping part of the earlier mixture reduces this
  forgetting» — поэтому в рецепте Lara между main и anneal стоит отдельная transition-стадия
  0,6T (10 % бюджета) при **постоянном** LR; смена микса и спад LR разведены.
- Наш собственный прогон: на шаге 28 449 сменился дамп Common Crawl внутри W (CC-MAIN-2023-14 →
  CC-MAIN-2013-48). Медиана loss выросла с 4,35 до 4,58 (+5,3 %), и возврат к прежнему уровню
  занял ~9 тыс. шагов. Причина — смена режима данных, а не конфига.
- В хвосте прогона на адаптацию к смене данных остаётся 2 500 шагов, причём LR в это время уже
  падает. Если Q даст скачок, «высокого» LR для перестройки уже не будет.

Ограничение по времени: до 47 500 остаётся ~5 065 шагов (~2,1 сут), поэтому решение должно быть
реализуемо и проверяемо до этой границы.

## Decision

Ввести **переходную фазу** между stable и decay: последние `transition_steps` шагов перед
`decay_start` данные берутся из W и Q со ступенчато растущей долей Q (0 → 100 %), при
**постоянном** LR stable-фазы. На `decay_start` в Q уже 100 % данных, и начинается только спад LR.

Параметры для текущего прогона:

| параметр | значение |
|---|---|
| `transition_steps` | **1 000** шагов (≈16,4M токенов) |
| `transition_start` | **46 500** |
| доля Q в переходе | линейно 0 → 1 по шагам |
| правило выбора | детерминированное, без состояния: Q выбирается на шаге `t` (0-based внутри перехода), если `floor((t+1)(t+2)/(2N)) > floor(t(t+1)/(2N))`, где `N = transition_steps`; это в точности даёт кумулятивную долю `(t+1)/N` |
| LR | не меняется: спад по-прежнему начинается на `decay_start` |
| расход Q | ≈ 0,5·1 000 + 2 500 = 3 000 шагов ≈49M токенов из 855M — запас 17× |

Правило выбора обязано быть **функцией только номера шага** (а не накопленного счётчика): иначе
resume из курсора даст другой поток, чем непрерывный прогон, и нарушится L-6.

Фаза добавляется в курсор (`phase: transition`) и в журнал сегмента; `transition_steps=0`
воспроизводит текущее двухфазное поведение побитово (регрессионный тест).

## Alternatives

1. **Оставить как есть (статус-кво).** Плюс: ноль работы и риска. Минус: смена распределения
   совпадает со спадом LR; при скачке loss в хвосте нет шагов на адаптацию. Отклонено: цена
   риска выше цены 1 000 переходных шагов.
2. **Пересобрать Q как смесь medium+high quality (например, 70 % score≥4 / 30 % score=3).**
   Плюс: без изменений кода, сглаживание «из коробки». Минус: необратимо размывает anneal-выборку
   и снижает ценность Q-кулдауна; к тому же не убирает жёсткую границу, а лишь уменьшает её
   амплитуду. Отклонено.
3. **Сдвинуть старт LR-decay позже, оставив жёсткое переключение данных.** Плюс: проще. Минус:
   меняет расписание LR и бюджет anneal; смена данных всё равно остаётся одномоментной, а
   именно от неё скачок. Отклонено.
4. **Разбить Q на два шарда и подавать их последовательно.** Плюс: без изменения кода. Минус:
   `_StreamIterator` перемешивает документы внутри окна (`shuffle_window`), поэтому порядок
   «сначала смесь, потом чистый Q» не гарантируется. Отклонено.

## Consequences

Положительные:

- Смена распределения происходит при LR 1e-3 — модель успевает перестроиться до спада.
- Формально закрывается расхождение с рецептом Lara (transition перед anneal).
- Механика переиспользуема для будущих смен микса (W→W+C, смена дампа и т. п.).

Отрицательные (обязательны к учёту):

- **Усложнение контракта загрузчика**: третья фаза в `PHASES`, новое поле курсора, новое поле
  журнала. Старые чекпоинты совместимы (отсутствующее поле = 0), но обратная совместимость
  «новый код → старый курсор» требует явной проверки.
- **1 000 шагов stable-фазы уходят на смесь вместо чистого W** — это осознанное сокращение
  времени обучения на «широком» корпусе на 2 % бюджета.
- **Q расходуется раньше**: 16,4M токенов Q сгорают при высоком LR, что чуть снижает запас
  anneal-выборки (не критично: 49M из 855M).
- **Новый код на живом прогоне**: требуется канарейка на копии чекпоинта до рестарта; риск
  ошибки реализации переносится на 2 дня до границы.
- Переход не устраняет скачок полностью — он его **растягивает и переносит на высокий LR**;
  величина скачка останется, если Q действительно «труднее» W.

## Reversibility

- **До шага 46 500** решение обратимо полностью: снять флаг `--transition-steps`, рестарт не
  нужен (флаг инертен до `transition_start`).
- **В переходе (46 500…47 499)** обратимость частичная: курсор уже в фазе `transition`; откат
  требует правки курсора или прогона оставшихся шагов перехода с `transition_steps=0` (потеря
  нескольких шагов).
- **После 47 500** решение необратимо для этого прогона: курсор в фазе `decay`.
- Стоимость отката на любом этапе — один рестарт (~15 мин) и ≤50 шагов пересчёта.

## Evidence plan

| гейт | проверка |
|---|---|
| до рестарта | unit-тесты: границы фаз, кумулятивная доля Q, resume ≡ непрерывный прогон, `transition_steps=0` ≡ старое поведение |
| канарейка | 3 шага от копии pinned-чекпоинта: журнал показывает `phase: transition` на 46 500-м шаге и `q_share`, близкий к 0 в начале окна |
| после 46 500 | журнал: `phase` меняется stable→transition→decay; доля Q в `token_share` растёт; loss не даёт скачка >3 % от медианы 1 000 шагов (порог Lara) |
| финиш | сравнение медианы loss последних 100 шагов с/без перехода — только если будет параллельная ветка; в текущем прогоне — наблюдение |
