# ADR-060. Детектор changepoint в кривой loss

- Date: 2026-11-14
- Status: Accepted (решение владельца 14.11.2026: «добавь детектор changepoint
  (CUSUM/страница), а не только относительный дрейф»)
- Маршрут: Fast (1 триггер: significant_nfr). Код детектора исполняется кодовым
  харнессом; ADR, дельта-спека, правила и реестр — архитектурные артефакты.
- Модель-автор: spine-arch

## Context

14.11.2026 на живом прогоне `long-jax2-ab14050` зафиксирована ступень loss:
медиана 300 шагов выросла с **4,320** (шаги 41 500–42 300) до **4,489**
(шаги 42 500–43 100), то есть **+3,9%** — крупнейший сдвиг за прогон. Модель
при этом продолжила учиться: наклон после сдвига **−0,084 loss / 1000 шагов**.
Сдвиг не связан ни с рестартом (начался в середине сегмента 571), ни со сменой
шарда (`shard_index=2/52`), ни с расписанием (LR постоянный 1e-3), ни с порчей
данных (декодированные чанки связны).

Действующий мониторинг — **относительный дрейф к медиане последних 1000 шагов
(+3%)**, заимствованный из Lara Mini Base (arXiv:2611.16956, правило сопровождения
прогона). Он ступень **не увидел**: после сдвига окно 1000 шагов само впитало
новый уровень, и дрейф составил **−0,05%**. Это не дефект реализации, а свойство
статистики: rolling-медиана — адаптивный baseline, а ступень, которая держится,
для неё не аномалия. Нужен детектор **точки изменения**: сравнение «до» и «после»,
а не «сейчас» и «недавно».

## Decision

1. **Инструмент** `tools/check_loss_changepoint.py` — двухоконный робастный тест
   (класс Page) на блочных медианах кривой loss:
   - поток `metrics-seg-*.jsonl` (схема `pretrain-metrics/v1`) читается целиком,
     сортируется по `step`, дубли шага схлопываются (перекрытие сегментов);
   - блок **B = 25** шагов → медиана блока (робастно к выбросам, σ снижается ~в 5 раз);
   - окно «после» **N = 6** блоков (150 шагов), окно «до» **M = 12** блоков
     (300 шагов), зазор **G = 2** блока (50 шагов), чтобы граница не размывала
     оба окна;
   - статистика: `Δ = med(recent) − med(reference)`,
     `z = Δ / (σ_b · sqrt(1/N + 1/M))`, где `σ_b = 1.4826 · MAD` по всем блочным
     медианам (робастная оценка масштаба);
   - срабатывание: **|Δ| ≥ 0,10** (абсолютный пол — отсекает медленный тренд
     обучения) **и |z| ≥ 3,5**, удержание **≥ 3 блоков подряд**;
   - события в пределах 3 блоков сливаются, репортится начало события.

2. **Реестр известных сдвигов** `evidence/monitoring/changepoints.yaml`.
   Событие подавляется, если `|detected_step − step| ≤ tol` (по умолчанию 400).
   Запись реестра обязана нести `owner`, `reason`, `ref` и `review_by`.
   Неподавленное событие → **exit 1**; подавленные и отсутствие данных → **exit 0**.

3. **Правила CONSTRAINTS:**
   - **C-058** `--selftest` — исполняется всегда (CI, без стенда), severity critical,
     kind structural: доказывает, что детектор ловит ступень и не ловит шум/тренд;
   - **C-059** живой прогон по каталогу метрик с реестром, `requires: [stand]`,
     severity high, kind behavioural: неподавленный сдвиг — красный гейт.

4. **Контракт CLI:** `--metrics <dir|file> [...]`, `--ledger <yaml>`, `--block`,
   `--recent`, `--reference`, `--gap`, `--min-abs`, `--z-threshold`,
   `--persist`, `--tol`, `--json`, `--quiet`, `--selftest`.
   Коды возврата: **0** — чисто/нейтрально, **1** — неподавленный changepoint,
   **2** — некорректный вход (битая строка, NaN/Inf loss, пустой набор).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **Статус-кво: относительный дрейф к медиане 1000 шагов (+3%)** | уже есть, ноль цены, ловит быструю деградацию | ступень 42 375 не увидел (−0,05%): адаптивный baseline впитывает новый уровень; класс «тихая ступень» вне контроля — проверено на живых данных 14.11 |
| **Классический CUSUM по остаткам глобального линейного тренда** | простая реализация, стандартная теория | на реальных 29 170 шагах дал **32 срабатывания** при h=5σ: тренд локально нелинейный (плато + спуски), остатки автокоррелированы; порог, подавляющий шум, не ловит целевой сдвиг |
| **Page-Hinkley на per-step loss** | классика, минимум параметров | σ(loss) = 0,233, сдвиг 0,17 — это 0,7σ; порог, который его ловит, ловит и шум; нужна агрегация, то есть тот же блочный тест |
| **EWMA-контроль (Shewhart/EWMA-карта)** | простая, привычная | не даёт точку изменения и величину сдвига; та же проблема адаптивного baseline, что и у rolling-медианы |
| **Двухоконный робастный тест на блочных медианах (выбран)** | на живых данных: **3 события / 0 ложных** на 1 166 блоках, находит исторические сдвиги 14 538 и 28 588, даёт величину и направление | задержка обнаружения 50–150 шагов; требуется реестр известных сдвигов, иначе гейт остаётся красным |

## Consequences

### Positive

- Класс «тихая ступень loss» становится механически наблюдаемым: сдвиг 42 375
  и исторические 28 436 / 14 501 ловятся без LLM и без ручного просмотра графиков.
- Детектор даёт **величину и направление** сдвига — с этим можно принимать решение
  (продолжать, откатывать на pin, разбирать данные), а не только «что-то не так».
- Относительный дрейф +3% остаётся вторым, независимым стражем: он быстрее ловит
  резкую деградацию, changepoint — устойчивую ступень. Правила не дублируют друг друга.
- Реестр превращает шум в знание: каждый подавленный сдвиг имеет владельца,
  причину и ссылку на разбор.

### Negative

- **Задержка обнаружения 50–150 шагов** (2–6 блоков) — при 40 с/шаге это 0,5–1,7 ч;
  для быстрой деградации остаётся относительный дрейф.
- **Реестр — ручной артефакт.** Новый сдвиг делает гейт красным до разбора и записи;
  это желаемое поведение, но оно требует дисциплины владельца прогона.
- **Пороги откалиброваны на одном прогоне** (819M токенов, 29 170 шагов, English web).
  На другом масштабе, другой модели или другом составе данных понадобится
  рекалибровка; поэтому B/N/M/G/min_abs/z вынесены в CLI и в правило, а не зашиты.
- **Детектор не диагностирует причину.** Он не различает «данные стали труднее»
  и «модель деградировала»; сигнал требует разбора (сравнение с pin-чекпоинтом,
  декодирование чанков, профиль корпуса).

## Reversibility

**reversible.** Инструмент автономен и не входит в путь обучения; правила C-058/C-059
удаляются из `CONSTRAINTS.yaml` одной правкой, реестр — данные и остаётся как история.
Откат кода — удаление `tools/check_loss_changepoint.py` и его теста; на прогон
`long-jax2-ab14050` это не влияет (детектор работает офлайн по метрикам).

## Evidence

План доказательств (A4 — conformance, A5 — drift):

- **A4:** `--selftest` покрывает ≥ 9 кейсов: стационарный шум → 0 событий;
  линейный тренд → 0 событий; ступень вверх → обнаружена в ±150 шагов;
  ступень вниз → обнаружена; тяжёлые хвосты (t3) → 0 событий; NaN → exit 2;
  дубли шагов → схлопнуты без ложного события; подавление реестром → exit 0;
  сдвиг на некратном блоке → обнаружен.
- **A4 на реальных данных:** прогон по `long-jax2-ab14050/pretrain` (29 170 строк,
  590 сегментов) даёт ровно 3 события (≈14 538, ≈28 588, ≈42 488), все подавлены
  реестром → exit 0; без реестра — exit 1 и три строки отчёта.
- **A5:** еженедельный прогон C-059 на живом прогоне; каждое новое событие
  фиксируется в реестре с владельцем и разбором либо приводит к решению об откате.
