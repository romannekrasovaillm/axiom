# Карточка датасета `axiom-pretrain-l3` — ЧЕРНОВИК

- **Статус:** DRAFT. Состав, правила и источники — фактические; **хеши и объёмы
  шардов — прочерки**, они заполняются после полной загрузки (17B + 3B), до
  запуска претрейна (ADR-021: карточка и хеши фиксируются ДО старта, это
  блокирующее условие гейта).
- **Решение:** ADR-021 (претрейн-микс L3: 17B FineWeb-Edu / 3B Stack /
  1B decay), в рамках конвейера ADR-004 (данные готовятся локально, на аренду
  уходит публичный датасет с карточкой и хешем).
- **Расположение:** `~/gb10-shared/datasets/axiom-pretrain-l3/{W,C}/`
  (C-032/C-033: крупные данные вне рабочих каталогов репозитория).
- **Инструмент сборки:** `tools/prep_pretrain` (`build.py`, см. README модуля).

## 1. Состав

| Шард | Источник | Цель | Назначение |
|---|---|---|---|
| W | FineWeb-Edu (en, edu-фильтр), конфиг `sample-100BT` | 17B токенов | базовый язык и знания |
| C | The Stack, подмесь разрешённых лицензий, 5 языков | 3B токенов | код-компетенция под агентную ось |
| Q | decay/annealing: сужёный качественный микс из W + кодовые примеры с тестами | 1B токенов | финальное качество (WSD-декей) |

Шард Q этим пайплайном **не собран**: он берётся сужённым фильтром из W и C
(отдельная дельта). Пропорция W+C ≈ 85/15 — стартовая гипотеза ADR-021.

## 2. Правила отбора (фактические, зашиты в код)

**Шард W** (`tools/prep_pretrain/fineweb.py`):

- источник: `HuggingFaceFW/fineweb-edu`, конфиг `sample-100BT`, split `train`;
- качество: edu-классификатор источника; дополнительный порог `--min-int-score`
  **выключен** (ручка зарезервирована, в прогоне не использовалась);
- пустой/пробельный текст отбрасывается;
- дедупликация документов: точная, sha256 текста, окно 5 000 000 хешей (LRU);
  источник уже дедуплицирован — фильтр страховочный.

**Шард C** (`tools/prep_pretrain/stack.py`):

- языки: `python`, `rust`, `go`, `javascript`, `shell`;
- лицензии: `mit`, `apache-2.0`, `bsd-3-clause`, `bsd-2-clause`, `isc`, `0bsd`;
  файл проходит, только если **все** заявленные лицензии в белом списке
  (смесь вида `MIT + GPL-3.0` отбрасывается);
- длина файла по UTF-8: 256 Б ≤ len ≤ 100 КБ (микробные выбрасываются, длинные
  усекаются до 100 КБ);
- дедупликация документов: как в W (sha256 текста, окно 5М).

**Общее:** `approx_tokens = max(1, len(text) // 4)` (символы/4, ADR-021) — это
**оценка**, а не счёт токенизатором: собственный BPE 160K применяется позже, при
упаковке в 8K (`net/data.py`). Оценка смещена в сторону источника (текст с
большим числом пробелов/пунктуации даёт меньше токенов на символ).

**Формат записи (jsonl в zstd):** `{"text": …, "meta": {source, …}}`; у W в мете
дополнительно `id`, `dump`, `url`, `language`, `int_score`; у C — `lang`,
`license`, `path`, `repo`.

## 3. Происхождение и лицензии источников

| Источник | Лицензия датасета | Как используется |
|---|---|---|
| `HuggingFaceFW/fineweb-edu` | ODC-BY 1.0 (карточка датасета) | шард W целиком, публичный, без гейта |
| The Stack v2 / v1 (`bigcode/*`) | «other» (per-file лицензии репозиториев; наш фильтр — белый список разрешённых) | шард C, **доступ к bigcode не выдан** (см. §6) |
| `bigcode/the-stack-smol-xl` | «other» (per-file лицензии, поле `max_stars_repo_licenses`) | проверка пайплайна C на реальных данных Stack v1 |
| `codeparrot/codeparrot-clean` | «other» (per-file `license`; только python) | резервная проверка пайплайна C |

Приватные компоненты E/K/D/S (ADR-020) в претрейн не входят (AD-6).

## 4. Хеши и объёмы (ЗАПОЛНЯЕТСЯ ПОСЛЕ ПОЛНОЙ ЗАГРУЗКИ)

| Поле | Значение |
|---|---|
| `dataset_sha256` (сводный хеш состава) | — |
| W: шардов / байт / approx_tokens / записей | — |
| C: шардов / байт / approx_tokens / записей | — |
| W: sha256 шард-файлов | — (список из `manifest-w.json`) |
| C: sha256 шард-файлов | — (список из `manifest-c.json`) |
| `environment_version` (AD-4, `environment v1`) | — |

Сводный `dataset_sha256` считается как sha256 от канонического списка шардов
(`shard/token/файл/bytes/sha256` в лексикографическом порядке) — та же форма, что
в `evidence/a4-skeleton-run-manifest.json` (`dataset_sha256`).

Проверка перед стартом претрейна (воспроизводимо):

```bash
python -m prep_pretrain.build verify-manifest \
    --manifest ~/gb10-shared/datasets/axiom-pretrain-l3/W/manifest-w.json
python -m prep_pretrain.build verify-manifest \
    --manifest ~/gb10-shared/datasets/axiom-pretrain-l3/C/manifest-c.json
```

## 5. Числа пробы (фактический прогон 27.09.2026)

Проба — `build.py probe --limit-mb 200 --shard-mb 100 --max-minutes 25`, выход в
`/tmp/axiom-pretrain-probe/`, отчёт `probe-report.json`; **не** боевая загрузка.
Хеши пробных шардов сверены пересчётом с диска (`verify-manifest`: `bad: []`).

| Метрика | W | C |
|---|---|---|
| источник прогона | `HuggingFaceFW/fineweb-edu`, `sample-100BT` | `bigcode/the-stack-smol-xl` (публичный срез v1, 5 языков) |
| шардов / байт (сжатых) | 2 / 209 733 257 (200.0 МиБ) | 1 / 76 473 525 (72.9 МиБ) |
| approx_tokens / записей | 134 047 082 / 113 031 | 78 573 192 / 41 604 |
| прочитано из источника | 113 058 (дедуп отбросил 27) | 50 000 — **источник исчерпан** |
| время прогона, с | 489.4 | 267.9 |
| скорость: выход / текст источника | 0.409 / 1.046 МБ/с | 0.272 / 1.119 МБ/с |
| скорость по токенам | 273 899 ток/с | 293 279 ток/с |
| пик RSS / RSS в конце | 928.0 / 929.1 МиБ | 1063.5 / 1064.4 МиБ |
| стоп | `max_output_bytes` | `source_exhausted` |
| оценка полной загрузки | 17.2 ч на 17B | 2.84 ч на 3B — **недостижимо**: публичный источник даёт 0.079B |

Профиль RSS (сэмплы каждые 5k записей) — ступенчатый, с плато: W
452 → 545 → 634 → 704 → 764 → 800 → 866 → 922 МиБ (на 85–110k записей —
плато 922 МиБ), C 958 → 1063 МиБ. Рост объясняется буферизацией row-group
`pyarrow` и окном дедупа, а не накоплением документов: **пик не растёт монотонно
вместе с объёмом** (датасет-источник — 286 ГБ). Для боевого прогона (десятки
часов) профиль памяти стоит перепроверить на более длинном прогоне — 17 ч на канале
дают достаточно точек, чтобы увидеть утечку, но решение принимается по факту
первых часов.

**Разброс канала:** тот же прогон W, выполненный на полчаса раньше, дал
1.32 МБ/с на выходе и 886 967 ток/с (оценка 5.3 ч на 17B) — то есть оценка
длительности полной загрузки лежит в диапазоне **5.3–17.2 ч** и зависит от
канала, а не от кода. Наблюдались обрывы чтения паркета
(`The read operation timed out`) с автоповтором (до 5 попыток) — таймаут поднят
до 60 с (`HF_HUB_DOWNLOAD_TIMEOUT`), но полностью обрывы это не снимает.

Отбраковка на шарде C (реальные данные Stack v1, 50 000 записей):
`dropped_too_small` 4 829 (9.7 %), `dropped_license` 3 567 (7.1 %),
`truncated_oversized` 633 (1.3 %), `dropped_language` 0, `dropped_dedup` 0 —
прошло 83.2 %. По языкам: go 9 344, python 8 679, javascript 8 440, rust 7 972,
shell 7 169 (чередование потоков работает, все пять языков в шарде).

## 6. Решение по источнику кода: v2 или v1

**Статус: ЗАБЛОКИРОВАНО доступом; проверено на публичном срезе Stack v1.**

Замер (`build.py sources`, команда печатает состояние каждого источника и долю
записей, проходящих фильтры, — свидетельство, а не описание карточки датасета):

- `bigcode/the-stack-v2-dedup` — **gated:auto**, доступа у токена нет: итератор
  падает `DatasetNotFoundError: ... is a gated dataset on the Hub`. Конфиги по
  языкам ровно нужные (`Python`/`Rust`/`Go`/`JavaScript`/`Shell`) — стриминг по
  языку структурно осуществим, упирается только в доступ;
- `bigcode/the-stack-dedup` (v1) — **gated:auto**, то же самое; при этом v1
  удобнее для текстового пайплайна: контент и поля `content`/`lang`/`license`/
  `size` лежат прямо в строке;
- `bigcode/the-stack-smol-xl` — публичный срез Stack v1 по языкам, поля те же,
  что у v1 (`lang`, список лицензий `max_stars_repo_licenses`, `content`):
  на нём проверены фильтры языка/лицензии/длины (см. §5). Объёма (~0.6 ГБ на
  5 языков) на 3B токенов нет — только проверка и приёмка;
- `codeparrot/codeparrot-clean` — публичный, только python, поля языка в записи
  нет (одноязычный по построению): годен как резервная проверка;
- `common-pile/stackv2` — публичный Stack v2 с контентом, но поле языка —
  детектированный формат (`CSV`, `Futhark`, …), объявленных языков в потоке
  практически нет: для шарда C не годится (нулевой выход замерен).

Замер потолка публичного среза (см. §5): 50 000 записей на 5 языков (по 10 000
на язык) → 41 604 после фильтров → **0.079B токенов**. Это в ~38 раз меньше цели
3B — публичными источниками шард C не набирается.

**Следствие для боевого прогона:** нужен выданный доступ к
`bigcode/the-stack-dedup` (v1) либо `the-stack-v2-dedup` (v2). Пайплайн готов к
обоим: v1 — фолбэк по умолчанию (`--source stack-dedup-v1`), v2 —
`--source stack-v2-dedup`. Владельцу решения: запросить доступ к bigcode под
HF-токеном, которым пойдёт боевой прогон, и перепроверить `build.py sources`
(команда печатает, читается ли источник и сколько записей проходит фильтры).

## 7. Что не сделано и открытые вопросы

- шард Q (decay, ~1B) не собран — отдельная дельта;
- боевая загрузка 17B/3B не запускалась (по контракту задачи её запускает
  владелец отдельным процессом);
- токенизация и упаковка 8K — вне этого пайплайна (`net/data.py`);
- остаётся проверить свободное место на `gb10-shared` под ~80 ГБ загрузок
  (ADR-021, Consequences) — на момент пробы свободно 1.7 ТБ;
- вопрос к архитектору: допускается ли замена источника C на публичный
  одноязычный корпус (только python) или 5 языков обязательны; от этого зависит,
  можно ли закрыть C без доступа к bigcode.
