# A4-RUN.delta — прогонный путь A4 и честный манифест покрытия

- **Статус:** Proposed (реализуется дельтой; гейт остаётся красным до полного покрытия)
- **Решение:** `docs/adr/ADR-014-*.md` (Standard, 3 триггера) — манифест A4 несёт состав стадий конвейера
- **Связь:** спайн AD-4 (пиннинг), AD-10 (стражи предметны), AD-3 (единый контракт прогона); ADR-010 (пиннинг бэкенда и точности); NFR-002 (воспроизводимость); `tools/a4_manifest.py`; C-038
- **Правило имени:** манифест, покрывающий часть конвейера, **не** называется закрытием A4 — он несёт `pipeline_complete=false`

## 1. Что такое «прогон A4» механически

Прогон A4 — исполнение эталонного набора стадий на зафиксированных снапшотах, где каждая стадия
оставила машинно проверяемый след. Прогон без следа стадии — не прогон стадии. Манифест без прогона —
фабрикация доказательства (AD-4, сохраняется без ослаблений).

Прогон считается **полным** (`pipeline_complete=true`) тогда и только тогда, когда все стадии
эталонного набора имеют `status: executed` и непустой `evidence`.

## 2. Эталонный набор стадий `stage_set v1`

Соответствует определению A4 (README, гейты) и ADR-005 (пост-тренировка).

| Стадия | Что доказывает | Машинный след (`evidence`) | Состояние 13.09.2026 |
|---|---|---|---|
| `pretrain_checkpoint` | веса инициализированы с нуля (REQ-001), прошли ≥1 шаг, сохранены Orbax-чекпойнтом, хеш посчитан детерминированно | путь чекпойнта, `tree_hash` весов (`net/checkpoint.py`), число шагов | кода цикла обучения нет → `absent` |
| `spark_inference` | инференс исполнен **на стенде gb10** (DGX Spark), не на другой GPU | журнал инференса с `device_kind=gb10`/hostname стенда, версия JAX, число токенов | операторская; замер есть на RTX 4080 → `skipped` |
| `rl_environment` | среда v1 исполнила ≥N задач и выдала **механические** вердикты | Run Manifest среды (задачи, вердикты, хеши workspace), N≥10 | есть (`env/`, `net/tests/test_13_integration.py`) → может быть `executed` |
| `sft` | стадия SFT по ADR-005 п. 1 исполнена, чекпойнт SFT сохранён | путь чекпойнта SFT, лог лосса, хеш датасета SFT | **кода нет** → `absent` |
| `rl_base_scheme` | RL по схеме базы (ADR-005 п. 2: групповое преимущество, токен-уровневый клиппинг, без LLM-судьи в награде) исполнен, чекпойнт сохранён | путь чекпойнта RL, конфиг алгоритма, хеш среды и награды, стоп-правило | **кода нет** → `absent` |

`stage_set_version` расширяется только новой версией и ссылкой на решение (например, MOPD-консолидация,
ADR-005 п. 7 → `stage_set v2`). Молча дорисовывать стадии запрещено.

## 3. Схема манифеста `a4-skeleton-run-manifest/v2`

```json
{
  "schema": "a4-skeleton-run-manifest/v2",
  "stage_set_version": "v1",
  "model_weights_sha256": "<64 hex>",
  "dataset_sha256": "<64 hex>",
  "environment_version": "v1.1",
  "harness_version": "0.1.4",
  "git_commit": "<40 hex>",
  "run_date": "2026-09-13",
  "run_ref": "<путь/ссылка на журнал прогона>",
  "backend": {
    "platform": "cpu|cuda|rocm",
    "device_kind": "<строка устройства>",
    "jax_version": "<semver>",
    "matmul_precision": "<политика точности>"
  },
  "stages": [
    {"name": "pretrain_checkpoint", "status": "executed|skipped|absent", "evidence": ["<файл|команда|число>"]},
    {"name": "spark_inference",     "status": "executed|skipped|absent", "evidence": []},
    {"name": "rl_environment",      "status": "executed|skipped|absent", "evidence": []},
    {"name": "sft",                 "status": "executed|skipped|absent", "evidence": []},
    {"name": "rl_base_scheme",      "status": "executed|skipped|absent", "evidence": []}
  ],
  "pipeline_complete": false
}
```

Обязательные поля v1 сохраняются; добавляются `stage_set_version`, `backend`, `stages`, `pipeline_complete`.
Все пути в манифесте (`run_ref`, пути внутри `stages[].evidence`) — **относительные от корня репозитория**;
абсолютные пути запрещены (§4 правила 6–7, K11–K12).
`backend` вводится потому, что вердикт одного и того же коммита различается на CPU и GPU
(6e-08 против 3.37e-04 — `docs/research/attn-cost-and-matmul-precision-2026-09-12.md`): без пиннинга
бэкенда и политики точности доказательство A4 не интерпретируемо (ADR-010).

**Семантика статусов:** `executed` — стадия исполнена, `evidence` непуст; `skipped` — исполнитель
сознательно пропустил (например, стенд занят) с причиной в `evidence`; `absent` — стадия не реализована
в коде. `skipped` и `absent` **не** закрывают гейт.

## 4. Правила полноты и ретенции

1. `pipeline_complete` **вычисляется** генератором по `stages`; переданное извне значение игнорируется.
2. `--verify` возвращает ненулевой код, если: манифеста нет; схема не `v2`; состав стадий не совпадает
   с `stage_set_version`; хотя бы одна стадия не `executed` или имеет пустой `evidence`; `pipeline_complete != true`.
3. Сообщение об ошибке различает случаи: `манифест не найден` / `покрытие частично: <поимённый список>`
   / `схема v1 не поддерживается (ожидается v2)`. Красный гейт обязан читаться как план работ.
4. Запрет фабрикации: без `--weights-hash` / `--dataset-hash` / `--run-ref` генератор завершается
   ненулевым кодом и **ничего не пишет** (сохраняется из v1).
5. `run_ref` обязан указывать на **существующий и непустой** журнал прогона; иначе генерация отклоняется.
   Это второй барьер против «манифеста из ниоткуда» после хешей.
6. **Все пути в манифесте относительны.** `run_ref` и любые пути внутри `stages[].evidence` —
   относительные от корня репозитория (`git rev-parse --show-toplevel`; для кейса-подкаталога это,
   например, `кейсы/axiom/evidence/a4-run-wire/run-journal.json`). Абсолютные пути файловой
   системы в манифесте **запрещены**: они непортируемы (worktree флота удаляется после мержа — дефект,
   найденный на приёмке 13.09.2026) и выдают личные пути сборочной машины (гейт CI «personal paths»).
7. **Нормализация пути.** Абсолютный путь **внутри** репозитория генератор приводит к относительному;
   абсолютный путь **вне** репозитория — отказ (код 1, без записи). `--verify` отклоняет манифест
   с любым абсолютным путём, в том числе если файл вручную отредактирован после генерации.
8. Генерация атомарна (temp + `os.replace`, сохраняется из v1): частичных манифестов не остаётся.

## 5. Что входит в эту дельту (wire-прогон)

Даёт реальное продвижение без фабрикации и без реализации SFT/RL:

- **`tools/a4_manifest.py`** — схема v2: `stage_set_version`, `backend`, `stages`, вычисляемый
  `pipeline_complete`; усиленный `--verify` по правилам §4.
- **`tools/run_a4_pipeline.py`** (или `net/a4_run.py` — место выбирает исполнитель, интерфейс обязателен) —
  оркестратор доступных стадий:
  1. инициализация весов с нуля (seed-пиннинг) → ≥1 шаг → Orbax-чекпойнт → `tree_hash` → `pretrain_checkpoint`;
  2. **тот же** чекпойнт → детерминированный инференс (`net/infer.py`) → журнал;
  3. среда v1: ≥10 задач через `env/net_executor.py` → вердикты → Run Manifest среды → `rl_environment`;
  4. `spark_inference`, `sft`, `rl_base_scheme` — `absent`/`skipped` **с причиной**, без подмены стенда;
  5. сборка журнала прогона (`run_ref`) и вызов генератора манифеста.
- **Повторяемость:** повторный прогон с тем же seed даёт те же хеши весов и вердикты (репетиция A5).
- **Не входит:** цикл обучения, SFT, RL по схеме базы, прогон на Spark, оптимизация цены 8K (критерий 16),
  снятие `xfail` критерия 6. Каждое — отдельная дельта.

## 5.1 Контракт CLI генератора манифеста (`tools/a4_manifest.py`)

Обязателен для всех исполнителей: оркестратор вызывает генератор **по этому контракту**, а не по своему усмотрению.

```
python3 tools/a4_manifest.py \
  --weights-hash <sha256> --dataset-hash <sha256> --run-ref <путь> \
  [--stage <name>=<status>[:<evidence>]]... \
  [--output evidence/a4-skeleton-run-manifest.json] \
  [--environment-version V] [--harness-version V] [--git-commit H] [--run-date D]

python3 tools/a4_manifest.py --verify [--manifest PATH]
```

- `--stage` повторяемый: `name` ∈ `stage_set`; `status` ∈ `executed|skipped|absent`; `evidence` — строка,
  несколько следов разделяются `;`. Непереданные стадии получают статус `absent` (а не «пропущены молча»).
- Успех генерации: код 0, атомарная запись JSON схемы v2 (temp + `os.replace`).
- Отказ генерации: код 1, диагностика в stderr, **файл не создан и не изменён** — нет `--weights-hash` /
  `--dataset-hash` / `--run-ref`; `--run-ref` указывает на несуществующий или пустой путь; **`--run-ref`
  абсолютный и лежит вне репозитория** (внутри репозитория — нормализуется в относительный, §4 п. 7);
  неизвестное имя стадии или недопустимый статус.
- `pipeline_complete` вычисляется генератором; одноимённый вход игнорируется.
- `--verify`: код 0 только при схеме v2, полном составе стадий `stage_set_version`, всех стадиях `executed`
  с непустым `evidence` и `pipeline_complete=true`. Иначе код 1 и классифицированное сообщение:
  `манифест не найден` | `покрытие частично: <поимённый список>` | `схема v1 не поддерживается (ожидается v2)`.

## 5.2 Контракт CLI оркестратора (`tools/run_a4_pipeline.py`)

```
python3 tools/run_a4_pipeline.py --seed 0 --steps 1 --tasks 10 --out <каталог> [--manifest-out PATH]
```

- Пишет в `--out`: журнал прогона (`run_ref`), Orbax-чекпойнт, журнал инференса, вердикты среды.
  **Все пути, попадающие в манифест, — относительные от корня репозитория**; оркестратор не зависит
  от текущего рабочего каталога запуска (K12).
- Вызывает генератор из §5.1 (подпроцессом или импортом), передавая `--stage` по каждой стадии.
- Код 0 — доступные стадии исполнены, **независимо** от полноты конвейера (частичный прогон легален);
  ненулевой код — сбой исполненной стадии.
- В stdout печатает JSON-сводку: `{run_ref, model_weights_sha256, dataset_sha256, stages, pipeline_complete}`.

## 6. Критерии приёмки дельты (механические)

| № | Критерий | Проверка |
|---|---|---|
| K1 | Отсутствие манифеста → код 1, сообщение «манифест не найден» | `python3 tools/a4_manifest.py --verify` на чистом дереве |
| K2 | Генерация без `--weights-hash` / `--dataset-hash` / `--run-ref` → код 1, файл не создан | три запуска; `ls evidence/a4-skeleton-run-manifest.json` пусто |
| K3 | Частичное покрытие: манифест создан, `pipeline_complete=false`, `--verify` → код 1 с поимённым списком | wire-прогон оркестратора |
| K4 | Полное покрытие (фикстура всех 5 стадий `executed` с `evidence`) → `--verify` код 0 | фикстурный манифест в тесте |
| K5 | Подделка `pipeline_complete=true` при неполных стадиях → генератор пишет `false` | юнит-тест генератора |
| K6 | Манифест схемы v1 → `--verify` код 1, сообщение про ожидаемую v2 | фикстура v1 |
| K7 | `run_ref` на несуществующий журнал → код 1, манифест не создан | негативный тест |
| K8 | Детерминизм: два wire-прогона с одним seed дают одинаковые `model_weights_sha256` и вердикты среды | повторный запуск, сверка |
| K9 | Тесты `net/tests` не деградировали: без новых падений (существующий `xfail` критерия 6 сохраняется) | `python3 -m pytest net/tests -q` в `~/venv-axiom` |
| K10 | `fitness_check` по корневому `CONSTRAINTS.yaml` не даёт **новых** нарушений; красный по C-038 остаётся, его сообщение — про частичное покрытие, а не про отсутствие файла | `arch-ml control check . --constraints CONSTRAINTS.yaml` |
| K11 | Портируемость: манифест с абсолютным путём (в `run_ref` или в `stages[].evidence`) → `--verify` код 1 с сообщением «абсолютный путь запрещён: <поле>»; генерация с `--run-ref /абсолютный/путь/вне/репо` → код 1, файл не создан; генерация с абсолютным путём **внутри** репозитория → в манифесте относительный путь | негативные и позитивные фикстуры в tmp_path |
| K12 | Сквозная портируемость: wire-прогон из произвольного cwd → в манифесте нет ни одного абсолютного пути; `run_ref` резолвится от корня репозитория, существует и непуст; после `git clone` в другой каталог `--verify` даёт тот же вердикт (частичное покрытие), а не «журнал не найден» | прогон + `grep` по манифесту + резолв пути |

## 7. Что дальше (не в этой дельте)

1. `pretrain` — минимальный цикл обучения (шаг → лосс → чекпойнт) с бюджетом и стоп-правилом (AD-8).
2. `sft` — стадия SFT по ADR-005 п. 1 (датасеты с `~/gb10-shared`, симлинки по C-032/C-033).
3. `rl_base_scheme` — RL по схеме базы (ADR-005 п. 2), `backend_pin` обязателен.
4. `spark_inference` — операторский прогон на gb10; в манифест попадает только при реальном исполнении.
5. Только при всех пяти `executed` — C-038 зелёный, A4 закрыт, далее A5 (drift-прогон по манифесту).

## 8. Открытые вопросы

1. Место оркестратора: `tools/` (рядом с манифестом) или `net/` (рядом с сетью)? Решает исполнитель;
   важно, что интерфейс — CLI с `--seed`, `--steps`, `--tasks`, `--out`.
2. Порог N задач среды для `rl_environment` (предлагается N≥10 на уровне 1 лесенки сложности) —
   подтверждает владелец вместе с кальбровкой K3 (precondition RL, ENVIRONMENT-V1).
3. Нужен ли `pretrain_checkpoint` минимальный шаг обучения (≥1 optimizer step) или достаточно
   инициализации + сохранения? Предлагается ≥1 шаг: иначе стадия не доказывает обучаемость пути.
