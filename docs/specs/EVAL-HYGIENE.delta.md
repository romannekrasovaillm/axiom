# EVAL-HYGIENE.delta — гигиена eval-замеров конвейера (реализация ADR-023, уроки Лагуны §2)

- **Статус:** Proposed (реализуется дельтой; поведенческая часть — PENDING-EVIDENCE до сборки eval-наборов)
- **Основание:** ADR-023; `docs/research/LESSONS-LAGUNA-LADDER.ru.md` §2 (источники LAG-ADR-025/041/044/055/059)
- **Связь:** AD-12 / C-043 (чистота eval до вердикта), AD-11 (вердикт не зависит от окружения — включает режим декодирования), AD-2 (вердикт механический), C-032/C-033 (данные только симлинками)
- **Применяется к:** любому замеру, по которому выносится вердикт (holdout ppl, пробы генерации, SFT-пробы формата, RL-замеры holdout, сравнения кандидатов)

## 1. Предмет

Спека фиксирует три обязательных свойства eval-числа axiom: **чистота набора** (не утечка из обучающего источника), **воспроизводимость прибора** (единый режим декодирования, база тем же прибором), **различимость** (заявленная разница больше SE). Без соответствующего свойства число — справочное: вердикт не выносится.

## 2. Чистота eval-набора — гейт до использования числа (AD-12)

1. `eval_holdout.jsonl` и `eval_ood*.jsonl` до первого вердикта проходят `leak_check`: нулевое пересечение с каждым кандидатным миксом (tokens-v2 W/C/Q) и со всеми SFT/RL-наборами — проверка документами подстрокой + 12-граммовыми окнами; фильтр против **всего источника**, не против обученного префикса (прецедент Лагуны: `general_eval_v2` — 200/200 в обучающем источнике, «PPL ×0.99» — артефакт).
2. Результат пишется полем `leak_check` в карточку набора (методика, дата, число отброшенных записей, с чем сверялось). **Без поля `leak_check` число справочное — вердикт не выносится** (AD-12).
3. Инструмент: `tools/check_eval_leak.py`; гейт C-043 проверяет инструмент selftest-мутантами (красный на пересекающейся синтетике, зелёный на чистой). Поведенческий прогон по реальным наборам — при их сборке (PENDING-EVIDENCE в AD-12).

## 3. Единый штатный режим декодирования

1. Штатный режим проб генерации: **no-repeat-4gram + eos на конце хода**. Петли — свойство декодера, не модели: у Лагуны greedy давал 54 % петель, repetition-penalty 58 %, запрет повторов 4-грамм — 0.0 % (LAG-ADR-040).
2. Каждый отчёт несёт `protocol.decoding` (режим, бюджет, температура). Число без `protocol.decoding` — справочное.
3. База снимается **тем же прибором**; смена прибора/режима = пересъёмка базы. Сверка переснятого замера с замороженной legacy-цитатой — ложное красное (LAG-ADR-041/059): старые числа помечаются `legacy-not-checked`, а не «чинятся» и не сравниваются.

## 4. Различимость и честная отчётность

1. Рабочая точка: **n ≥ 100** задач на вердикт; один сид — только направление (`std: null, single_seed`).
2. Заявленная разница меньше SE — «неразличимо», а не победа (у Лагуны SE разности при m=192 ≈ 5.1 п.п.; «1 SE» давал 31.7 % ложных заявок, LAG-ADR-055).
3. pass@k не экстраполируется за пределы измеренного k.

## 5. Критерии приёмки дельты

1. `tools/check_eval_leak.py` существует; `--selftest` зелёный; C-043 зелёный на гейте.
2. Тесты дельты (`tools/tests/test_check_eval_leak.py`): мутант «пересечение подстрокой» красный; мутант «пересечение 12-граммовым окном» красный; чистая синтетика зелёная; `fail-closed` — нечитаемый вход даёт FAIL, не пропуск.
3. Спека не меняет критерии/пороги A4 — добавляет условия действительности чисел eval.

## 6. Запреты

- Не выносить вердикт по набору без `leak_check` в карточке (AD-12) — справочное число допустимо в анализе с пометкой.
- Не сравнивать числа разных приборов/режимов декодирования без пересъёмки базы.
- Не заменять механическую проверку пересечений «экспертной оценкой похожести».
