# MODEL-L3-SKELETON — спека сети с нуля (walking skeleton L3, JAX)

- **Статус:** Proposed → реализация (гейт A4)
- **Дата:** 2026-09-12 · **v1.1 — MoE**: решение владельца 12.09 — скелет строится как **MoE** (Stable LatentMoE-минимум), не dense. Закрывает gap FIDELITY §4: ось LatentMoE не была размечена в скелете; главная инновация базы обязана быть доказана за $200, а не за $44k.
- **v1.2 (12.09, после реализации 00ef575, решения архитектора):** Gated MLA — собственная реализация с reference-оракулом (MaxText не вендорился на скелете; кросс-чек при вендоринге на L1); оракул KDA — первично внутренняя согласованность (FLA gated_delta_rule — DeltaNet со скалярным decay, строгий паритет против него не валидирует KDA); MaxText на скелете — слой отображения, вендоринг — precondition L1.
- **v1.3 (12.09, после MoE-дельты 5583d5c):** ориентир активных параметров пересмотрен: **фактически ≈0,47B** (пол ≈0,30B задаёт замороженное внимание + dense-слой; 0,25–0,35B недостижим без ломки внимания) — принято: MoE-экономика сохраняется (2,1× к dense), смета держится. QB гистограммный (all-reduce) — подтверждён в L1-план.
- **v1.4 (12.09, после фикса регресса test_06, 8a83b85, решения архитектора):** (1) **QB-терм — мониторинговый со stop-gradient**: дифференцируемая версия эмпирически ломала needle-recall до 0.0; балансировку выполняет bias-обновление Eq. 14 (K3 auxiliary-free по построению), роутер учится только через NTP/MTP. (2) **Определение счётчика active_params_per_token согласовано**: backbone-вычисление на токен (внимание + dense-слой + top-2 routed + shared + нормировки), **без** tied-embedding (lookup), ViT (только image-токены) и MTP-головы (снимается на инференсе). Регресс также вскрыл узость tiny-фикстуры (expert 16/shared 32 — тестовая константа, §7).
- **Основания:** ADR-008 (стек JAX/MaxText), FIDELITY §1/§4 (рецепт и разметка скелета), извлечение техотчёта `docs/research/k3-tech-report-extract.md` (§1–5), ADR-004 (смета/стадийность), CMP-001/002.
- **Артефакт:** собственная сеть с нуля, ~1B MoE / 20B токенов / ≈$200 — доказательство конвейера до масштабных трат.

## 2. Компоненты (реализация по первоисточнику, оракулы для проверки)

1. **KDA** (18 слоёв) — Kimi Delta Attention: линейное внимание с пер-измеренным gated decay и delta-правилом. Формулы — **из PDF §2.1.1** (извлечение помечает их непрочитанными — первый шаг реализации: `pdftotext` §2.1.1 и фиксация формул в `net/kda-formulas.md` со ссылками на строки). Рекуррентная форма — JAX `lax.scan`; тренировочная — чанкированная (64K-контекст в curriculume).
   - **Оракул проверки: FLA** (`flash-linear-attention`, PyTorch) — паритет выходов на малых формах (fp32, CPU) в пределах 1e-4. Это сильнейший доступный тест: чужая отрепетированная реализация того же алгоритма.
2. **Gated MLA** (6 слоёв) — **v1.2, решение архитектора:** собственная реализация (сжатый латент + full-rank gate + NoPE) с reference-оракулом (согласованность до ~1e-9); MaxText-K2 кросс-чек — при вендоринге MaxText на L1. Функционально эквивалентна базе, отклонение — по реализации, не по архитектуре.
3. **Stable LatentMoE** (23 слоя) — эксперты в латентной проекции (latent 0,5×hidden), sparse top-k routing + shared expert, **QB-балансировка**. Формулы — из PDF §2.3 (извлечением не покрыт — читать первоисточник в Шаге 0); в MaxText есть стандартные MoE aux-losses — QB это наша реализация по статье. Router детерминирован (seed в манифесте прогона).
3. **AttnRes** (attention residuals) — PDF §2.2 (извлечением не покрыт): читать первоисточник; если семантика после чтения неоднозначна — пометить отклонение как «наше» (FIDELITY §3), не додумывать.
4. **SiTU-GLU** — активация из Table 1; семантика в §2 PDF. Если в отчёте не раскрывается — реализуем SiLU-GLU с пометкой «наше отклонение» в config.json (поле `deviations`).
5. **NoPE** — нигде нет позиционных эмбеддингов и RoPE; порядок несёт рекуррентность KDA. Порядок слоёв/гейтинг — по PDF.
6. **MTP** — 1 слой, вспомогательная потеря по DeepSeek-паттерну (в MaxText поддержка MTP есть с 07.2025 — взять оттуда).
7. **Vision** — ViT-S patch 14 → проекция в hidden, общий LM-лосс на interleaved image-text (native, без отдельной стадии выравнивания).

## 3. Оптимизатор и расписание

- **Muon, per-head вариант** + weight clipping (MuonClip-механика из K2; в MaxText Muon есть с 12.2025 — адаптация per-head — наша правка, помечается).
- cosine-LR, 1% линейный warmup, weight decay 0,1 (K3 :772–773).
- Куррикулум контекста: стадия 1 — 8K, стадия 2 — 64K; переход по доле токенов (20B общий бюджет; расщепление 90/10 — наше решение, помечается).
- **QAT со стадии SFT** (не претрейна): собственная fake-quant MXFP4-весов (straight-through) в JAX; активации MXFP8 — на полном масштабе, в скелете достаточно весовой ветки (FIDELITY §4).

## 4. Данные

- **Претрейн:** 20B токенов, таксономия базы — Web Text, Code, Mathematics, Knowledge + минимальный vision-корпус (captions/OCR-подмножество); публичные датасеты по ADR-004 (карточка + хеш на каждый).
- **SFT/RL:** датасеты владельца с `~/gb10-shared` (решение 12.09), подключение симлинками (C-032/C-033), карточка + хеш набора в манифесте прогона.
- **Токенизатор:** собственный BPE 160K, обучение на выборке претрейн-корпуса (детерминированно, seed-пиннинг), хеш в config.json.
- Длинные данные апсемплятся; длинно-контекстные задачи синтезируются склейкой/перестановкой (K3 :790–796) — механика на скелете в минимальном виде (64K-стадия).

## 5. Фазы реализации

**Фаза 1 — ядро сети (чистый JAX, без MaxText):** config.json + счётчик параметров; KDA (рекуррентная scan-форма + чанкированная), Gated MLA, SiTU-GLU MLP, NoPE, MTP-слой, ViT-минимум; сборка модели; паритет-тесты против оракулов; overfit-смоук; Orbax-чекпойнт.

**Фаза 2 — интеграция MaxText (форк):** перенос слоёв в MaxText-структуру, дата-пайплайн (шарды 4 доменов + vision, пакинг 8K/64K), per-head Muon, куррикулум 8K→64K, QAT fake-quant на SFT-стадии, претрейн-смоук на доступном GPU, полный прогон — отдельно по смете ADR-004 (8 GPU × 12 ч).
**v1.2, решение архитектора:** на стадии скелета MaxText — задокументированный слой отображения (`net/maxtext/README.md`), не вендореный репозиторий; вендоринг MaxText — precondition L1 (там нужны его инфраструктурные единицы: TP/PP/EP). Рецепт (per-head Muon, куррикулум, QAT) реализован нативно в JAX с документированным соответствием MaxText.

Код — только в `кейсы/axiom/net/`. Данные — симлинки на `~/gb10-shared`. Веса/чекпойнты — туда же (каноническое хранилище, C-032/C-033).

## 6. Критерии приёмки (механические, pytest в net/tests/)

1. Счётчик параметров в config.json ∈ [0,9, 1,2]B; словарь 160K; пропорция слоёв 18:6.
2. **KDA-паритет**: первичный оракул — внутренняя согласованность форм (recurrent↔chunked, порог ≤1e-4; фактически ~6e-8) + соответствие формулам первоисточника (`net/kda-formulas.md`). Кросс-чек против FLA — дополнительный, не блокирующий: `gated_delta_rule` во FLA — DeltaNet со скалярным decay, не KDA (per-channel + lower-bounded sigmoid), строгий паритет против него не валидирует KDA (решение архитектора, v1.2).
3. Gated MLA-паритет против реализации K2 в MaxText (тот же протокол).
4. Forward 8K-контекста на одном GPU без OOM; выходы конечны (нет NaN/Inf) на 100 случайных батчах.
5. Overfit-смоук: 1M токенов одного корпуса → loss монотонно ниже порога (значение порога фиксируется в тесте по базовому прогону).
6. **NoPE-экстраполяция**: модель, обученная на 8K, инференсится на 16K без рескейла — нет NaN, toy needle-recall не обваливается. Порог recall задаётся **относительно вырожденного предиктора** (доля самого частого ключа в eval-батче), а не абсолютным «≥50%»: при двух возможных ключах 50% — это ровно уровень угадывания, и константный предиктор проходил такой порог (замер 12.09). Статус на смоуке — **не достигнут** (12.09): модель вспоминает иголку на тренировочном гэпе (0.98–1.00 по сидам), но на экстраполированном сваливается в одну константу уже при gap=6, и больший бюджет не помогает (при 1200 шагах 0 из 3 сидов против 2 из 3 при 600). `net/tests/test_06` фиксирует это как `xfail(strict=True)`: провал виден в отчёте сьюта, а не замаскирован проходом. Механизм закрытия — ADR-009 (D1: SWA-ветка в каждом слое + D2: sparse-выбор в MLA-слоях, §9); критерий переходит в зелёный только по факту замера, ручное снятие mark запрещено.
7. Orbax save/load: побитовая идентичность весов после round-trip; хеш чекпойнта пишется в манифест.
8. QAT fake-quant MXFP4: round-trip ошибки весов в заявленном формате (квант-дебикализация), fine-tune-смоук с fake-quant — loss ↓; включается флагом, на претрейне выключен.
9. Токенизатор: round-trip на корпусе ≥99,5% (детенизация→токенизация идемпотентна), vocab ровно 160K, хеш зафиксирован.
10. Претрейн-смоук на GPU (если доступен): ≥ N ток/с (N фиксируется по факту железа в отчёте, не в тесте); тесты GPU скипаются с явной причиной при отсутствии железа.
11. **Routing детерминирован**: одинаковый вход+seed → идентичные назначения экспертов; счётчик активных параметров в config.json.
12. **Балансировка QB**: на равномерном батче после QB-тюнинга доля самого нагруженного эксперта ≤ 2× средней; QB-лосс монотонно убывает на смоук-прогоне.

## 9. Дельта v1.5 (ADR-009, ратифицирована владельцем 12.09) — SWA-ветка, sparse-выбор, FP4 латента

Основание: **ADR-009** (Status: Accepted 2026-09-12, гейт A3, объём утверждён владельцем). Факты первоисточника — `docs/research/v41-flash-report-extract.md` (PDF V4.1-Flash 2026-09-10). Отклонение от базы K3 оформлено по AD-5; в `config.json` каждая часть идёт отдельной строкой в `deviations`, а не правкой кода по месту (spine AD-9, страж C-034).

### 9.1 Что меняется в сети

**D1 — SWA-ветка в каждом слое.**
- `n_win = 128` — значение источника (§2.2); параметр конфига `swa_window`.
- **MLA-слои (6):** собственные K/V-проекции от своего hidden — как в источнике; выход окна и выход sparse-внимания объединяются, доля смешивания — обучаемый скаляр на слой.
- **KDA-слои (18):** окно строится на **уже вычисленных** q/k/v линейного слоя (`dk = dv = 128`, 12 голов) — 0 новых параметров. Это **наше решение**, источником не подтверждено (у V4.1 у SWA-ветки свои параметры) → отдельная строка в `deviations`. При провале A/B — выделенные проекции (+~28M ко всему счётчику, коридор 0,9–1,2B выдерживает).

**D2 — sparse-выбор в MLA-слоях (CSA2-lite).**
- Indexer: **1 голова, дом 128** (в источнике 32 голова × 128 при 64 Q-головах); indexer Q — от своего hidden, indexer K — **проекцией из main KV** (то есть из латента), как в CSA2 (§2.3); скор считается по записям main KV, отбирается `top_k`.
- `top_k = 512` — целевое значение источника; на скелете — параметр `mla_top_k`, фактически `min(512, T)`.
- Внимание — softmax по **объединению** выбранных записей и окна SWA (дубликаты снимаются маской), т.е. локальная точность не зависит от качества выбора.
- **Не импортируется:** компрессия последовательности `m > 1`, overlap-компрессор и absolute PE внутри компрессора, режимы Full/Reindex/Reuse, иерархический пул кандидатов (±16 384 позиции — бессмыслен при `m = 1` и шести слоях; см. ADR-009, Alternatives 5).
- Детерминизм: `indexer_seed` пиннится в манифесте прогона (spine AD-4).

**D3 — FP4 на латентном KV-кэше MLA.**
- Fake-quant латента `c_t` в **MXFP4**: E2M1 + **один E4M3 scale на 16 каналов**, без second-level global scale; **де-квант перед attention** — нативный FP4-matmul не требуется.
- **SWA KV остаётся FP8** (источник: чувствительность окна к квантованию, §2.4.4).
- Обоснование формата переносится буквально: латент 512 каналов, RMSNorm≈1 → L2-норма ≤ √512 ≈ 22,6, наблюдаемый максимум ≈10 ≪ 448×6 = 2688.
- RoPE в скелете нет (NoPE), поэтому оговорка источника «квантовать после RoPE» вырождается и конфликта не создаёт.
- Включается флагом `qat_kv_enabled`: на претрейне `false`, со стадии SFT — по общему плану QAT (§3).

**D4/D5 — оракул и train-aware.**
- Плотный путь внимания сохраняется как **оракул за флагом** `attn_dense_reference` до снятия гейта A4; A/B — на одном чекпойнте, в одной среде, при одном бюджете (spine AD-3).
- Тот же sparse-выбор и усечение окна **симулируются на всех стадиях**, включая пост-тренинг (источник §3.2.2, §5), иначе train/inference mismatch обесценивает замер.

### 9.3 Новые критерии приёмки (продолжение §6)

13. **Эквивалентность при неполном усечении:** при `mla_top_k ≥ T` и `swa_window = 0` выходы совпадают с плотным путём в пределах 1e-4 (fp32, CPU) — независимо от натренированных весов.
14. **Экстраполяционный recall:** критерий №6 переходит из `xfail` в зелёный. Снятие mark — только по факту выполнения; при частичном улучшении фиксируется измеренное (не хуже плотного пути на тренировочном гэпе, строго лучше на экстраполированном) и mark **остаётся**.
15. **FP4 латента:** дельта recall против FP8-бейзлайна ≤ 2 п.п. (порог NFR-004); при провале `qat_kv_enabled` откатывается, весовая ветка QAT сохраняется.
16. **Цена:** forward на 8K — не хуже 5% по времени/памяти против плотного пути; на 64K — строго лучше. Иначе — новый расчёт сметы (spine AD-8), прогон не стартует.
17. **Детерминизм indexer'а:** одинаковый вход + seed ⇒ идентичные top-k индексы (аналог критерия 11).

### 9.4 Границы и порядок реализации

- **Скелет не проверяет 1M** (куррикулум 8K → 64K); 1M остаётся критерием L1. Заявления о 1M на скелете запрещены (spine AD-9).
- **Плотная фаза перед sparse допускается** короткая и помечается как наше: источник учил sparse с нуля, но на 45T токенов и 552B, а переносимость вниз по масштабу не доказана (ADR-009, Consequences).
- Порядок работ (каждый шаг закрывается A/B против плотного оракула): (1) indexer + окно на MLA-слоях; (2) окно на KDA-слоях через шаринг проекций; (3) FP4 латента с QAT-смоуком.
- Отложено с условиями возврата (ADR-009, `deferred`): Engram-минимум, DSpark вместо MTP, Sinkhorn-balanced update.
