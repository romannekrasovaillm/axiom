# RL-STAGE.delta — стадия `rl_base_scheme` конвейера A4 (реализация ADR-005 п. 2)

- **Статус:** Proposed (реализуется дельтой; гейт A4 остаётся красным, пока `spark_inference` — skipped)
- **Основание:** ADR-005 (RL по схеме базы на детерминированной награде), ADR-014 (`stage_set v1`), ADR-002 (арена и механический вердикт), ADR-009 D5 (train-aware симуляция)
- **Связь:** AD-2 / C-039 (LLM-судья вне контура награды — форсируется стражем), AD-3 (единый контракт прогона), AD-4 (пиннинг), AD-8 / C-041 (смета), AD-11 (вердикт не зависит от окружения), C-032/C-033 (данные только симлинками); ADR-022 (2026-10-04: RL-стадия исполняется на самом arch-ml; рецепт — онлайн-синтез сред по FrogNano + практики Laguna)
- **Предшественник:** стадия `sft` (принята, коммит `6e4bef5`): чекпойнт, журнал стадии, признак `qat_weights`

## 1. Предмет

Стадия `rl_base_scheme` в манифесте A4 сейчас `absent` («кода RL по схеме базы нет»). Дельта добавляет **цикл RL** и машинный след стадии.

Ключевое ограничение контура: **награда — детерминированный сигнал среды**, не модель. Это уже форсируется поведенческим стражем C-039 (`AD-2`), который читает код среды и падает, если в пути награды появится LLM-клиент, судейский модуль или внешний API.

## 2. Состав стадии (ADR-005 п. 2, п. 6)

1. **Среда:** `env/` (v1): генерация задач (`env/generate.py`), исполнение и вердикт (`env/verifier.py`, `env/run.py`, `env/net_executor.py`), награда (`env/reward.py`) — берётся как есть; дельта её не переписывает.
2. **Схема базы:** обновление по схеме K2.5/K1.5 (log-ratio / mirror-descent класс, ADR-005 п. 2); плотный soft-score там, где бинарный гейт даёт разреженный сигнал (`cb31759`, ADR-005 п. 2).
3. **Этапность (ADR-005 п. 6):** SFT → **короткий RL** → замер на holdout → решение о продлении. Дельта реализует короткий RL и стоп-правило: продолжение без положительной дельты на holdout прекращается.
4. **QAT:** признак `qat_weights` наследуется из журнала SFT (ADR-005 п. 7, решение по вопросу 5 SFT-дельты).
5. **Микс задач (ADR-005 п. 4):** доля general-purpose задач фиксируется в журнале стадии (узкий RL не должен уничтожить общие способности).
6. **Сравнение (ADR-005 п. 5):** holdout фиксирован и не использован ни в SFT, ни в RL; замер — тем же харнессом, что и baseline (сравнительный стенд — отдельно, по AD-3).

## 3. Что реализуется

`tools/run_rl_smoke.py` — стадия RL в смоук-масштабе (доказательство провода, не обучение):

1. **Вход:** чекпойнт стадии SFT (симлинк на `~/gb10-shared/...`), `qat_weights` из её журнала, фиксированный сид, среда v1 в детерминированном режиме.
2. **Цикл:** N шагов (смоук ≤ 100): генерация задач среды → исполнение политикой → **механический вердикт** среды → награда (взвешенная по сложности, ADR-005 п. 2) → обновление по схеме базы. Без LLM-судьи (C-039 падает, если он появится в пути награды).
3. **Чекпойнт** после стадии (Orbax, `tree_hash`), **относительные пути** (ADR-014 п. 8).
4. **След стадии:** `evidence/a4-run-wire/rl/stage-journal.json`: `run_ref`, `status`, `steps`, `tasks_used`, `verdict_mix` (passed/failed), `reward_mean_first/last`, `holdout_before/after` (если holdout доступен), `qat_weights`, `seed`, `checkpoint`, `wall_clock_s`, `mix_share` (доля general-purpose).
5. **Смета:** печать фактических часов и сравнение с лимитом; смоук — без сметы, полный прогон — только со сметой (AD-8/C-041).

## 4. Критерии приёмки дельты

1. Тесты (`net/tests/test_21_rl_stage.py`): журнал валиден и без абсолютных путей; `qat_weights` наследуется из журнала SFT (и трактуется как `off` при отсутствии); стоп-правило срабатывает при отсутствии положительной дельты; симлинк чекпойнта проверяется (копия — отказ); повтор при том же сиде даёт тот же набор задач и ту же первую награду (детерминизм).
2. **C-039 остаётся зелёным** после дельты: награда считается из артефактов среды, судья вне контура — это проверяется не тестом дельты, а стражем.
3. Манифест A4: `rl_base_scheme` переходит `absent → executed`; `pipeline_complete` остаётся `false` из-за `spark_inference: skipped` (ADR-014 п. 5 — красный C-038 штатен).
4. Никаких копий весов/данных в репозитории (C-032/C-033 зелёные).

## 5. Запреты

- **Никакого LLM-судьи и внешних API в контуре награды** — инвариант AD-2, форсируется C-039; подмена награды моделью = откат дельты.
- Не переписывать среду v1 (`env/`) ради удобства RL; изменения среды — отдельное решение.
- Не называть смоук закрытием стадии: масштаб (шагов, задач, часов) указывается в журнале явно.
- Не трогать `pretrain_checkpoint`/`rl_environment`/`spark_inference` и файлы параллельного потока (`tools/run_a4_pipeline.py`, `tools/a4_manifest.py`, `.arch-fleet/*a4*`).

## 7. Находки первого смоука (13.09.2026, коммит `ee1a384`)

1. **Дефект сети (не дельты): NaN в backward на дополняющих нулях.** `net/kda.py:apply_chunked` дополняет последовательность нулями до кратности `chunk_size`; производная `l2_norm` на строго нулевом векторе даёт `0/0` → NaN, который доходит до KDA-параметров. Обнаружено при RL-роллаутах (журнал стадии, `findings[]`). Требуется отдельная дельта-фикс с регрессионным тестом (нулевой/патченный вход → конечный градиент).
2. **Precondition запуска RL: калибровка среды.** `ENVIRONMENT-V1 §10` требует калибровки K3 (pass-rate в диапазоне [10%, 90%]) до запуска RL. В смоуке награда вырождена (`verdict_mix: 0 passed / 4 failed`, `reward_mean 0.0`), поэтому сравнение «до/после» информативно только по норме параметров, а не по награде. Полный RL до калибровки не запускается — иначе награда не несёт сигнала, и стоп-правило ADR-005 п. 6 сработает ложно («учиться нечему» вместо «нечему учиться по этой награде»).
3. **Стоп-правило сработало честно:** holdout 0.0 → 0.0, дельта не положительна → `decision: stop`; смоук закрытием стадии не объявлен (`scope` в журнале).

4. **Преэкзистентный XLA-abort (не связан с фиксом NaN).** На tiny-конфиге компиляция падает с abort `GemmFusion` при `chunk ∈ {8, 9, 10, 11, 16, 32, 64}`; воспроизводится и на до-фиксовой формуле, поэтому KDA-тест использует `chunk ∈ {7, 13, 14}`, а в RL-смоуке стоит страховка `safe_chunk`. К фиксу NaN отношения не имеет, но это **отдельный дефект окружения/компиляции**, который может ограничивать размеры чанков в полном прогоне: до полного RL/претрейна нужен либо разбор (какая операция и почему не компилируется), либо явное объявление допустимого множества chunk-размеров в конфиге. `safe_chunk` до этого разбора не снимается.

## 8. Гейты здоровья и подготовка RL по урокам Лагуны (ADR-023; уроки §4)

Не подтверждено полным прогоном Лагуны (разведка стоимости + контракт среды) — первый полный RL axiom обязан перепроверить. Все пороги — от собственного smoke-замера на 1B, чужие коридоры не копируются (у Лагуны 91/100 шагов «выше коридора» 1.0–2.0 без коллапса, LAG-ADR-008/011).

### 8.1. Страж вырождения награды (`tools/check_rl_health.py`) — по первым 50 шагам

Все пороги применяются к **агрегатам окна** (среднее по окну ≤ 50 шагов), не к отдельному шагу: единичный шумный шаг не даёт стопа; шаблон для агрегатов — `pass_rate`, `reward_mean`, `zero_reward_share`, `entropy`, `clip_frac` (среднее окна), `no_group_variance` — «все adv = 0 на окне».

- **стоп**: `pass_rate=0 ∧ reward_mean ≤ 0.05`; или `zero_reward ≥ 90 %`; или `no_group_variance` (adv ≠ 0 отсутствуют на окне);
- **warn**: `template_collapse` (повтор 4-граммы ≥ 8); `clip_frac ≥ 0.2`;
- **стоп**: энтропия < 0.5 два шага подряд; **внимание**: энтропия < 1.0;
- действие — **остановка** (после ближайшего чекпойнта), не смена алгоритма на ходу;
- страж обязан иметь **мутантов**: краснеет на вырожденном ряде, зеленеет на здоровом (LAG-ADR-017);
- один страж на две точки замера: живая строка лога ≠ свод окна — «не оценён» ≠ «чисто»; исходы OK/FAIL/НЕ ПРОВЕРЕНО.

### 8.2. Полоса трудности — до RL и по каждому раунду синтеза

Precondition (ENVIRONMENT-V1 §10) дополняется: pass-rate базовой моделью замеряется по каждому раунду онлайн-синтеза (ADR-022); список «мёртвых типов» задач (pass-rate вне коридора [10 %, 90 %] на калибровочном чекпойнте) — отдельным файлом раунда; **пустая полоса — RL не запускается** (у Лагуны из 9162 задач пула ни одной в полосе 0.25–0.80 — RL был бы заранее обречён, LAG-ADR-049/061). Сравнение пулов — на одном чекпойнте.

### 8.3. Интерфейс замера = интерфейс обучения

RL-замер после SFT измеряет незнакомый API, а не способность, если SFT-набор без env-блока (LAG-ADR-061/062: pass_rate=0 — ноль измерения интерфейса, не умения) — precondition в SFT-STAGE.delta §8.5: блок формата `env/` v1, доля заземлённых примеров 15 % старт, траектории ≥ 2 действий ≥ 50 %, синтез по среде с проверкой по состоянию без судьи. Стадия RL фиксирует в журнале долю env-блока чекпойнта-источника; при отсутствии env-блока — замер честно помечает «интерфейс не заземлён», и нулевой pass_rate не трактуется как вырождение способности.

### 8.4. Смета RL — от собственного smoke

Доля генерации роллаутов ~71 % шага у Лагуны, разброс 41 % — от «болтливости» чекпойнта; заземление добавляет ×1.02–1.34 (LAG-ADR-010/011). Смета (AD-8/C-041) считается от собственного smoke-замера с запасом на хвост генерации; `RESYNC_EVERY` и `KL` — **явные поля манифеста** (у Лагуны манифест печатал дефолт 25 при факте 10 — расхождение поймано сверкой); KL 0.01 — нижняя граница, обнуление без strict on-policy запрещено; группа под бимодальный пул: 4 задачи × 2 роллаута с EMA-baseline по задаче.

## 9. Две методологии — ветки `laguna` и `frognano` (ADR-027; номер 025 в ранней редакции секции перенумерован из-за коллизии с ADR-025 «зоны сессий»)

RL-стадия исполняется **двумя именованными ветками** с одного SFT-чекпойнта, с равным бюджетом RL-шагов и одним скрытым holdout; вердикт сравнения — МакНемар (4 прогона mean pass@1, разница < 8 попаданий на n=100 = «неразличимы»). Сравнение методологического уровня: внутри пакета факторы коллинеарны (LAG-026), атрибуция факторов — отдельными абляциями позже.

### 9.1. Arm `laguna` (алгоритмически-селекционный пакет)

- алгоритм: **CISPO** — потокенный суррогат, клип IS-веса (1, 4), length-weighted LOO baseline;
- задачи: пул + отбор по коридору pass-rate [10 %, 90 %] калибровочным прогоном текущего чекпойнта, сэмплинг ∝ 1 − pass_rate, {0, 1} выбрасываются; **состав пула** — лесенка ENVIRONMENT-V1 §9 ({real, corruption} × {L0, L1, L2} × ≥5, ~30–60 задач) + откалиброванные real-кейсы владельца; малый объём пула — свойство методологии «отбор из существующего», фиксируется в карточке ветки (риск: группа задач узка против ~1500 сред соперника — вердикт учитывает это как фактор пакета);
- reward: формула среды v1 **+ префикс Лагуны** (parse-error −0,1; anti-give-up −0,1; таймаут 0,0).

### 9.2. Arm `frognano` (среда-синтезный пакет)

- алгоритм: **базовая схема ADR-005** (групповое преимущество, токен-уровневый log-ratio клип-маска, MuonClip, плотный soft-score);
- задачи: **онлайн-синтез раундами** ~300 × до 5 раундов, генератор — детерминированный мутатор `env/corruption.py` (AD-4), приёмка задачи — двусторонняя исполняемая валидация (fail-to-pass ∧ restore ∧ пустое решение падает), насыщение → следующий раунд;
- reward: формула среды v1 **без** префикса Лагуны; вердикт по финальному состоянию среды.

### 9.3. Общее (гигиена, вне сравнения)

substrate `env/` на arch-ml (TITO, AD-3); маскирование промпта/выводов инструментов в loss; LLM-судья запрещён (AD-2/C-039); QAT из журнала SFT; batch=1, контекст 8–32k; сид/пиннинг (AD-4/AD-11); health-гейты §8.1 (C-045), анти-hacking контур; смета (AD-8/C-041); holdout скрытый, ротируемый, с `leak_check` (AD-12/C-043) до вердикта.

### 9.4. Порядок и предусловия

1. Дельта исполнителя: `--arm laguna|frognano` — декларативные пакеты конфигурации раннера (после SFT-стадии).
2. Smoke обеих веток (масштаб в журналах; провод, не обучение).
3. Precondition'ы: env-блок в SFT (SFT-STAGE §8.5); калибровка K3 [10, 90] (ENVIRONMENT-V1 §10); непустая полоса трудности + мёртвые типы (§8.2); смета от smoke (§8.4).
4. Полные прогоны **последовательно** (одна GPU, AD-7) с одного чекпойнта; очерёдность — по готовности, на вердикт не влияет.
5. Вердикт → победитель = основная схема; элементы проигравшей ветки остаются флагами-абляциями (механика ADR-022 п. 3). Wall-clock веток фиксируется в карточках (синтез `frognano` в бюджет шагов не входит).
