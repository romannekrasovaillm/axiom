# SFT-STAGE.delta — стадия `sft` конвейера A4 (реализация ADR-005 п. 1)

- **Статус:** Proposed (реализуется дельтой; гейт A4 остаётся красным до полного покрытия stage_set v1)
- **Основание:** ADR-005 (пост-тренировка: SFT → RL по схеме базы → MOPD), ADR-014 (манифест A4 несёт состав стадий; `stage_set v1` = `pretrain_checkpoint`, `spark_inference`, `rl_environment`, `sft`, `rl_base_scheme`)
- **Связь:** AD-4 (пиннинг снапшотов), AD-8 / C-041 (смета до запуска), AD-11 (вердикт не зависит от окружения), C-032/C-033 (данные только симлинками), ADR-004 (карточка + хеш корпуса)
- **Не входит:** RL-стадия (`rl_base_scheme`) и MOPD — следующие дельты; `spark_inference` — операторская стадия на стенде GB10

## 1. Предмет

Сейчас стадия `sft` в манифесте A4 имеет статус **`absent`**: «кода SFT нет (ADR-005 п. 1 не реализован)». Инфраструктура под неё есть: `net/data.py` (`DatasetCard`, `shard_hash`, `symlink_shard`, `pack_sequence`), `net/tokenizer.py` (`BPETokenizer`, vocab 160K), `net/checkpoint.py` (Orbax round-trip, `tree_hash`), `net/optimizer.py`, `net/model.py`.

Дельта добавляет **цикл SFT-обучения** и машинный след стадии.

## 2. Данные (решение владельца 12.09, память контура)

- Источник: сетевой диск `~/gb10-shared/datasets/` — билдеры `build_sft_v*.py` и готовые наборы (`sft_train_v12.jsonl` 464 МБ, `sft_train_v10.1.jsonl`, `sft_train.jsonl`); holdout для замера — `eval_holdout.jsonl`, OOD — `eval_ood*.jsonl`.
- **Вход стадии (решение архитектора 05.10, уточнено вечером):** **микс** = `sft_train_v12-normalized.jsonl` (~85%) + **env-блок** (~15% старт, §8.5). Основание замера состава v12-normalized (05.10): 94.6% записей — concept-search домен (`search_concepts`), интерфейс среды RL (восстановление порчи, arch-ml CLI) — **0%**; без env-блока RL-замер измерит незнакомый API (LAG-061/062 дословно). Сборка микса — детерминированный скрипт с карточкой и журналом (`sft_mix_v1`, зона операций).
- **Порядок анти-LAG-061/062:** формат инструментов env-блока = интерфейс харнесса RL-раннера (схема действий, формат наблюдений) — **пиннится дельтой раннера ДО генерации блока**; генерация — reference-траектории по Damage-листу мутатора (восстановление известно конструктивно) с **реальными наблюдениями** исполнения (проверка состояниями; судья запрещён, AD-2). Сырой `v12` и голый `v12-normalized` входом стадии не являются.
- **В рабочем каталоге — только симлинки** (C-032/C-033), копий не держим; проверка `tools/check_*` это форсит.
- **Карточка датасета обязательна** (ADR-005 п. 1, ADR-004): имя набора, sha256 содержимого, лицензия каждого блока, источник траекторий (если блок траекторный), дата. Карточка пишется рядом с журналом стадии и попадает в `stages[].evidence`; карточка v12-normalized — `docs/datasets/sft-train-v12-normalized.ru.md`.

## 3. Что реализуется

`tools/run_sft_smoke.py` — стадия SFT (смоук-масштаб, доказательство провода, не обучение модели):

1. **Загрузка и проверка данных:** чтение выбранного jsonl потоково; карточка с `sha256` (потоковый хеш, не в память целиком); проверка, что путь — симлинк на сетевой диск (иначе отказ).
2. **Подготовка:** токенизация (`net/tokenizer.py`), упаковка в последовательности 8K (`net/data.py:pack_sequence`), детерминированный шаффл с пиннутым сидом (AD-11: сид и версия в журнале).
3. **Цикл обучения:** N шагов (по умолчанию — смоук, ≤ 200) на скелете L3, bf16, оптимизатор — существующий (`net/optimizer.py`); QAT: fake-quant MXFP4 весов **включается с SFT** (ADR-005 п. 7) флагом, по умолчанию в смоуке `on`.
4. **Чекпойнт:** Orbax-сохранение (`net/checkpoint.py`), `tree_hash` весов, число шагов, кривая лосса.
5. **След стадии:** `evidence/a4-run-wire/sft/stage-journal.json` (или каталог, заданный `--out`): `run_ref`, `status: executed`, `steps`, `loss_first/loss_last`, `dataset_card`, `checkpoint` (относительный путь + `tree_hash`), `tokenizer_hash`, `seed`, `qat_weights`, `wall_clock_s`. Пути **только относительные** от корня репозитория (ADR-014 п. 8).
6. **Стоимость:** печать фактических часов GPU и оценка против лимита сметы (AD-8/C-041) — без сметы стадия не запускается «на длинную дистанцию»; смоук явно помечается как смоук.

## 4. Критерии приёмки дельты

1. `pytest net/tests/test_20_sft_stage.py` (или аналог) — зелёный; тесты проверяют: отказ при пути-копии вместо симлинка; карточка содержит sha256 и лицензию; журнал стадии валиден и не содержит абсолютных путей; `tree_hash` чекпойнта совпадает после round-trip; сид пиннут и повторный запуск при том же сиде даёт тот же первый лосс (детерминизм).
2. Лосс **падает** на смоук-окне (не «обучение ради галочки»): фиксируется `loss_first > loss_last` с числами в журнале.
3. Симлинк, а не копия: `tools/check_*` (C-032/C-033) остаются зелёными после прогона.
4. `tools/a4_manifest.py` с новым следом: стадия `sft` переходит из `absent` в `executed`; `pipeline_complete` остаётся `false` (нет `rl_base_scheme` и `spark_inference`) — красный по C-038 штатен по ADR-014 п. 5.
5. Никаких абсолютных путей в артефактах; `--verify` не ругается на пути.

## 5. Запреты

- **Не подменять стадию:** смоук SFT не называется закрытием стадии «в полном объёме»; в журнале прямо указывается масштаб (шагов, токенов, часов).
- Не приносить данные копированием в рабочий каталог; не коммитить веса/датасеты.
- Не выдумывать датасет: если выбранный jsonl не читается или карточки нет — стадия остаётся `absent`, дельта не «зеленеет».
- Не менять пороги и методики критериев A4; не трогать стадии, реализованные параллельным потоком (`pretrain_checkpoint`, `rl_environment`).

## 6. Решения по открытым вопросам (архитектор, 13.09.2026)

1. **Смета и реестр прогонов (AD-8 / C-041).** Стадия получает собственный идентификатор прогона в реестре (`sft-smoke`, при полном прогоне — `sft-full`). Вскрыт **дефект контракта**: `run_ref` в манифесте содержит *путь* к журналу, а файл сметы называется по `run_ref` — сверка не сходится. Решение: `run_ref` — идентификатор прогона, пути к артефактам живут в отдельных полях; это уточнение контракта ADR-014 (дельта к генератору/оркестратору — зона параллельного потока). Красный C-041 по `a4-skeleton`/`a5-rerun` закрывается только сметами с утвердившим: **сметы полного прогона — артефакт владельца**, смоук их не требует (спека §3.6).
2. **Маскирование промпта.** Для **полного** SFT — да: обучение только на токенах ответа (стандарт SFT; иначе модель учится предсказывать и промпт). Для смоука не требуется (спека §3). Оформляется уточнением спеки при переходе к полному прогону.
3. **Чекпойнт CPU → GPU (шардинг Orbax).** Признано отдельной дельтой «переносимость чекпойнтов между топологиями»: нужна для цепочки `pretrain → SFT → RL` на арендованном GPU. Приоритет — после RL-стадии, до полного прогона на аренде.
4. **`run-journal.json` оркестратора против манифеста.** Канон — **след стадии** (`stage-journal.json`); оркестратор обязан эмитить статус стадии из следа, а не хранить свою копию. Файл принадлежит параллельному потоку — правка предлагается ему как дефект интеграции, в этой линии не трогается.
5. **Признак QAT в RL-стадию.** Да: `qat_weights` передаётся из журнала SFT в RL-стадию (ADR-005 п. 7 — QAT включается с SFT и продолжается); отсутствие поля в журнале SFT трактуется как `off`.

## 7. Открытые вопросы (решить при реализации)

- Какой именно набор брать по умолчанию: `sft_train_v12.jsonl` против `sft_train_v10.1.jsonl` — выбор по карточке (свежесть + состав), зафиксировать в журнале причину выбора. *(Решено архитектором 05.10: вход стадии — `sft_train_v12-normalized.jsonl`, см. §2; вопрос закрыт.)*
- Траекторный блок (ADR-005 п. 1: «сначала траектории собственного агентного харнесса») в смоуке: если такого набора нет — стадия честно помечает, что смоук покрыл только доменный блок.
- Нужно ли отдельное поле в журнале для `qat_weights` при переходе к RL-стадии (ADR-005 п. 7).

## 8. Гигиена данных и замеров стадии (пакет уроков Лагуны, 2026-10-05)

Перенесено из `docs/research/LESSONS-LAGUNA-LADDER.ru.md` §2–3 (LAG-ADR-025/033/035/036/037/040/042/043/045/050/055). Лагуна выбросила ~14 ч SFT на структурных дефектах набора и остановила стадию на 49% из-за неконтролируемой длины рассуждений — эти критерии входят в стадию **до** её запуска, а не постфактум.

### 8.1. Структурный аудит набора — гейт до стадии

- Аудитор (`tools/check_sft_structure.py`, дельта исполнителя) проверяет три класса дефектов на наборе **до** старта: незакрытые `<think>`, `<tool_call>` внутри `<think>`, записи без ответа; «незакрытый think» считается только среди естественно завершённых ходов (LAG-ADR-042/043: 16.86% / 11.24% / 10.67% у Лагуны → модель воспроизвела дословно).
- Лечение — **механическая нормализация новым файлом**: исходник не трогается, журнал нормализации обратим, неизменённые записи байт-в-байт. Правка на лету запрещена.
- Числа аудита — в карточку датасета (`dataset_card`, §3 п. 2).

### 8.2. Критерии стадии (дополняют §4)

1. `unfinished_tool_call ≤ 5%` на пробе n ≥ 100 (LAG-ADR-050: 0 на входе → 30.8% на SFT@21500; бюджет-независим; ломает агентную ось и RL-граундинг).
2. Контроль длины рассуждений — **в данных** (пределы think-спанов и нормирование на этапе сборки набора), не в бюджете инференса; `truncated_share` в evidence. При ≥ 20% усечённых прибор сатурирован — вердикт по формату не выносится; порог обрывов — отклонение от уровня претрейн-входа в сигмах (n=104 → 2σ ≈ 0.1; LAG-ADR-045: медиана хода 408 → 928 → 4096 = бюджет пробы, обрывы при 4096 и 8192 совпали).
3. Раздельные метрики «кириллица в think» и «кириллица в ответе» — иначе «думает по-английски, отвечает по-русски» неотличимо от полного сдвига (LAG-ADR-035/039: 0.047 → 0.834 переноса одной SFT); решение о лечении — только по ним, перегенерация учителем не планируется без раздельного замера.

### 8.3. Маскирование: промпт — да, think — только после замера цены

- §6.2 (маска промпта для полного прогона) остаётся в силе.
- **Think-маска внутри ответа не вводится без замера цены**: доля обучающего сигнала в think-спанах и доля целей `tool_call` внутри think (у Лагуны: 46.1% сигнала; наивная маска сняла бы до 70% целей tool_call — LAG-ADR-036/037). Спаны `<tool_call>` не маскируются **никогда**; маркеры `<think>`/`</think>` остаются в лоссе.

### 8.4. Дедуп — на этапе сборки, без «исторической сопоставимости»

- Дедупликация MinHash/20-gram + кап 4–5 эпох на чанк при сборке набора (у Лагуны 57.71% дублей = 7.09 фактических проходов, LAG-ADR-033).
- Поля `duplicates_share` и `effective_passes` — в карточке датасета в любом случае.

### 8.5. Блок env-интерфейса — обязателен (сильнейший урок для связки SFT→RL)

- SFT-набор обязан включать блок примеров в формате env/ v1 (вызов инструмента → наблюдение → ответ), иначе RL-замер после SFT измерит незнакомый интерфейс, а не способность (LAG-ADR-061/062: SFT-политика знала один инструмент, среда дала файлы/shell/HTTP → pass_rate = 0).
- **Порядок (архитектор 05.10, анти-LAG-061/062):** схема инструментов блока = **интерфейс харнесса RL-раннера** — пиннится дельтой раннера (`--arm laguna|frognano`, ADR-027) **до** генерации блока; генерация — reference-траектории по Damage-листу мутатора (восстановление известно конструктивно) с **реальными наблюдениями** исполнения (проверка по состоянию; судья запрещён). Замер доли env-формата в наборе — до запуска стадии; в `v12-normalized` он равен 0% (замер 05.10: 94.6% — concept-search), поэтому вход стадии — микс §2, а не голый normalized.
- Стартовая доля заземлённых примеров — **15%** (пересмотр одним шагом 5/15/30%); доля траекторий ≥ 2 действий — **≥ 50%**; LLM-судья в награде запрещён (AD-2/C-039, `tools/check_reward_isolation.py`).
- Cross-link: `docs/specs/RL-STAGE.delta.md` §8, §9.4.

### 8.6. Замер и декодирование

- Штатный режим проб: no-repeat-4gram + eos на конце хода (greedy — 54% петель, repetition-penalty — 58%, запрет 4-грамм — 0.0%, LAG-ADR-040); каждый отчёт несёт `protocol.decoding`; смена прибора = пересъёмка базы, старые числа — `legacy-not-checked`.
- База прибора снимается с чекпойнта-старта тем же прибором **до** старта стадии (§1.1 уроков); предмет замера бронируется по `docs/RUNBOOK-GB10.ru.md` §4 (hardlink/копия + sha256 с копии + `RECEIPT.json`).
- `leak_check` (страж `tools/check_eval_leak.py`) обязателен для `eval_holdout.jsonl`/`eval_ood*.jsonl` против tokens-v2 (W/C/Q) и всех SFT/RL-наборов **до** первого вердикта по ним; без поля `leak_check` число справочное, вердикт не выносится (LAG-ADR-025/044).
- n ≥ 100 на вердикт; один сид — только направление (`std: null, single_seed`); разница < SE — «неразличимо», не победа; pass@k не экстраполируется (LAG-ADR-055).

### 8.7. Учитель синтеза — по качеству подмен, не по скорости

- Выбор модели-учителя/синтезатора (доменные эпизоды, env-блок §8.5) — по выборочному чтению смысловых подмен (n ≥ 5 на кандидата), не по tok/s и не по языковым метрикам: у Лагуны 8B быстрее 27B в 5.5 раза, но 3 искажения смысла из 5 против 0/5 (LAG-ADR-038); страж терминологии ловит идентификаторы, не смыслы.
