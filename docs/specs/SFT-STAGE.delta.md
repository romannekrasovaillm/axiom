# SFT-STAGE.delta — стадия `sft` конвейера A4 (реализация ADR-005 п. 1)

- **Статус:** Proposed (реализуется дельтой; гейт A4 остаётся красным до полного покрытия stage_set v1)
- **Основание:** ADR-005 (пост-тренировка: SFT → RL по схеме базы → MOPD), ADR-014 (манифест A4 несёт состав стадий; `stage_set v1` = `pretrain_checkpoint`, `spark_inference`, `rl_environment`, `sft`, `rl_base_scheme`)
- **Связь:** AD-4 (пиннинг снапшотов), AD-8 / C-041 (смета до запуска), AD-11 (вердикт не зависит от окружения), C-032/C-033 (данные только симлинками), ADR-004 (карточка + хеш корпуса)
- **Не входит:** RL-стадия (`rl_base_scheme`) и MOPD — следующие дельты; `spark_inference` — операторская стадия на стенде GB10

## 1. Предмет

Сейчас стадия `sft` в манифесте A4 имеет статус **`absent`**: «кода SFT нет (ADR-005 п. 1 не реализован)». Инфраструктура под неё есть: `net/data.py` (`DatasetCard`, `shard_hash`, `symlink_shard`, `pack_sequence`), `net/tokenizer.py` (`BPETokenizer`, vocab 160K), `net/checkpoint.py` (Orbax round-trip, `tree_hash`), `net/optimizer.py`, `net/model.py`.

Дельта добавляет **цикл SFT-обучения** и машинный след стадии.

## 2. Данные (решение владельца 12.09, память контура)

- Источник: сетевой диск `~/gb10-shared/datasets/` — билдеры `build_sft_v*.py` и готовые наборы (`sft_train_v12.jsonl` 464 МБ, `sft_train_v10.1.jsonl`, `sft_train.jsonl`); holdout для замера — `eval_holdout.jsonl`, OOD — `eval_ood*.jsonl`.
- **В рабочем каталоге — только симлинки** (C-032/C-033), копий не держим; проверка `tools/check_*` это форсит.
- **Карточка датасета обязательна** (ADR-005 п. 1, ADR-004): имя набора, sha256 содержимого, лицензия каждого блока, источник траекторий (если блок траекторный), дата. Карточка пишется рядом с журналом стадии и попадает в `stages[].evidence`.

## 3. Что реализуется

`tools/run_sft_smoke.py` — стадия SFT (смоук-масштаб, доказательство провода, не обучение модели):

1. **Загрузка и проверка данных:** чтение выбранного jsonl потоково; карточка с `sha256` (потоковый хеш, не в память целиком); проверка, что путь — симлинк на сетевой диск (иначе отказ).
2. **Подготовка:** токенизация (`net/tokenizer.py`), упаковка в последовательности 8K (`net/data.py:pack_sequence`), детерминированный шаффл с пиннутым сидом (AD-11: сид и версия в журнале).
3. **Цикл обучения:** N шагов (по умолчанию — смоук, ≤ 200) на скелете L3, bf16, оптимизатор — существующий (`net/optimizer.py`); QAT: fake-quant MXFP4 весов **включается с SFT** (ADR-005 п. 7) флагом, по умолчанию в смоуке `on`.
4. **Чекпойнт:** Orbax-сохранение (`net/checkpoint.py`), `tree_hash` весов, число шагов, кривая лосса.
5. **След стадии:** `evidence/a4-run-wire/sft/stage-journal.json` (или каталог, заданный `--out`): `run_ref`, `status: executed`, `steps`, `loss_first/loss_last`, `dataset_card`, `checkpoint` (относительный путь + `tree_hash`), `tokenizer_hash`, `seed`, `qat_weights`, `wall_clock_s`. Пути **только относительные** от корня репозитория (ADR-014 п. 8).
6. **Стоимость:** печать фактических часов GPU и оценка против лимита сметы (AD-8/C-041) — без сметы стадия не запускается «на длинную дистанцию»; смоук явно помечается как смоук.

## 4. Критерии приёмки дельты

1. `pytest net/tests/test_20_sft_stage.py` (или аналог) — зелёный; тесты проверяют: отказ при пути-копии вместо симлинка; карточка содержит sha256 и лицензию; журнал стадии валиден и не содержит абсолютных путей; `tree_hash` чекпойнта совпадает после round-trip; сид пиннут и повторный запуск при том же сиде даёт тот же первый лосс (детерминизм).
2. Лосс **падает** на смоук-окне (не «обучение ради галочки»): фиксируется `loss_first > loss_last` с числами в журнале.
3. Симлинк, а не копия: `tools/check_*` (C-032/C-033) остаются зелёными после прогона.
4. `tools/a4_manifest.py` с новым следом: стадия `sft` переходит из `absent` в `executed`; `pipeline_complete` остаётся `false` (нет `rl_base_scheme` и `spark_inference`) — красный по C-038 штатен по ADR-014 п. 5.
5. Никаких абсолютных путей в артефактах; `--verify` не ругается на пути.

## 5. Запреты

- **Не подменять стадию:** смоук SFT не называется закрытием стадии «в полном объёме»; в журнале прямо указывается масштаб (шагов, токенов, часов).
- Не приносить данные копированием в рабочий каталог; не коммитить веса/датасеты.
- Не выдумывать датасет: если выбранный jsonl не читается или карточки нет — стадия остаётся `absent`, дельта не «зеленеет».
- Не менять пороги и методики критериев A4; не трогать стадии, реализованные параллельным потоком (`pretrain_checkpoint`, `rl_environment`).

## 6. Решения по открытым вопросам (архитектор, 13.09.2026)

1. **Смета и реестр прогонов (AD-8 / C-041).** Стадия получает собственный идентификатор прогона в реестре (`sft-smoke`, при полном прогоне — `sft-full`). Вскрыт **дефект контракта**: `run_ref` в манифесте содержит *путь* к журналу, а файл сметы называется по `run_ref` — сверка не сходится. Решение: `run_ref` — идентификатор прогона, пути к артефактам живут в отдельных полях; это уточнение контракта ADR-014 (дельта к генератору/оркестратору — зона параллельного потока). Красный C-041 по `a4-skeleton`/`a5-rerun` закрывается только сметами с утвердившим: **сметы полного прогона — артефакт владельца**, смоук их не требует (спека §3.6).
2. **Маскирование промпта.** Для **полного** SFT — да: обучение только на токенах ответа (стандарт SFT; иначе модель учится предсказывать и промпт). Для смоука не требуется (спека §3). Оформляется уточнением спеки при переходе к полному прогону.
3. **Чекпойнт CPU → GPU (шардинг Orbax).** Признано отдельной дельтой «переносимость чекпойнтов между топологиями»: нужна для цепочки `pretrain → SFT → RL` на арендованном GPU. Приоритет — после RL-стадии, до полного прогона на аренде.
4. **`run-journal.json` оркестратора против манифеста.** Канон — **след стадии** (`stage-journal.json`); оркестратор обязан эмитить статус стадии из следа, а не хранить свою копию. Файл принадлежит параллельному потоку — правка предлагается ему как дефект интеграции, в этой линии не трогается.
5. **Признак QAT в RL-стадию.** Да: `qat_weights` передаётся из журнала SFT в RL-стадию (ADR-005 п. 7 — QAT включается с SFT и продолжается); отсутствие поля в журнале SFT трактуется как `off`.

## 7. Открытые вопросы (решить при реализации)

- Какой именно набор брать по умолчанию: `sft_train_v12.jsonl` против `sft_train_v10.1.jsonl` — выбор по карточке (свежесть + состав), зафиксировать в журнале причину выбора.
- Траекторный блок (ADR-005 п. 1: «сначала траектории собственного агентного харнесса») в смоуке: если такого набора нет — стадия честно помечает, что смоук покрыл только доменный блок.
- Нужно ли отдельное поле в журнале для `qat_weights` при переходе к RL-стадии (ADR-005 п. 7).
