# VERIFICATION-LEG — проверка конвейера на dense-модели против известных кривых (GPT-2 124M-класс)

- Date: 2026-10-05
- Status: Accepted (архитектор; решение владельца «отделить баги от архитектуры»)
- Route: Fast (прибор + прогон)

## Цель

Отделить **баги конвейера** (данные, пакинг, токенизация, оптимизация, resume, QAT-контур) от **цены архитектуры** (KDA/MLA/SWA-слои L3-скелета): тот же претрейн-конвейер на **dense-конфигурации GPT-2-класса** и известном корпусе должен воспроизводить известные кривые. Расхождение в dense-режиме = баги конвейера; согласованность dense при отставании арх-конфигурации = измеренная цена архитектуры.

## Конфигурация dense-reference

- GPT-2-класс **по ширине**: 12 слоёв × 12 голов × d_model 768; параметр-каунт НЕ равен 124M — словарь 160k и машинерия скелета дают ~354M (фиксируется отчётом); сравнение по **BPB**, от параметр-каунта не зависит.
- **Dense-only сборка (решение архитектора 06.10 по эскалации E-4):** `attn_dense_reference` заменяет только внимание (оракул dense-apply), но KDA-слои остаются delta-rule рекуррентными, MLA — gated, каналы — LatentMoE. Для чистого теста конвейера добавлен **диагностический слой-тип `dense-standard`** (стандартный QKV-attention + MLP, через существующий dense-оракул внимания) в `net/model.py` — диагностический компонент, боевой путь (композиция 18 KDA + 6 MLA) не меняется. Конфиг `net/config-dense124m.json` — layer_composition dense-standard.
- Токенизатор — канонический tokens-v2 (vocab 160k, пин `net/config.json`), embeddings tied.
- Данные: FineWeb (W-источник, тот же пайплайн пакинга pretreйна, токенизатор v2), нога **~1B токенов** (сокращённый протокол: 2–4 ч GPU на GB10).

## Раннер

- Контракт раннера расширен: `tools/pretrain_run.py --config-path <path>` (переопределение пути конфига; пресеты small/tiny/l3-full остаются; дефолт — прежнее поведение). Решение архитектора по эскалации E-4 (вариант (а)); подмена `net/config.json` запрещена (пин скелета).

## Метрика и эталон

- **BPB (bits per byte)** — токенизатор-независимая метрика: `BPB = loss_nats_per_token × (tokens / bytes) / ln(2)`. Позволяет сравнивать кривые разных токенизаторов/словарей на том же тексте.
- Эталоны (репликации GPT-2 124M, проверены по первоисточникам 05.10):
  - llm.c (karpathy), GPT-2 124M на FineWeb: **val loss ≈ 3.28** на полном ~10B-токен прогоне;
  - nanoGPT (karpathy), GPT-2 124M на OpenWebText: **val loss ≈ 2.85**.
- **Пара сравнения (решение архитектора 06.10 по эскалации E-4): эталон llm.c — полный 10B-прогон, наша нога — 1B; ранняя точка законно отстаёт. Вердикт конвейера строится на**: (i) **внутреннем A/B** — arch-124M (12L, KDA/MLA-композиция) vs dense-124M (12L, dense-standard) при равном бюджете токенов: разница кривых = измеренная цена архитектуры при равной ширине; (ii) наклоне BPB-кривой на участке 0.5–1B против эталонной формы (если точка llm.c на ~1B доступна — абсолютная свертка, иначе наклон). Абсолютная точка 10B-эталона — ориентир порядка, не вердиктный порог.

## Критерии вердикта

1. **A/B (главный)**: dense-124M кривая согласована с формой эталонной GPT-2-кривой (наклон в пределах разумного разброса репликаций) → конвейер здоров (данные/оптимизация/токенизация/резюм работают); артефакт: BPB-разница dense vs arch-124M = цена архитектуры при равной ширине.
2. Отклонение dense-кривой от эталонной формы >15% → разбор по слоям конвейера в порядке дешевизны проверки: (а) пакинг/токенизация (BPB-профиль токенизатора на эталонном тексте), (б) оптимизация (LR-скедул, клипы, инициализация), (в) данные (dedup, mix). Архитектура в этом вердикте не участвует (dense).
3. Атомарный артефакт: dense-BPB-кривая + arch-124M-BPB-кривая → таблица цены архитектуры (отдельная нога, тот же бюджет).
