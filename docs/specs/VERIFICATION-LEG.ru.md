# VERIFICATION-LEG — проверка конвейера на dense-модели против известных кривых (GPT-2 124M-класс)

- Date: 2026-10-05
- Status: Accepted (архитектор; решение владельца «отделить баги от архитектуры»)
- Route: Fast (прибор + прогон)

## Цель

Отделить **баги конвейера** (данные, пакинг, токенизация, оптимизация, resume, QAT-контур) от **цены архитектуры** (KDA/MLA/SWA-слои L3-скелета): тот же претрейн-конвейер на **dense-конфигурации GPT-2-класса** и известном корпусе должен воспроизводить известные кривые. Расхождение в dense-режиме = баги конвейера; согласованность dense при отставании арх-конфигурации = измеренная цена архитектуры.

## Конфигурация dense-reference

- GPT-2-класс: 12 слоёв × 12 голов × d_model 768; **без KDA/MLA/SWA** (`layer_composition` dense через существующий режим `attn_dense_reference`; если net не поддерживает чистый dense — эскалация в TASK исполнителя, не самодеятельный код net/).
- Токенизатор — канонический tokens-v2 (vocab 160k, пин `net/config.json`), embeddings tied.
- Фактический параметр-каунт фиксируется в отчёте (с vocab 160k будет >124M классического GPT-2 — это ожидаемо; сравнение по **BPB**, не по абсолютному числу параметров).
- Данные: FineWeb (W-источник, тот же пайплайн пакинга pretreйна, токенизатор v2), нога **~1B токенов** (сокращённый протокол: 2–4 ч GPU на GB10).

## Метрика и эталон

- **BPB (bits per byte)** — токенизатор-независимая метрика: `BPB = loss_nats_per_token × (tokens / bytes) / ln(2)`. Позволяет сравнивать кривые разных токенизаторов/словарей на том же тексте.
- Эталоны (репликации GPT-2 124M, проверены по первоисточникам 05.10):
  - llm.c (karpathy), GPT-2 124M на FineWeb: **val loss ≈ 3.28** на полном ~10B-токен прогоне;
  - nanoGPT (karpathy), GPT-2 124M на OpenWebText: **val loss ≈ 2.85**;
  - форма раннего участка кривой — из логов репликаций (точки ~0.5–1B токенов), для оверлея.
- Сравнение: оверлей BPB-кривых (наша dense vs эталонная), на равном объёме токенов корпуса FineWeb.

## Критерии вердикта

1. **|BPB_наша − BPB_эталон| ≤ 10%** после 1B токенов → конвейер здоров (данные/оптимизация/токенизация/резюм работают), leg PASS.
2. Отклонение >10% → разбор по слоям конвейера в порядке дешевизны проверки: (а) пакинг/токенизация (BPB-профиль токенизатора на эталонном тексте), (б) оптимизация (LR-скедул, клипы, инициализация), (в) данные (dedup, mix). Архитектура в этом вердикте не участвует (dense).
3. Отдельный артефакт: dense-BPB-кривая становится базой для последующего сравнения «архитектурная конфигурация vs dense при равном compute» — вклад архитектуры меряем отдельной ногой, не здесь.

## Исполнение

- Прогон — GB10 (единственная GPU-нагрузка, лок-протокол AD-7/C-040), конфиг dense, runner претрейна без изменений.
- Отчёт: `evidence/verification-leg-dense124m/` — конфиг, кривая (jsonl + png), BPB-таблица, вердикт, sha256 чекпойнта/данных.
- Пиннинг: манифест данных (какие шарды), манифест конфига, BPB-конверсионные коэффициенты (tokens/bytes на holdout).
