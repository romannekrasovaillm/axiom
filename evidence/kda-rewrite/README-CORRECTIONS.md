# Поправки к ранее опубликованным замерам (evidence)

## 09.10.2026 — «kda_chunk 64→256 пуст» измеряло НЕ тот параметр

**Что было заявлено** (коммит e713c28, «два параметрических рычага пусты»): ширина чанка KDA 64→256 не даёт эффекта (−0.3%).

**Что неверно.** Рычаг менял `kda_wyut_chunk` в конфиге. По коду `net/kda.py:687-704` диспетчер использует `chunk_size` **вызывающего** (`chunk_size or cfg.kda_wyut_chunk`), а вызывающий — `net/model.py:forward(chunk_size=...)` — получает его из CLI-флага `--chunk-size` (`tools/pretrain_run.py:1276`, дефолт 64). То есть при `chunk_size=64` от вызывающего `kda_wyut_chunk` не читается вовсе, и прогон шёл с C=64 и в «изменённой» клетке.

**Следствие:** ширина чанка `chunked_cc` **не проверена**. Настоящий рычаг — `--chunk-size` (влияет на обе формы; для `chunked` 64 — запинненный эталон).

**Что делать:** замер `--chunk-size` ∈ {64, 128, 256} на `chunked_cc` с прочими равными; ожидание — компромисс между ростом внутричанкового `C×C`-слагаемого и падением числа итераций цикла чанков (хостовой оверхед).
