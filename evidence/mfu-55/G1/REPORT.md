## 3. Диагноз: гипотеза G1 опровергнута измерением

Замена `jnp.linalg.inv` → `jax.lax.linalg.triangular_solve` **убрала LU-факторизацию** (`getrf_panel`, `LuPivotsToPermutation` исчезли — это подтверждает, что правка сделана верно), **но не убрала мелкоядерность**: XLA исполняет батчевое треугольное решение **как 115 200 отдельных TRSM-ядер** (`batch_trsm_left_kernel<...,64,4,...>` — блок 64×4, то есть `nrhs` дробится мелкими порциями) плюс **230 400 служебных `MakeBatchPointers`** (по 2 на каждый TRSM) и удвоенные DtoD-копии.

Ответ на вопрос исполнителя («батчирует ли XLA TRSM на (H=12, C=64, ·) в одно крупное ядро?»): **нет, дробит**. Математически эквивалентная замена сдвинула класс работы с `getrf/getri` на `trsm` + указательные обвязки, сохранив масштаб запусков (≈115 тыс.) и уронив занятость.

**Итог гейта G1:** **НЕ достигнут** (нужно MFU ≥3% = 977 ток/с; получено 1.17%). Работа не напрасна: она исключила один класс гипотез и дала точный следующий адрес.

## 4. Следующие шаги (по убыванию ожидаемого эффекта)

1. **Слить решения `w` и `u` в один TRSM** (общая матрица `(I+L)`, разные правые части → `concat` по последней оси): вдвое меньше вызовов при том же объёме; проверить, увеличивает ли это `nrhs` в ядре (сейчас дробление до 4).
2. **Крупный `nrhs`**: сделать так, чтобы TRSM вызывался с правой частью `(H·C, dk+dv)` целиком, а не по срезам; критерий — падение числа TRSM-ядер на порядок при том же объёме.
3. **Убрать `MakeBatchPointers`-обвязку** (230 400 запусков): она — следствие batched-вызова; либо единый вызов, либо собственная подстановка.
4. **Своя прямая подстановка** (`lax.scan` по строкам чанка, C=64): C шагов скана с векторными операциями — предсказуемо одно ядро на скан вместо тысяч; проверять после (1)–(3).
5. Только затем — кастомный Pallas-кернел (методика `pallas-gb10-kernel`: «керенл оправдан, если XLA не фьюзит»).

**Ограничение метода (честно):** замеры на ПК-конфигурации CE-чанка (дефолт) vs базовой клетки `mfu-remat-none`; для чистоты следующего сравнения фиксировать одинаковые `--ce-chunk-tokens` и remat-политику в обеих ногах.
