# Цикл-21 кампании MFU-55 — тонкая провенанс-карта (подготовка G2)

- Дата: 18.10.2026, стенд GB10, JAX 0.11.2, nsys node-level.
- Основание: ADR-054 Am.33 (G2: SIMT < 5 %, MFU ≥ 10 % = 3 258 ток/с).
- Код меток: ветка `arch/theseus-20261018150713` (`e97d986`; харнесс theseus,
  в main НЕ влита — owner-gate). Тонкие метки: `probe_forward`, `probe_ntp_ce`,
  `probe_mtp`, `probe_opt`; внешний `probe_ce` убран (он захватывал backward
  через `transpose(jvp(probe_ce))`).
- Клетка: B=4 persist-on, `AXIOM_MTP_KDA_IMPL=campaign`, `AXIOM_TRACE_MARKERS=1`,
  2 шага, HLO-дамп + nsys node-level. Стационар: **1 113.7 ток/с, 29.422 с, nan 0**
  (метки не замедлили шаг — граф тот же по числу операций).
- Тесты меток: `test_45` 30 passed; регресс `test_46`+`test_02` 22 passed/1 skip.

**Ключевые факты.**
- **CE/lm_head — не проблема:** 0.65 с (2.2 %). Гипотеза «хвост = CE-голова» снята.
- **MoE — крупнейший именованный компонент:** 4.13 с forward (14 %); его backward —
  внутри неотнесённых 15.22 с (там же библиотечные `cutlass simt` 4.87 с и
  `magma` 1.03 с — fp32 SIMT-класс, цель критерия G2).
- **Оптимизатор:** 1.91 с, но **17 889 ядер** (0.1 мс/ядро) — модель запусков, а не
  арифметики; кандидат на фьюзинг/группировку.
- **MTP после цикла-20:** 2.32 с (KDA уже персистентный; остались W_f/MLP/голова).
- **Персистентные MLA+KDA:** 5.2 с GPU (`_body_mosaic` 3.69 + `batched_body_mosaic` 1.51).

## 2. Что это значит для G2

G2 = 11.7 с/шага (10 % MFU) против текущих 29.5 с — разрыв **2.54×**. Одного адреса
не хватает; карта даёт порядок:
1. **MoE** (4.13 с forward + его backward-доля в 15.2 с) — группированный/персистентный
   expert-кернел (класс DeepGEMM/MegaMoE): цель −2…−4 с и SIMT-класс вниз;
2. **fp32 SIMT/batched GEMM** (cutlass 4.87 с + magma 1.03 с = 5.9 с, 20 % шага) —
   перевод на bf16/тензорные ядра там, где паритет позволяет (критерий `SIMT < 5 %`);
3. **оптимизатор** (1.91 с, 17.9k ядер) — фьюзинг NS/AdamW;
4. **MTP-остаток** (2.32 с) — фьюзинг W_f/MLP;
5. персистентные MLA/KDA (5.2 с) — полировка после 1–4.

## 3. Ограничение карты

Backward (51.5 %) не атрибутирован по компонентам: имена `probe_*` не переживают
`transpose(jvp(...))` для внутренних границ. Для точного разложения backward нужна
следующая дельта меток — на **backward-правилах** (`kernel_bwd`/`reference_bwd_scan`,
MoE-backward, CE-grad) или метка на уровне `jax.custom_vjp`-правил. Без неё выбор
между MoE и SIMT-классом опирается на forward-карту и классы ядер (что уже даёт
измеримый адрес).
