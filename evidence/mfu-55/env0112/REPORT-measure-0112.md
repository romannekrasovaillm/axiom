# Перемер кампании на JAX 0.11.2 (10.10.2026)

**Условия (сопоставимы с потолком 0.10.2 — правило сопоставимости ADR-050 Am.2):** 6 шагов, l3-full@8192, B=1, `--ce-chunk-tokens 4096`, remat `none`, `XLA_PYTHON_CLIENT_MEM_FRACTION=0.9`, `TF_GPU_ALLOCATOR=cuda_malloc_async`, `PREALLOCATE=false`, `AXIOM_KDA_SOLVE=jax` (базовый путь, без Mosaic). Окружение: `<HOME>/venv-axiom-0112` (jax/jaxlib 0.11.2, jax-cuda13-plugin 0.11.2). Требуемые сверх jax зависимости раннера: `pytest`, `orbax-checkpoint` (доустановлены).

## Результат

| Метрика | JAX 0.10.2 (потолок кампании) | **JAX 0.11.2** | Δ |
|---|---|---|---|
| tok/s | 377.1 | **410.7** | **+8.9%** |
| шаг, с | 21.72 | **19.93** | −8% |
| **MFU** | 1.16% | **1.26%** | +0.10 п.п. |
| loss (6 шагов) | 13.542 → 12.074 | 13.542 → 12.066 | паритет |
| power.draw (на шагах) | 42–56 Вт | **~90 Вт** | нагрузка иная |

**Это первый измеренный рост MFU за кампанию** — и он получен сменой линии JAX, без изменения кода кейса.

## Что это значит

1. Смена версии JAX дала **+8.9% ток/с** «бесплатно» (тот же конфиг, тот же код). Само по себе этого мало для G1 (нужно 977 ток/с = +137%), но это подтверждает: **барьер частично лежит в стеке**, а не только в архитектуре шага.
2. Мощность выросла вдвое (42–56 → 90 Вт) при том же времени шага — косвенно указывает на иную структуру исполнения (меньше простоев/иная диспетчеризация).
3. Структурный вопрос (число `cuGraphLaunch`, ядра, занятость) снимается nsys-прогоном в этом же окружении — результат будет ниже.

## Что НЕ сделано

- Паритет прочих режимов (bt16-гейт, remat `dots`, `--chunk-size 256`) на 0.11.2 не проверялся — только базовая клетка.
- Mosaic-путь (см. `evidence/mfu-55/mosaic/`) в этом замере **не участвовал** (`AXIOM_KDA_SOLVE=jax`).
