# Свип ширины чанка KDA (`--chunk-size`) — 09.10.2026

**Клетка:** l3-full, T=8192, B=1, `kda_impl=chunked_cc`, `remat_policy=dots_with_no_batch_dims_saveable`,
`AXIOM_COMPUTE_DTYPE=bf16`, 12 шагов, `--phase-profile`, XLA-лимит 0.6, поток W, стенд GB10.

| `--chunk-size` | Шаг, с | Ток/с | TFLOPS |
|---|---|---|---|
| 64 (прежний дефолт CLI) | 16.7 | 490.2 | 1.478 |
| **128** | **15.7** | **522.1** | **1.574** |
| 256 | 17.2 | 476.2 | 1.435 |

**Вывод:** зависимость немонотонна — c ростом C растёт внутричанковое `C×C`-слагаемое и падает
число итераций цикла чанков (хостовой оверхед). Оптимум на измеренном множестве — **C=128 (+6.5% к 64)**;
C=256 уже хуже прежнего дефолта (−2.8%).

**Контекст поправки.** Прежний вывод «ширина чанка не влияет» (коммит e713c28) измерял `kda_wyut_chunk`,
который при заданном `chunk_size` не читается (`net/kda.py:687-704`); см.
`../README-CORRECTIONS.md`. Настоящий рычаг — `--chunk-size` (`tools/pretrain_run.py:1276`).

**Подтверждение:** прогон `cf-*` (порядок 128 → 64 → 128, чтобы исключить прогрев кэша) — см. каталог
`confirm/` (при наличии).

**Откат:** параметр CLI, кода не меняет; значения 64/128/256 дают воспроизводимые графики
(тесты паритета формы передают `chunk_size` явно и от дефолта CLI не зависят).
