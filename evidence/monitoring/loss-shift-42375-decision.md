# Решение по сдвигу loss на шаге ≈42 375 (прогон long-jax2-ab14050)

- Дата решения: 2026-11-14
- Владелец: владелец прогона (согласовано: «три шага, без вмешательства сейчас»)
- Статус: Accepted, действует до шага 46 500
- Связано: ADR-060 (детектор changepoint), реестр `evidence/monitoring/changepoints.yaml`,
  правило C-059

## Что произошло (факты на 14.11 06:40Z, шаг 43 377)

| показатель | значение |
|---|---|
| точка сдвига | шаг ≈42 375, детектор дал 42 488 (Δ=+0,205, z=3,67) |
| величина | +0,17 (+3,9%): уровень 4,31 → 4,46 |
| данные в точке сдвига | энтропия 11,009 → 11,113 бит; редких токенов 0,65% → 0,67% |
| конфигурация | не менялась: LR 1e-3, шард 2/52, расписание без событий |
| рестарт | сдвиг начался в середине сегмента 571 — не рестарт |
| порча данных | исключена: чанки декодируются связно |
| наклон после сдвига | 43 100–43 377: **−0,001 / 1000** (плато на новом уровне) |
| состояние модели | NaN нет, сегменты rc=0, guard OK |

Вывод: не деградация модели. Уровень поднялся и стабилизировался; данные в этом
участке чуть труднее (+0,1 бита энтропии — порядок наблюдаемого +0,17 нат).

## Решение: три шага

### Шаг 1. Сейчас — не вмешиваться

Не откатывать, не менять LR, не менять расписание.

Причина: откат на `step-43000` прочитает **те же самые токены** (курсор данных
лежит в чекпоинте), сдвиг повторится; цена — 3–4 часа и сломанное сравнение
с baseline. Уровень стоит, а не растёт; механические стражи зелёные.

### Шаг 2. Триггер на шаге 45 500 (за 1 000 шагов до перехода W→Q)

Проверка: **медиана последних 200 шагов**.

- **< 4,42** — восстановление идёт, продолжаем без вмешательства;
- **≥ 4,42** (сейчас 4,4693) **или** наклон за 500 шагов ≥ 0
  **или** новое неподавленное событие C-059 — запускаем диагностику (ниже).

Почему 45 500: до перехода W→Q (46 500) остаётся 1 000 шагов (~11 ч), достаточно
для диагностики и решения; после 46 500 состав данных сменится и отделить эффект
перехода от остаточного сдвига будет нельзя.

### Шаг 3. План B — исправленная версия

**Ошибка в первоначальной формулировке:** «откат + старт с шарда 3» неприменим.
Шард 2 заканчивается на шаге **50 637**, то есть весь остаток прогона (до 50 000)
лежит внутри шарда 2. Пропуск региона = пропуск всего остатка.

Рабочие варианты:

- **B1. Откат на `step-43000` и продолжение** — только если диагностика покажет
  деградацию модели на фиксированном батче. Если причина в данных, сдвиг
  повторится: тогда вмешательство прекращаем и фиксируем в отчёте.
- **B2. Доиграть как есть** и судить по финальному eval — базовый вариант, если
  диагностика покажет, что данные просто труднее.

## Процедура диагностики (выполняется только при срабатывании шага 2)

Цель: отделить «данные труднее» от «модель деградировала».

1. Остановить прогон на границе сегмента (STOP-файл), дождаться `rc=0`.
2. Взять два чекпоинта: `active/step-00043000` (pinned) и последний pinned на 45 500.
3. Один и тот же фиксированный батч (held-out, вне обучающего потока; seed
   зафиксирован), forward-only, одинаковые XLA-флаги,
   `XLA_PYTHON_CLIENT_MEM_FRACTION=0.15`.
4. Критерий: `loss(после) − loss(до) > +0,05` на том же батче → **деградация**
   (план B1); `≤ +0,05` → **данные труднее** (план B2, продолжаем).
5. Поднять прогон с последнего чекпоинта. Потеря — один сегмент (~15–20 мин).

Ограничение: AD-7 (одна модельная нагрузка за раз) — поэтому диагностика идёт
в паузе обучения, а не параллельно.

## Что не делаем

- Не подавляем сигнал: сдвиг остаётся в реестре с `review_by: 2026-11-21`.
- Не меняем пороги детектора под текущий прогон (калибровка зафиксирована в ADR-060).
- Не трогаем состав Q и `decay_ratio` в этом прогоне (решения от 13.11 в силе).
