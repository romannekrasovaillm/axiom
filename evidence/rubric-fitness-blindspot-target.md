# Утверждение владельца (target оценки, 06.10.2026)

> Но есть и сильный контрпример, и для автора он, по-моему, ценнее любой похвалы. Самый дорогой дефект проекта прошёл сквозь все 45 правил. Это KDA с явными матрицами dk×dk, MFU ниже 1%, годы обучения вместо часов. Fitness-правила проверяют прозу ADR, трассируемость, пиннинг и детерминизм, но ни одно не сравнивает фактическую скорость с теоретическим потолком железа. Агенты оформили неэффективный алгоритм безупречно, и docstring даже назвал его «FLA-style».

## Приложенная фактура контура (проверяемые ссылки)

1. **Реализация**: `net/kda.py` — чанковый KDA; docstring ссылается на FLA-style алгоритм; вычисление через явные матрицы (dk×dk), без WY/UT-перепараметризации.
2. **KPI факт**: ADR-032 (директива владельца): ток/с базис **80–86** (замер endurance-ноги l3-full на GB10), приёмка дельты WY/UT — **от ≥800 ток/с (10×)**; владелец: «годы обучения вместо часов» (при полном претрейне 1B-масштаба).
3. **Пиковая производительность железа**: DGX Spark GB10 — petaFLOP-класс FP4 / десятки TFLOPS BF16; факт 80–86 ток/с для ~1B-класса модели соответствует MFU << 1% (ток/с 80-86 против достижимых тысяч-десятков тысяч ток/с для этой размерности).
4. **Покрытие правил**: 45 правил CONSTRAINTS.yaml (кейс) — типы: must_contain / each_file_must_contain / must_not_contain / file_exists (31 контентное) + command_succeeds (14 стражей: детерминизм, манифесты, стражи чистоты eval, single-load GB10). Формулировки проверяют: прозу ADR (C-001…C-015), пиннинг (C-019), приватность (C-011, C-021), детерминизм (C-013, ADR-013/C-034-профиль), трассируемость (C-004/C-005-требования к AD), существование стражей (C-036…C-045). **Ни одно правило не сравнивает измеренную скорость (ток/с, MFU) с теоретическим потолком железа** — проверяемо grep'ом по CONSTRAINTS.yaml: ни «MFU», ни «roofline», ни «theoretical peak», ни «ток/с» как порог.
5. **Фальсифицируемость**: тезис опровергается наличием в 45 правилах сравнения фактической скорости с theoretical peak — его нет.
6. **Источник утверждения**: владелец проекта; контекст — директива ADR-032 (переписать чанковый KDA на WY/UT, KPI 10×).
