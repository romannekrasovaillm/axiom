Манифест прогона A4 поднимается до схемы `v2`: обязательные поля пиннинга сохраняются, добавляются
`stage_set_version`, `backend` (platform/device/jax/matmul_precision — пиннинг по ADR-010), `stages`
(`{name, status: executed|skipped|absent, evidence}`) и **вычисляемое** `pipeline_complete`. Эталонный
набор стадий `stage_set v1` — `pretrain_checkpoint`, `spark_inference`, `rl_environment`, `sft`,
`rl_base_scheme`; гейт A4 закрывается только при полном покрытии, частичный прогон даёт красный C-038
с поимённым списком непокрытых стадий. Основание — обследование 13.09.2026: прогонного пути A4 в коде
нет (есть сеть, Orbax-чекпойнт, инференс, среда и стыковка `net_executor` + `test_13_integration`;
цикла обучения, SFT- и RL-стадий нет), при этом схема v1 проверяла только непустые хеши — прогон
доступной части конвейера дал бы зелёный C-038 при непройденном A4, то есть воспроизвёл бы дефект,
ради предотвращения которого AD-4 вводился (AD-10: страж проверяет артефакт, а не предмет инварианта).
Запрет фабрикации сохранён и усилен: `run_ref` обязан указывать на существующий непустой журнал прогона.
Отвергнуто: статус-кво со схемой v1, отдельное правило C-039 вместо усиления C-038, требование полноты
прозой без машинной проверки, немедленное требование полного прогона без промежуточного режима.
